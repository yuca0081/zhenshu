## 结论：通过

| 验证点 | 结果 |
|---|---|
| **CPU 稳定流体的水墨观感** | ✅ 宣纸暖白底 + 柔边晕染 + 笔划拖尾有运动感；无网格伪影/撕裂/整屏黑（`f_*.png` 三帧留证） |
| **确定性：两次独立渲染逐帧同像素** | ✅ 两渲 t=1.0/3.5/5.8 三时刻 md5 逐对全同（`6359ba32… / f4bb05fb… / b78c1c3c…`） |
| **确定性机制** | 状态式模拟但「任意 t = 从 0 固定步长重放到 t」：顺序渲染只推演一遍（180 步），倒 seek 自动 reset 重放 |
| **性能（离线批渲染可接受）** | 6s 1080p30 ≈ 15s/次（192×108 模拟格 + Jacobi 22 迭代 + 粗格双线性放大） |

## 实现要点（对 §5.1 造墨工具的直接输入）

- **流体核**：Stam 1999 稳定流体——半拉格朗日平流 + Jacobi 压力投影（22 迭代）
  + Fedkiw 2001 涡度约束（卷曲来源）+ 墨微耗散(×0.9985/步) + 墨比水重缓沉(+0.012·d/步)。
  全部 CPU/JS，不依赖 WebGL——离线工具不挑机器，headless 也能跑。
- **渲染分辨率解耦**：192×108 染料格 → 小画布 → 双线性放大到 1920×1080。
  墨的软边界来自放大插值，正是宣纸晕染的观感；要更细腻把网格翻倍即可（成本线性）。
- **事件表运笔**：注墨 = 高斯核染料 + 冲量；横扫笔 = 沿正弦笔路逐帧微注。
  「按项目现做素材」（§5.3）= 换事件表：把 target 字形位图的梯度做成持续外力——
  本原型未做（进阶项），机制已留位（splat/事件表即注入接口）。
- **管线内零模拟**：产物是 mp4（`render1.mp4`，594KB/6s）。入库走素材库 video 类型，
  引擎只挑 id——与 §5.4「不做常驻渲染服务/不让 LLM 写 shader」一致。

## 复现

```bash
cd demo/ink-prototype
npx -y hyperframes@0.8.55 render . -c ink.html -o render1.mp4
npx -y hyperframes@0.8.55 render . -c ink.html -o render2.mp4
for t in 1.0 3.5 5.8; do ffmpeg -y -v error -ss $t -i render1.mp4 -frames:v 1 a_$t.png \
  && ffmpeg -y -v error -ss $t -i render2.mp4 -frames:v 1 b_$t.png; done
md5sum a_*.png b_*.png   # 三对全同
```
