音乐驱动（PV）架构草案 · 2026-10-21 讨论定稿，未排期未动工。发令枪从文稿换成音乐——舞台还是那个舞台（渲染引擎/素材/风格库不动），换的是指挥。准备阶段：主题（或主题＋上传曲子：跳过做曲直进地图，「给一首曲子做片子」模式）→ ① 音乐工位（一个 ReAct 会话调两个白名单工具：曲brief → 做曲/选曲 → 音乐地图，一次交付三件套；地图对 brief 闭环自检，做曲重做 ≤2；demo/agi-mv-repro/analyze_audio.py 已验证节拍分析；自家曲库 v2（MIDI 做曲）＝首个后端，谱面直出节拍地图）→ ② 分镜工位（镜头边界钉在节拍上，只认地图不认 brief——曲先行不是偏好是唯一解）→ 打包终审门。制作阶段全链复用段级流水线机器：写画面注入节拍事件、check 新增卡点机械闸、镜头审判卷骨架照搬、拼接挂原曲音轨、终审判据换血。纯音乐无歌词：TTS / 歌词 / 字幕整个退场，时间轴来源唯一化。框色：蓝＝新增工位、橙＝判据换血、默认＝直接复用。点击节点看详情。
