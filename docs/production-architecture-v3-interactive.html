完整背景（大白话）

这个项目是一条自动做短视频的流水线：你给它一个主题（或一篇稿子），它自动查资料写口播稿、定画风、切分镜、配音、画画面、自己质检自己审片，最后交出一部带配音、字幕、配乐的成片（竖屏/横屏都行）。全流程只有一次人工参与——制作开始前的「打包终审门」，其余全部自动。

准备阶段像设计部：写手 → 美术指导 → 分镜师三位 AI 接力，各自产出一份「工件」（文件），最后打包给你过目。制作阶段像自动车间：先配音定时间轴，然后几十个「画师」同时开工，每段画面独立走 质检→渲染→审片 的迷你流水线，谁做完谁先走、不等齐；全部段落过审后拼成一整部、混上配乐，最后总监审抽帧把关。

名词大白话解释
工件每个阶段交出的产物文件：文字稿、风格包、分镜稿。后面的环节只看工件、不看前面探索的过程——所以改某一环时，别的环不用重做。
工位一道工序。准备阶段三个工位（文稿/风格/分镜），制作阶段按段流转的写画面/质检/渲染/审片也是工位。
段（seg）5–20 秒的一小节画面。一个段 = 一个 HTML 文件 = 一次渲染 = 一份缓存。打回只重做出问题的那段，绝不整片重来——省钱省时的根基。
ReAct一种让大模型「边想边干活」的方式：想一步 → 调一个工具 → 看结果 → 再想……直到交出作业（submit）。准备阶段三位 AI、制作阶段的审片员都是这么干活的。
submit-or-die工位的唯一合法出口是交作业工具。光说不交 = 白跑，预算烧完就报错，防止 AI 空转。
check（机检）程序质检：查画面代码的语法、黑场、字幕缺失、动画不守规矩等硬伤。纯机器活，不花大模型的钱——便宜的门挡在昂贵的环节前面。
段审 / 终审「AI 审片员」（多模态大模型）看截图挑毛病：段审逐段看，终审拼完看整部。打回走「只改问题处」的循环，有轮次上限。
续写 + patch打回时不许整份重写：在原来的对话上续写，AI 只回一张「改哪几处」的改动单，程序照单套用。改动小、不引入新毛病。
签名刹车同一毛病连续两轮原样出现 → 判定「系统性问题」，立即停车报人，不再反复重掷骰子烧钱。
journal / manifest流水线账本：每一段的状态迁移、每一次审查取证都有记录。中途崩了能从断点续跑（做好的段不重做），事后能查每一步。
并发上限写画面最多 4 路同时（云端 API 限额）、审片最多 4 路、渲染按本机 CPU（≤min(4, CPU−2)）——三类资源互不抢嘴。

现行架构：准备阶段 = 三个 ReAct 工位工件链 + 打包终审门；制作阶段 = 段级流水线（写 ≤4 ∥ 审 ≤4 ∥ 渲按 CPU，谁写完谁往下流）。点击节点，右侧看设计细节。

制作阶段全链复用段级流水线机器：写画面注入节拍事件、check 新增卡点机械闸、镜头审判卷骨架照搬、拼接挂原曲音轨、终审判据换血。纯音乐无歌词：TTS / 歌词 / 字幕整个退场，时间轴来源唯一化。

全链复用：成本闸 · 磁盘缓存 · 事件流 · 风格库 · 样张 · 素材工位 · patch 修复——舞台不变，换的是指挥。
