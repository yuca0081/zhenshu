# 整片连续 comp / three.js 评估结案

> 日期：2026-09-29。关闭 `docs/upgrade-plan.md` §M-C 剩余清单中的两项后置评估
> （「整片连续 comp / three.js 评估（scene 通道稳定后）」）。
> 依据：webgl-gap-analysis.md P2-12、ak-pv-repro 经验、scene 通道 10/10 成活率、
> 本批落地的转场 v1b xfade。

## 1. 结论

| 项 | 决定 | 一句话理由 |
|---|---|---|
| **整片连续 comp** | **采纳，M-D 候选范围立项前置**（做「连续模式」双轨之一） | ak-pv-repro 已验证自写引擎直产 comp JSON；scene 通道证明了确定性画布词汇表；xfade 把段间断点从「黑场」降到 0.4s 叠化——连续叙事题材的剩余痛点只剩「跨段状态延续」，连续 comp 正面解决它 |
| **three.js（3D 词汇）** | **缓议，不立项** | 需求未到：现有参考片里 3D 资产走「管线外素材引入」（ink 路线同款）；真要 DCC 级 3D 是 M-D 之后的事，先把 scene 通道的 2D 程序化天花板吃完 |

## 2. 整片连续 comp：怎么落（评估结论，非实施记录）

**双模式并存，不替换段式**：段式（当前唯一模式）是修改循环的承重墙——段级重渲/
圈选/时刻引用全建立在「重渲单元=段」上。连续模式只对连续叙事题材开放：

- **触发**：分镜 plan 阶段 LLM 判 `timing_basis=narration && continuity=high`
  （如歌词 MV、诗歌、一镜到底讲解）→ 生成 1 个整片 comp 而非 N 个段 comp。
- **复用 ak-pv-repro 路线**：`demo/ak-pv-repro` 验证过「自写引擎直产 comp JSON」
  （无 hyperframes 段工程），整片一个 timeline，音频对齐词级时间戳驱动 reveal。
- **修改单元降级约定**：连续 comp 的重做单元=整片画面（音频不动），UI 上要在
  开工前明示用户（「这类题材改一处要重渲整片画面」）；或按 timeline 区间做
  局部重渲（hyperframes `-c` 单段切片的连续版，评估留给实施时）。
- **与 M-D 的关系**：音乐驱动模式（`timing_basis=music`）是最典型的连续题材，
  连续 comp 通道应作为 M-D 的组成部分一起立项，不单独排期。

**风险**：整片 comp 的 check/lint 粒度要重设计（现在按段报 ✗）；失败重试爆炸半径
从一段变整片。实施前须先做「整片 comp 的 lint 分区报错」设计。

## 3. three.js：为什么不立项

1. **需求侧**：四篇参考片差距分析（webgl/群论/MAD/歌词MV）里没有一条差距
   必须真 3D 才能补——「世界+相机」的观感大头（逐帧程序化、连续演化、景深光效）
   已被 scene 通道（canvas 2D + seeded PRNG + 相机预设）覆盖到 2D 天花板。
2. **供给侧**：DCC 级 3D 资产（模型/贴图）超出「确定性网页渲染」边界——
   ink-fluid-analysis 的结论同样适用：管线外做资产（录屏/预渲 mp4 入库），
   管线内只挑 id。
3. **成本侧**：three.js 进 HyperFrames 意味着确定性回放门禁要管 WebGL 状态
   （GPU 浮点不确定性已在 scene 回放闸里踩过 LSB 抖动坑，3D 只会更糟）、
   元素菜单/lint/防呆全套要再开一层。
4. **重开条件**（写死，防反复评估）：出现必须实时 3D 的参考片差距
   （如可交互相机跟随），且 scene 通道 2D 表达确认到顶时，再按 scene 通道
   同款四步走（原型闸→契约→prompt→成活率基准）。
