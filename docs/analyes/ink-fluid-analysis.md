# 水墨流体视频 · 案例解析与落地路线

> 状态：v1（2026-09-27）。样本：B 站 UP 主 Diddums 的「水中墨」演示片（B站 DASH 流，
> AV1 1080p30 / AAC 48kHz，128.6s，本地样本 `42182970279-1-100026.m4s` + `-30232.m4s`）。
> 结论来源：逐帧抽检 + ink.raylin.ai 官方"法"页自述（原文 "Everything here is computed
> live in your browser. There is no video."）。上位文档：`docs/plan.md`。

## 1. TL;DR

**这个视频不是生成式 AI 做的。** 它是一个互动网页应用「点睛」（ink.raylin.ai）的录屏，
画面 = GPU 实时流体力学模拟（Navier-Stokes）+ 目标驱动墨汇聚，AI 只用在外围（TTS 旁白、
例句翻译）。它比视频生成模型强在**可控**：字要成形就一定成形。

我们的引擎做不出，不是模型能力或提示词问题，而是**渲染词汇表缺一层"逐像素物理"**：
DOM/CSS 是排版引擎，表达不了密度场/速度场演化。补法走路线 1（本文件 §5）：
本地离线渲染水墨片段 → 入素材库 → 引擎加视频层元素 → stitch 阶段叠底合成。

## 2. 样本逐段拆解

| 时间 | 画面 | 技术实质 |
|---|---|---|
| ~2s | 墨滴入水，卷出漩涡 | 纯流体模拟（涡度约束出卷曲） |
| 5–10s | 「永」字按笔顺被墨写出 | 笔顺中线驱动注墨 + target 汇聚 |
| ~20s | 永字八法竖排引文 | 普通竖排排版（我们能做到） |
| ~30s | 上善若水 +《道德经》出处 | 墨絮背景 + 竖排文字 |
| ~50s | 绳锯木断/水滴石穿 | 同构版式，换引文 |
| ~80s | 墨团汇聚成飞鸟剪影 | target-driven smoke，target=鸟剪影位图 |
| ~110s | 网页 UI：输入框/拼音/"听"按钮 | 交互式网站本体，证明是录屏 |
| ~127s | 落地页「在线体验 ink.raylin.ai」 | 产品演示片实锤 |

## 3. 「点睛」技术全解（官方自述）

1. **实时流体模拟**：GPU 上解不可压 Navier-Stokes（Stam 1999 *Stable Fluids*），
   半拉格朗日平流 + Jacobi 压力迭代；涡度约束（Fedkiw, Stam & Jensen 2001）制造卷曲；
   MacCormack 平流（Selle et al. 2008）减少数值耗散。墨比水重，会下沉。
2. **墨按目标汇聚**：Fattal & Lischinski SIGGRAPH 2004 *Target-Driven Smoke Animation*——
   给一张模糊目标图，用其梯度驱动墨流飘向目标。字、鸟、龙全是这个方法，**这是全片灵魂**。
3. **字形数据**：Make Me a Hanzi（Arphic Public License），经 hanzi-writer-data 提供
   笔画轮廓与中线，按标准笔顺书写。
4. **光影**：GPU Gems 3 第 13 章的光线步进体积光（光柱被墨遮蔽），水缸通透感的来源。
5. **音效**：加法合成古琴拨弦，E 羽五声；笔画高度定音高，低通滤波跟随水动能。
6. **真正的 AI**：旁白 = Fish Audio s2.1-pro（"纪录片男声"）；例句翻译 = GPT（OpenRouter），
   结果服务器缓存。**画面零生成式 AI。**

## 4. 能力差距：为什么我们的引擎做不出

| # | 差距 | 具体到我们 |
|---|---|---|
| 1 | 渲染词汇表 | DOM/CSS 是排版原语（盒子/文字/图/滤镜），没有"每帧对 200 万像素解物理方程"的能力；LLM 写再好的 CSS 也写不出 Navier-Stokes |
| 2 | custom 预算 | custom 元素 html 3200 / css·js 2000 字符，装不下数千行 WebGL shader 工程 |
| 3 | 渲染模型 | HyperFrames 要求确定性 seek（禁 CSS 动画、任意 t 截图复检）；流体是有状态逐帧积分，第 N 帧依赖全部历史，必须"从 0 快进到 t"（固定步长+固定种子可确定性，但与现有截图模型是两套逻辑） |
| 4 | 系统气质 | 我们是拼装系统（版式+元素+配音）；点睛是单一连续物理系统，标题/字/转场从同一个场里长出来，整体感拼装给不了 |

注：片中的竖排引文、出处小字（`writing-mode: vertical-rl`）我们完全做得出；
真正缺的只有"墨"本身。

## 5. 落地方案（路线 1，已选定）

**原则：墨在管线外渲染成确定性 mp4，管线内只有素材，没有任何模拟。**
不确定性被关在"入库前"，这是本方案最重要的架构性质。

### 5.1 四步链路

1. **造墨工具**（`tools/` 下离线脚本，非常驻服务）：headless Chrome 跑流体模拟，
   固定时间步长 + 固定种子，逐帧截 canvas → ffmpeg 拼 mp4。分辨率/帧率对齐成片契约。
   底子用开源 Pavel Dobryakov *WebGL-Fluid-Simulation*（MIT），target-driven 汇聚自加。
2. **素材库加视频素材类型**：tags（水墨/背景/转场）、时长、封面帧；沿用素材库 v1
   的 id 引用机制（`docs/asset-library.md` §P1）。
3. **引擎加视频层**：`video` 元素或 role=bg 接受视频源；LLM 只做"挑哪个 id、放哪、
   多大"，不生成内容；防呆沿用四道闸思路。
4. **合成**：见 §5.2 决策。

### 5.2 合成方式决策

| 方案 | 做法 | 评价 |
|---|---|---|
| a. HTML 内 `<video>` 逐帧 seek | 每帧设 `currentTime=t` 等 seeked 再截，截图管线零改动 | 受 headless 解码器限制（h264 看构建，素材需转 VP9/AV1）；视频过浏览器缩放 |
| b. stitch 阶段 ffmpeg 叠底（**选定**） | 用视频底的段 HTML 截透明底，stitch 时 overlay 垫底 | 与 BGM 走 stitch 同款架构：媒体在终装阶段合入；不经浏览器解码，原分辨率质量最稳 |

### 5.3 进阶（杀手锏）：按项目现做素材

复刻 target-driven 核心：用户关键词 → 开源中文字体渲染成剪影 → 作为 target 图 →
离线跑出"墨写出这个词"的专属片段入库。固定素材库保底，按词现做负责贴合内容——
这是「点睛」效果的可复制部分，也是比接视频生成 API 强的根本原因（可控+零 API 成本）。

### 5.4 明确不做

- 不做常驻渲染服务（跑批出片即可）；
- 不让 LLM 写 shader（shader 是我们的固定工程，LLM 只填参数）；
- 不接可灵/即梦类视频生成 API（点睛证明了不需要，且生成模型不可控）。

## 6. 风险与待定

- **GPU**：headless Chrome 走 SwiftShader 软渲染会很慢；本机若有 NVIDIA GPU 需确认
  Chrome 吃到硬件 GL（`chrome://gpu`）。慢只影响出库速度，不影响质量。
- **字形数据版权**：Make Me a Hanzi 是 Arphic Public License（可商用需保留声明）；
  备选思源宋体自行抽轮廓/中线（工作量↑）。原型期直接用 hanzi-writer-data。
- **素材版权**：B 站原片不可直接搬用，全部素材必须自渲。
- **存储**：视频素材比图大两个数量级，素材库 P3（PG/MinIO）迁移时需把视频算进容量模型。

## 7. 验收路径

1. **原型闸**：固定种子渲染 10s（墨滴 + 一字成形），肉眼对比点睛效果，达标才动引擎侧。
2. **链路闸**：固定水墨素材走完 库→元素→stitch 叠底 全链，出一条测试片。
3. **进阶闸**：按词现做"墨写字"片段，进真实项目。
