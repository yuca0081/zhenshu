# 对标参考片差距分析与改造方案

> 参考片：B 站 UP 主「第十一次元」《地球四十六亿年》（1920×1080 / 30fps / 290s，HEVC）。
> 我方对照样本：`videos/` 下三部风格测试片（bingqi-era 构成主义 PV / colour-out-of-space 克苏鲁 / elden-ring 黑金史诗 PV，均 2026-09-27）。
> 日期：2026-09-27。本文档 = 逐帧分析的证据 + 根因结论 + 分级改造方案。

## TL;DR

**不是技术做不出来——参考片本身就是网页渲染的（片尾自述 REAL-TIME WEBGL & WEB AUDIO），与我们是同一底座。** 差距在于我们的语法是「排版文档」，它的语法是「世界 + 相机」：我们的确定性规则封死了程序化每帧绘景，段式架构消灭了连续性，审美供给层没有 HUD/后期/排版规范。三层都是自设的边界，不是浏览器的边界。改造按 P0（后期链路 + 全局 overlay + 字幕重做 + 去水印，天级）→ P1（`scene` 元素开放程序化画面，周级）→ P2（style pack + 整片连续 comp）推进。

## 一、参考片拆解

### 1.1 技术构成（片尾 credits + 画面证据）

- **一个连续的 Three.js/WebGL 世界**：290 秒不是 N 张卡片，是相机在同一个宇宙里飞完 46 亿年。
- **GPU 粒子系统**：开场太阳星云数千粒子 + 体积感尘埃团；吸积段粒子盘环绕。
- **GLSL 程序化着色器**：熔岩海洋星球（fbm 噪声发光裂纹）、大气 fresnel 辉光、动态云层、雪球地球冰盖、水下丁达尔光柱。
- **低多边形 3D 场景**：石炭纪巨木森林、白垩纪针叶林+恐龙、农业革命梯田+茅屋村庄——程序化建模 + 雾 + 影。
- **公版素材**：NASA Blue Marble / Visible Earth（现代地球、ISS 模型），零水印。
- **实时音频**：旁白 + 环境音乐（Web Audio）。

### 1.2 画面语言（这是「高级感」的真正来源）

| 维度 | 做法 |
|---|---|
| HUD 三锚点 | 左上：章节名（中文宋体 + 英文 small caps）；右上：`距今 46.00 亿年` 计数器**全程实时跳动**；底部：宙代时间轴（冥古宙→太古宙→元古宙→显生宙）+ 进度点 |
| 章节题 | 画面居中，大号宋体宽字距 + 斜体英文小字 + 一行旁白摘要，随章节淡入淡出 |
| 排版纪律 | 一套字体系统、一个强调色（金）、大量留白、暗背景单主体构图 |
| 后期 | 暗角 vignette、轻微色差、颗粒——统一铺满全片 |
| 运动 | 相机持续运镜（推/拉/绕/穿行），粒子永远在动，画面没有一秒是静止的 |

### 1.3 硬参数

1920×1080、30fps、视频流 ~1.08 Mbps（HEVC）、AAC ~110 kbps、总长 290s。

## 二、我方现状

### 2.1 三部测试片观察（抽帧证据）

| 片子 | 观察 |
|---|---|
| bingqi-era t20 | 近乎空屏：米色底 + 一个圆线图形 + 灰底字幕条。构图贫瘠 |
| bingqi-era t40 | 大色块（构成主义）+ 背景生图被灰罩压淡，主体黑色块是空的 |
| colour t20/t40 | AI 生成紫色星云底图 + 引言卡 + 图标行；本质是「图上放字」 |
| elden-ring t20 | AI 生成火海底图 + 左上小图卡 + 标题 + 字幕条；「海报配注」语法 |
| 共性 | 灰底卡拉OK字幕条拉低档次；右下/左上「AI生成」水印；段间硬切；除字幕高亮外画面大面积静止 |

### 2.2 引擎事实（代码核实）

- 段 = 独立 HTML 页，LLM 按契约写 spec，`hyperframes@0.8.55` headless Chrome 逐帧截图 + ffmpeg 拼接；`contract.FPS=30`、`SegTail=0.35`。
- **确定性封禁**（`server/internal/contract/spec.go` jsBan/cssBan）：`requestAnimationFrame`、`Date`、`Math.random`、`setTimeout/setInterval`、`window/document/fetch/eval`、CSS `animation/transition`、外链资源、`position:fixed`。动画只能走 `tl.to(容器ID,…)` 补间时间线。
- **词表**：camera ∈ {zoom_in, zoom_out, pan_left, pan_right, drift}；anim ∈ {pop, fade, rise, slide, wipe, blur, chars, none}。
- **元素词表**：title|note|label|big|beam|disc|circle|arrow|icon|chart_bar|chart_line|chart_pie|image|emoji + custom（表达力逃生舱：**每段 ≤3 个**，html ≤3200 / css ≤2000 / js ≤2000 字符，`spec.go:635`）；role=bg 仅 image/custom 每类每段 1 个。
- 运行时无 three.js 供给，且外链被 cssBan 禁止。
- 生图走智谱免费档，**带「AI生成」水印**。

推论：星云粒子、熔岩流动、云层漂移、计数器跳动、相机穿行——参考片的每一类核心画面，**在我们的语法里都不可表达**，不是 LLM 不想写。

---

## 三、根因：三层自锁 + 素材层

1. **语法层**——「每帧程序化绘景」这个能力维度不存在：rAF/随机/时间被确定性规则封禁，canvas 无循环可写；custom 预算装不下 WebGL 场景；无 three.js。→ 语法天花板 = 排版文档 + 补间。
2. **架构层**——段式模型（每段独立页面）导致：无跨段持久 HUD 的容身之处、无场景连续性、段间只能硬切；camera 词表 5 个词，做不了运镜叙事。
3. **审美供给层**——style pack 管了色彩/字体/版式，但没有 HUD 模板、双语排版规范、居中章节题模板；stitch 之后**没有任何后期链路**（vignette/grain/LUT 均无）；字幕条样式土。
4. **素材层**——免费档生图水印 + 静态贴图式底图（无景深无动态），与 NASA 公版程序化素材的观感差距是数量级的。

---

## 四、结论

底座（headless Chrome 截帧 + ffmpeg）完全能渲染参考片那类画面——它自己就是网页。差距是**产品语法与架构自设的边界**，每一层都可以拆。优先级上：审美供给（后期/HUD/排版）是性价比之王，程序化画面（scene 元素）是从「PPT 语法」跨到「世界语法」的关键一步。

## 五、改造方案

### P0 —— 不加新能力，先涨一档（天级）

| # | 事项 | 落地 |
|---|---|---|
| 1 | **后期链路** | stitch 后统一 ffmpeg 滤镜：`vignette` + `noise`（胶片颗粒）+ 轻微色差，可选统一色调/LUT。参数进 styles.json 按风格下发。参考片一半「电影感」来自这里 |
| 2 | **全局 overlay 层** | 引擎给每段页面注入同一套 overlay 模板（CSS+DOM），数据由 spec 的 global 字段提供（章节名/计数器/时间轴）。不动段式架构即可获得跨段一致的 HUD，消灭碎片感 |
| 3 | **字幕条重做** | 去掉灰底框 → 底部居中一行细字（无框）或提供无字幕档。字幕是文案不是 UI |
| 4 | **去水印** | 生图换付费档或本地 SD；或图片预算改程序化 CSS 纹理/渐变 |

### P1 —— 开放「程序化画面」（周级，核心投入）

| # | 事项 | 设计要点 |
|---|---|---|
| 5 | **`scene` 元素类型** | 宿主 seek(t) 时注入 t、驱动唯一 `tick(t)`——LLM 写「t 时刻画面是什么」的**纯函数**（粒子位置 = f(seed, t)），确定性不破坏。禁的不再是 rAF，而是「自管时间」 |
| 6 | **three.js 本地供给** | bundled 进运行时注入路径（不走 CDN，绕开外链禁令），白名单暴露 API 面 |
| 7 | **参数化 shader 积木库** | 星云粒子/程序化星球（熔岩·大气·云层·冰雪）/光柱/雪雨火/山脊线……LLM 只填参数不手写 GLSL——手写 GLSL 不可靠，模板+参数可靠。与素材库/方法库同构 |
| 8 | **scene 预算放宽** | 参数化后不需要无限自由度，但 2000 字符不够：scene 类 js 单独放宽（8000 级） |
| 9 | **相机升级** | 词表加「环绕/穿行」，支持段内关键帧相机路径（现有 tl 关键帧机制可复用） |

### P2 —— 审美供给侧与架构演进（持续）

| # | 事项 | 说明 |
|---|---|---|
| 10 | **「纪录片」style pack** | 以参考片为蓝本：中文宋体 + 英文斜体/small caps 双语、暗底、单强调色、HUD 三锚点、居中章节题模板；抽 20 帧进样张矩阵做 few-shot |
| 11 | **方法库注入** | 沉淀「高级感公式」：大留白+单一主体、暗底浅字纪律、转场公式（与 M2 方法库主线合并） |
| 12 | **整片连续 comp 通道** | 对连续叙事题材，跳过「每段一个 HTML」，一个 comp 渲到底（ak-pv-repro 已验证「直产 comp JSON」路线）。连续性问题从根上消失，段式与连续式双模式并存 |

## 六、技术难点与对策

| 难点 | 对策 |
|---|---|
| 确定性 vs 动画 | 时间第一公民：宿主注入 t，所有状态是 t 的纯函数；随机用 seeded PRNG；GPU 粒子用**解析轨迹**（位置=f(seed,t)）而非每帧积分 |
| headless Chrome 截 WebGL canvas | canvas 默认清缓冲会截出黑帧：需 `preserveDrawingBuffer:true` 或按帧 composite 后截图；在 hyperframes 侧验证一次 |
| GLSL 由 LLM 手写不可靠 | 不手写。积木库模板化，LLM 填参数；模板自带 fallback 与参数校验 |
| 性能 | 290s×30fps≈8700 帧逐帧截图，重粒子场景估 0.3–1s/帧，可接受；必要时 scene 段降采样至 15fps 后插帧 |
| 整片连续 comp 与现有段式管线的兼容 | 双模式并存：连续 comp 作为特殊项目类型（ak-pv-repro 路线），复用现有 TTS/BGM/合成尾段 |
