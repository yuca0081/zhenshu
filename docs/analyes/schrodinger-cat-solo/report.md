# 《薛定谔的猫》——大模型单兵出片实验报告

> 2026-10-14 · 实验问题：不借任何产线平台，一个大模型 agent 只凭"会写代码 + 能用本机工具 + 能访问公共网络接口"，能做出什么水准的视频？
>
> 成片：`schrodinger_cat_1080p.mp4`（本目录）· 1920×1080 · 30fps · **3 分 56 秒** · H.264+AAC · 40.4 MB

## 0. 一句话结论

能做出一支**叙事完整、画面统一、音画同步的动画讲解片**——风格是"深空蓝底 + 青/紫双色辉光"的扁平动态图形（motion graphics），不是实拍也不是 AI 生图；配音、配乐、音效、字幕、剪辑全部由 agent 一手包办，全程约 1.5 小时。短板也很明确：声音是公共 TTS 接口的普通音质，画面是程序画的示意图风格，离"商业级质感"还差着素材与审美积累的距离。

## 1. 实验设定

**允许用的**（agent 自身能力）：

- 写代码：Python（PIL/numpy/scipy）、ffmpeg、Git
- 本机已有资源：Windows 系统字体、16 核 CPU
- 公共网络接口：无密钥的公开服务（最终用了百度翻译的公开 TTS 端点）
- 自我检查：派多模态子代理"看"抽帧画面做质检

**不许用的**：甄数（zhenshu）平台的任何产线代码、服务、素材库、API key。本目录代码全部从零新写，与平台渲染器无任何复用关系。

## 2. 制作流水线全景

传统动画团队的角色分工 ↔ 这次 agent 一个人的对应做法：

| 工序 | 团队里的角色 | 这次怎么做的 | 工具 |
|---|---|---|---|
| ① 文稿 | 编导 | 写 9 段共 868 字解说词，按"钩子→来历→装置→叠加态→坍缩→诠释之争→澄清→今天→尾声"的科普结构 | 手写（模型直出） |
| ② 配音 | 配音演员 | 按句切 40 块，逐句请求公共 TTS，ffmpeg 量出每句精确时长 | 百度翻译公开 TTS（16kHz 单声道） |
| ③ 时间轴 | 剪辑助理 | 由"每句配音的真实时长"反推场景边界、字幕卡点、音效事件，生成 `timeline.json` 作为全片唯一事实来源 | Python |
| ④ 画面 | 动画师 | 写了一个小型"场景系统"：9 个场景函数，每一帧按时间参数算出所有元素的位置/透明度/颜色，逐帧画出 7073 张 1080p 图 | PIL + numpy，12 进程并行 |
| ⑤ 音乐音效 | 作曲/音效师 | 用正弦波叠加合成和弦垫底（Am9→F→C→G 循环）、钟声、盖革计数器咔哒声、坍缩低音轰、世界分裂琶音、转场嗖声 | numpy + scipy 滤波器 |
| ⑥ 合成质检 | 后期/审片 | 配音按时间轴精确摆放混入配乐，响度归一到 -15 LUFS；抽 54 帧预览 + 15 帧成片终检，三轮视觉审查 | ffmpeg + 多模态子代理 |

关键设计决策：**时间轴从音频反推，而不是让画面迁就音频**。每句配音的真实秒数测出来之后，场景时长 = 垫片 + 语音 + 尾垫，字幕卡点就是句子的起止。这保证了音画天然同步，不需要事后对齐。

## 4. 各工序细节与踩的坑

### 4.1 配音：两条路走不通，第三条路通

1. **edge-tts（微软 Edge 朗读接口）**：被 403 拒——微软对该接口加了反滥用令牌校验+区域封锁，本机网络环境下彻底不可用。教训：依赖灰色免费接口要先探路。
2. **Windows 本机语音**：只有 2014 年代的 Huihui/Kangkang，音质撑不起"高质量"目标，仅作兜底。
3. **百度翻译公开 TTS 端点**（最终方案）：无需密钥的公共接口，sped=5 档实测约 4.1 字/秒，女声清晰。按句请求共 40 次，每次间隔 0.35 秒避免触发限制。局限：16kHz 采样率（略闷）、语调平、句与句之间情感不连贯。

**时长控制的经验**：先按 4.5 字/秒估算写了 1073 字稿，实测 TTS 只有 4.1 字/秒，全片会拖到近 5 分钟——于是把稿子精炼到 868 字（砍冗余不砍信息），一版到位落在 3:56。

### 4.2 画面：写一个"以时间为唯一自变量"的渲染器

架构上最关键的选择：**每个场景是一个纯函数 `画面 = f(t)`**。不维护任何跨帧状态，任何一帧都能独立计算。好处：

- 天然可并行：12 个进程各渲染一段，各带一个 ffmpeg 管道出 mp4 分段，最后无损拼接（约 8 分钟出完全片 7073 帧）；
- 想改哪一帧改哪一帧，重来不需要"从头播放"。

风格系统：深空蓝渐变底 + 微网格 + 暗角 + 颗粒（掩盖渐变条带）；**青色=活/正面，紫色=死/对偶**，全片色彩语义一致；标题用微软雅黑粗体加辉光，引言卡片用楷体增加"人味"，数字年份用等宽字体。猫是手调 20 个顶点的多边形剪影（坐姿）+ 几何组合（卧姿），不追求写实、追求可读。

### 4.3 音频：全部程序化合成

- **和弦垫**：Am9→Fmaj7→Cmaj7→G6 每 8 秒一换、3 秒交叉淡化，每个音用 3 个泛音的正弦叠加，左右声道各带 ±0.16% 失谐（天然加宽立体声）+ 55Hz 低音根音；
- **音效对齐叙事**：盖革咔哒声只在"装置→叠加态"段落出现且密度递增；坍缩低音轰（110→36Hz 扫频）与画面白闪同一毫秒触发（都读同一个 `timeline.json` 事件）；每次转场有轻微嗖声；场景切换点缀五声音阶钟声；
- **混音**：配音峰值归一到 0.72 压过配乐，最终 ffmpeg `loudnorm` 归一到 -15 LUFS / -1.5 dBTP（流媒体标准响度）。

### 4.4 质检：三轮"看片"，修了 8 个问题

主模型自己看不了图，所以派**多模态子代理**当审片员，三轮共查 100+ 帧：

| 轮次 | 抓到的问题 | 修复 |
|---|---|---|
| 第一轮（54 帧预览） | "各 50%" 用错等宽字体→"各"字变豆腐块；公式条与"两个世界"标签压字幕；s3 结局图例盖住原子标签；**片尾淡出事件算错成"场景开始前"，片尾字幕全黑**；卧姿猫被坐猫完全遮住；裂缝线穿过公式 | 全修：换字体/挪位置/改几何/修事件偏移 |
| 第二轮（复核+全分辨率核字） | 片尾第二行中文整段豆腐块（又是等宽字体）；卧姿猫双耳挤成一团；"奥地利漏字"证伪（缩略图误读） | 混排字体；重写卧姿几何让头凸出双耳分离 |
| 终检（成片 15 帧） | 坍缩时序存疑（核实为抽帧太早，非缺陷）；芯片网格疑似糊成色块（核实为入场过渡帧，非缺陷） | 无需修 |

体会：**"渲染完≠做完了"**。一半以上的硬伤（字体缺字、遮挡、事件算错）是审片环节抓出来的，纯靠代码自证不够。这也印证了平台把"画面审查"做成独立工序的价值。

## 5. 成本账

- **墙钟**：全程约 1.5 小时（写代码约 50 分钟、渲染约 8 分钟、质检三轮约 25 分钟、编码混流约 5 分钟、其余为接口试错）；
- **代码量**：约 1500 行 Python（7 个文件，本目录 `src/`）；
- **机器**：16 核 CPU，渲染期 12 进程跑满，无 GPU 参与；
- **外部依赖**：百度 TTS 公共接口 40+ 次请求；无任何付费 API、无素材下载。

## 6. 客观自评

**及格线以上的**：叙事结构完整（钩子→解释→冲突→澄清→升华）；音画严格同步；视觉语言统一（双色语义、辉光、等宽数字）；信息密度适合大众科普；有记忆点（开箱坍缩的白闪+低音轰、世界树上的活死猫）。

**明显天花板**：

1. **配音音质**是全片最弱一环——公共 TTS 的 16kHz 平调女声，与平台用的商用 TTS（如 qwen-tts）差距一耳朵；
2. **画面是"示意图美学"**，适合科普但对题材适应性窄——换个美食探店题材这套矢量画风就完全不合适；没有摄影素材、没有 AI 生图；
3. **动效是插值不是表演**——所有动画都是缓动函数驱动，缺乏"重量感/弹性/跟随"这些动画基本功，看久了会感到机械；
4. 文案是模型直出，**没有多稿打磨环节**，句子质量取决于一遍成色。

## 7. 与平台产线的对照观察（写给甄数）

这次实验反过来看，恰好标出了平台的价值边界：

- **平台能补的**：商用级 TTS 音色（最大差距）；风格库与素材申请机制（题材适应性）；LLM 多轮打磨的文案工序；已被平台踩平的字体/渲染/回放坑；
- **agent 单兵也能做、但平台做得更稳的**：时间轴从音频反推（平台已有类似机制）、逐帧渲染并行化、响度归一这些"工程习惯"，写代码就能实现，但每次重写都有试错成本——平台把它们固化成了默认行为；
- **这次反而超出预期的**：自检-修复闭环（多模态审片三轮修 8 bug）证明了"渲染后质检"这一环用 agent 自己就能闭环，平台的画面审查工序方向是对的，且可以更激进（连审带修）。

## 8. 复现指南

```bash
cd docs/analyes/schrodinger-cat-solo/src
python baidu_tts.py     # 40 句配音 -> ../build/*.mp3 + segments.json（需能访问 fanyi.baidu.com）
python timeline.py      # 生成 ../build/timeline.json（场景/字幕/音效事件）
python render.py preview # 抽样帧 -> ../build/preview/（人工/子代理抽查）
python render.py full    # 12 进程并行渲染 + 拼接 -> ../build/video_silent.mp4
python audio.py          # 配音摆位 + 配乐音效合成 -> ../build/mix.wav
ffmpeg -i video_silent.mp4 -i <aac> -c:v libx264 -crf 26 -c:a copy -movflags +faststart out.mp4
```

依赖：Python 3.13（PIL/numpy/scipy）、ffmpeg（libx264/aac）、Windows 系统字体（msyh/msyhbd/STKAITI/consola——换机器需改 `style.py` 的字体路径）。
