## 1. 世界观：三层 + 一条通道

```
素材库（跨项目复用） ←── 提炼入库（带确认闸门） ── 项目（单次制作）
```

- **素材库**：制作前就有的、可跨项目复用的东西。只从闸门进。
- **项目**：一次制作的全部状态（输入件、中间产物、交付物）。
- **提炼通道**：项目产物 → 库的唯一入口，必须过人工确认。现有两条：
  - 成片 → 提炼风格（草稿 → 用户确认 → 入库）
  - 参考视频 → 解析风格 → 用户确认 → 入库

**纪律：管线产物永不自动污染库。** 这条立住，库就不会乱回去。
两条入库链路在 §12.3 统一升格为模板库。

## 2. 核心概念：五词表

| 词 | 一句话定义 | 详见 |
|---|---|---|
| **元素** | 画面部件词汇（箭头/表格/图片…27 种），唯一硬契约 | §2.1 |
| **素材** | 库里可检索的原料文件（图/音/视频） | §2.2 |
| **样张** | 风格的预览页（LLM 直写 HTML），确认动作的对象 | §2.3 |
| **风格** | 一次创作的皮肤 = 一份项目级风格文件（必填槽位 + 自由 CSS）+ 附件 | §2.4、§12.2 |
| **模板** | 入库的风格 + 配套参考包，复刻模式的载体 | §2.4、§12.3 |

**退役词**：tokens、方法包、StylePack、风格包、方向名匹配——全部收编进上表。

### 2.1 元素（kind）

页面的骨架词汇，spec 里每次现编。元素是"词汇 + 现编内容 + 编排"的合成物，
不存在"复用一张 chip"——所以元素**不是素材**，永远不入素材 catalog。

### 2.2 素材（type）

实例级的原料文件。现阶段管线只消费 `image`；`audio` 走声音通道（BGM）；
`video` **留空位不实现**（引擎无 video 元素，消费不了；库先不收，等元素词汇扩了再说）。

- type=image：fetch（必应→Commons→生图兜底）抓到的配图、用户上传图
- type=audio：BGM 曲库（现 ai/assets/music 3 首，程序化合成）
- type=video：预留，暂无

### 2.3 样张（注册表附件，不是素材类型）

- **风格样张**：风格的"样板间"——2-3 段 960×540 完整 HTML（**正本**）+ 截图 PNG（预览衍生物，可重渲）。
  用途：用户选风格看效果、冷启动复用、LLM 视觉对齐。现状正本内嵌在 JSON 字段里
  （项目 `style/style_samples.json` 的 `samples[].html`；入库后 stylepacks 的 `sample_html`）。
- **元素样张**：gallery——每种元素在某风格下渲染的 PNG（`data/gallery/<style>/*.png`）。
  用途：前端素材区展示、LLM 参考。

样张**永不上片**。它从属于风格/元素条目，不存在独立检索"一张样张"的场景。

### 2.4 风格与模板

- **风格**：一次创作的皮肤，**一份项目级风格文件**——必填槽位（暂定四项：底色/文字色/强调色/字体）+
  自由 CSS（纹理/特效/装饰不设键）+ 附件（样张/特效包/版式配方）。
  定义、生成与确认时机见 §12.2。
- **模板**：入库的风格（published）+ 配套参考包（示例 spec、素材清单）。语义与用法见 §12.3。

现状结构速记（过渡期旧术语，§12 主链路落地后逐步退场）：

- **styles.json 条目**（引擎消费，纯机器参数，无效果图）：
  `id / direction(方向名) / genre(适用题材) / keywords(检索词) / photo(配图调性) / layouts / tokens`
  - **direction = 对账暗号**：风格表、风格包、项目样张三方靠这个字符串认同一风格（join key）。
    目标是以 id 引用取代（§12.2 废除字符串匹配与静默回退）。
  - **tokens（旧称）= 皮肤参数**：font / bg（渐变+fx 特效）/ txt / ink / accent / border_w / radius…，
    引擎画元素时直塞 CSS。
  - **layouts = 版式配方**：每段构图说明书，spec 按段号轮换；仅 4/14 风格已配。
- **stylepacks.json 条目**（用户消费，纯选型信息，无渲染参数）：
  `name / desc(适用题材+来源) / sample_html(样张正本) / origin_project(溯源) / published(是否入库)`

### 2.5 参考视频（收件箱，不是库内容）

判据：**要不要直接进片子**。媒资直接被管线消费；参考视频不进片子，
它是"入库申请材料"——上传 → 抽帧取色 → vision 析构 → 用户确认 → 产物（风格）进库，
**视频本体即弃**（可归档）。语义上是收发室，物理上放 `library/refs/` 挨着无妨。

## 3. 片子的成分（什么上片）

```
上片的（被管线消费）
├─ 元素   spec 的 kind —— 骨架词汇，每段现编
├─ 素材   库的 type：image（video 预留）—— 填进元素的原料
├─ 风格   风格文件（槽位 + 自由 CSS）—— 刷在所有元素上的皮肤（第三成分，既非元素也非素材）
└─ 声音   BGM = 库的 audio 素材；配音 = 制作时现生成（项目产物，不是库素材）

不上片的（展示层）
├─ 样张   人看 / LLM 看；HTML 是正本，PNG 是截图
└─ 参考视频 解析完即弃本体
```

两个易错点：

1. **风格是第三种成分**。画面 = 元素 × 素材，刷上风格，由 spec 编排。
2. **配音不是素材**。BGM 是库里挑的 audio 素材；配音是 tts_align 现场生成的 wav；
   音色（晓晓/云希…）是设置项，不是素材。tts-samples 试听音频只是前端辅助资产。

## 4. 统一条目模型（catalog）

素材统一成一种条目，新增素材类型 = 加一个 `type` 值，不再发明新格式：

```json
{
  "id": "img-000123",
  "type": "image",                 // image | video | audio
  "file": "media/image/img-000123.jpg",
  "tags": ["科技", "实验室", "冷色调", "照片"],
  "desc": "量子计算实验室，蓝紫色冷光，无人",
  "origin": "fetch",               // fetch | gen | upload | builtin | film
  "meta": { "w": 1920, "h": 1080, "main_colors": ["#1a2a4a"] }
}
```

| 字段 | 作用 | 谁填 |
|---|---|---|
| id | 唯一标识；所有消费方只持 id | 系统生成 |
| type | 资源种类，决定 meta 装什么 | 入库时定 |
| file | 文件相对库根的路径（catalog 只存路径不存本体） | 入库时定 |
| tags + desc | **给 LLM 检索的一面**，全库统一口径 | 见 §5 打标 |
| origin | 溯源/版权判断 | 入库时定 |
| meta | 类型特有物理属性，**确定性代码提取**（尺寸/主色/时长） | 代码 |

统一的三件事：

1. **格式统一**：图、BGM、风格注册表、风格包（旧方法包）现状四种格式，素材侧收敛为一种条目。
2. **检索统一**：任何素材检索都是同一动作——按 type 圈范围、按 tags/desc 匹配、返回清单行。
3. **引用统一**：消费方只持 id，id→文件由库解析；将来文件搬到 MinIO，引用零改动。

边界澄清：

- **坐标/编排信息永远不进库**。x/y/动效/文案是"某一次使用的编排决定"，属于 spec（项目态）；
  库只存"素材本身是什么"（库态）。
- catalog 只是**素材**的清单。元素表、风格不进 catalog（避免双份事实源），
  但三张表对 LLM 暴露的"清单行"同构：`id / 类型 / tags(≈keywords) / desc(≈desc·scene)`。

## 5. LLM 检索契约

**LLM 只读清单，不碰库。** elements.json 已经验证了这个模式（27 行描述撑起组版），
推广到全部素材：

1. **检索**：生成 spec 前按主题匹配 tags，取 top-N 条目的清单行注入 prompt。
   库里一万张图也只注入几十行，token 可控。
2. **看图**：只在刀刃处给图——风格样张（每方向 2-3 张）、帧审查（QA）。
   日常生成零多模态。
3. **渲染**：spec 引 id，渲染器按 id 取文件（拷入项目 works 保持渲染本地性），LLM 不碰 blob。

**多模态的钱只在入库花一次**，之后检索全走文字：

- fetch 图：搜索词即天然 tags（搜"量子 计算机 实验室"→tags 就是这三词 + 来源页信息），零额外成本
- gen 图：生成 prompt 即 tags/desc
- 用户上传：vision 过一次生成 tags/desc
- BGM：曲库自带情绪标签

## 6. 两条链路（防混淆，反复确认过的）

```
正式制作段：  分镜 ──→ spec（元素清单 JSON）──→ render_spec.py ──→ 段 HTML ──→ 渲染 mp4
风格样张：    主题 + 风格要求 ──→ LLM 直接写完整 HTML（960×540 静态页）──→ 截图
```

- 样张**不经过 spec**——样张阶段没有分镜没有内容，spec 无从生成；它是 LLM 直出的独立页面。
- 样张确认后，正式段画面按风格重新生成，不复用样张代码；
  样张唯一被复用的场合是入库（当模板的样张附件 / 冷启动起点）。
- 样张存储现状：HTML 内嵌在 JSON 字段里（见 §2.3），不是独立文件。

## 7. 现状问题清单（"乱"的根子）

1. 库内容散在四处：`ai/registry`、`data/gallery`、`data/library`、`data/references`，
   无统一归口。
2. `style_samples_default.json`（一个默认风格包）住在 registry 而非 library——同类不同家。
3. **stylepacks 两种来源混存**：`sp-style-*` 内置种子与成片提炼条目混在一个数组。
4. **gallery 与注册表漂移**：15 个 gallery 目录 vs 14 条注册风格（`manual` 是幽灵目录）。
5. **配图无身份**：fetch 直落项目 `assets/img/imgNN.jpg`，spec 引相对路径，
   无 id 无标签，项目结束即死。
6. **参考视频只进不出**：解析确认后工作区不清理。
7. `data/samples` 与 `data/bakeoff/sheets` 职责重叠（同一批评测主题两份表示）。
8. icons 2113 个 SVG 全量进仓库；`demo/`、`videos/` 混在仓库根。
9. **风格趋同 + 静默回退**：渲染皮肤只能在 14 套预制里字符串匹配，找不到就偷偷退手绘引擎
   （克苏鲁"深海秘仪"实锤，见 §12.1）；样张的创意到不了成片。

```
data/
├─ library/                     # 素材库根（assetlib 的文件后端）
│  ├─ catalog.json              # 素材条目清单（唯一索引，只含 §4 条目）
│  ├─ media/                    # 素材本体，按 type 分目录
│  │  ├─ image/                 #   抓取/生成/上传的图
│  │  └─ audio/                 #   BGM 曲库（自 ai/assets/music 迁入）
│  ├─ registry/                 # 设计资产（git 追踪）
│  │  ├─ elements.json          # 元素表（含 gallery 附件索引）
│  │  ├─ gallery/<style>/       # 元素样张矩阵（自 data/gallery 迁入，清掉幽灵目录）
│  │  └─ styles.json            # 引擎风格注册表（现状 14 条；§12 主链路落地后与模板库合流）
│  ├─ templates/                # 模板库（§12.3）：风格文件 + 样张 + 示例 spec + 素材清单
```

- `data/samples`、`data/bakeoff`、`demo/`、`videos/`：实验区，不迁不删，另行归档。

## 12. 风格自由化：创意 / 复刻双模式

> 2026-09-27 两轮讨论收敛；皮肤文件的具体格式与校验器范围待动工时定稿（§11.1）。

### 12.1 对现状的判定

- 片子风格趋同的根因：渲染皮肤只能在 14 套预制里匹配，样张阶段 LLM 的创意在渲染时被丢弃。
  实锤：克苏鲁项目样张阶段自拟"深海秘仪"（#0a1216 暗调），渲染时注册表无此风格，
  **静默回退**手绘引擎（#FDF6E3 纸面）——样张与成片两张皮。
- 皮肤参数的真正价值不是"预制"，而是：引擎能消费、一次定死、代码统一应用、可校验。
  创意不必被预制库囚禁。

### 12.2 新共识：元素是唯一硬契约，风格 = 一份"风格文件"

- 元素词汇（elements.json）保持唯一硬契约，不动。
- 风格 = **一份项目级风格文件**，内容两段式：
  - **必填槽位（暂定四项，跑几个项目后再增减）**：底色 / 文字色 / 强调色 / 字体——引擎给标题、
    面板、箭头这些标准件上色时只认这几个"插座"，LLM 风格再花哨也得把值插进来（实现上即 CSS 变量）。
  - **自由 CSS**：纹理、特效、装饰，不设键、随便写。
- **风格文件不进 spec**：spec 一段一份（9 段 9 份），风格写进去 = LLM 独立发挥 9 次 = 段间漂移。
  风格必须一份、先于 spec 定稿、9 段共用；spec 里的 custom 元素（如雾底）是段级点缀，照旧现编。
- 生成与确认：样张阶段（③）LLM 写样张的同时产风格文件；校验靠**实测样张**
  （渲染样张测对比度/字体回退/溢出，不过打回重写）；确认样张 = 确认风格文件，锁死进项目。
- 渲染（⑤）只读应用，段间零漂移；渲染中 LLM 无发言权（与 §5/§6 原则一致）。
- **废除静默回退**：风格文件缺失/校验不过 = 硬报错，绝不偷偷换手绘引擎。

### 12.3 命名统一与双模式

命名收敛为五词（**退役词：tokens、方法包、StylePack、风格包、方向名匹配**，见 §2）：

| 词 | 含义 |
|---|---|
| 元素 | 画面部件词汇（27 种），唯一硬契约 |
| 素材 | 库里可检索的原料文件（图/音/视频），catalog 条目 |
| 样张 | 风格的预览页（LLM 直写 HTML），确认动作的对象 |
| **风格** | 一次创作的皮肤 = 必填槽位 + 自由 CSS + 附件（样张/特效包/版式配方） |
| **模板** | 入库的风格（published）+ 配套参考包，复刻模式的载体 |

**模板 ≠ 模具，是"强风格先例包"**。用同一模板出的片子：同一套皮肤、相似的画面气质、
完全不同的内容编排。模板内容与用法：

| 模板内容 | 用法 | 定死程度 |
|---|---|---|
| 风格文件（槽位 + 自由 CSS） | 直接沿用（可微调） | 定死——风格强一致的来源 |
| 示例 spec（1-2 份） | spec 阶段注入 prompt 仿写（few-shot），编排按本项目分镜重写 | 仿照——气质一致，不复制 |
| 样张（2-3 张） | 选用时预览、确认 | 展示 |
| 配套素材（素材 id 清单） | 新项目直接复用，可换可加 | 可用 |

即：**皮肤定死、编排仿照、内容自由**。示例 spec 仿写即 roadmap"方法库注入"的起步形态，
模板做厚后天然是方法库的载体。

双模式，汇合于同一接口（项目里一份确认过的风格文件）：

- **自由创作**：LLM 样张阶段现写风格文件 → 实测过闸 → 用户确认 → 渲染 →（可选）存为模板。
- **精准复刻**：模板库选一个 → 风格文件拷进项目（可微调）→ 看样张确认 →
  spec 阶段以示例 spec 为参考 → 渲染。现有方法库（成片提炼）与视频解析（styleref）
  统一升格为**模板库**，一个入口。

### 12.4 丰富路线（主链路之后的第二步）

1. **扩皮肤表达**：动效倾向（弹/滑/打字机/漂移）、质感层（纸纹/噪点/雾）、段间转场写进风格文件，
   引擎逐项实现、全部风格共享。
2. **母题库 motifs**：风格特有装饰片段（雾/版画纹理/星点）存为风格附件，spec 按需引用，
   替代每段现编 custom（现状限 3 个/段且用完即弃）。
3. **版式现编 + 沉淀**：样张阶段顺带产出 3-5 个构图配方，随风格文件确认、随模板入库。
4. **远期·模板加厚**：模板从"皮肤"扩到全片结构（分镜弧线/叙事节奏），方法库 storyboard_arc 类经验的归宿。

### 12.5 排期建议

先跑通主链路：样张 → LLM 产风格文件 → 实测校验 → 确认锁定 → 渲染用项目自有皮肤（缺皮肤硬报错）。
词汇扩容、母题库、模板库统一为第二步——主链路不通，扩了也没人用。
