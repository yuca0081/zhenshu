# 帧述 · 聊天式确定性视频创作平台 · 完整方案 v1

> 状态：v1（2026-09-21，2026-09-28 增补表现力层 v2 = §11 与进展快照）。本文取代 v0 讨论稿，是产品与架构的唯一权威文档。
> 技术选型暂沿用 `docs/tech-stack.md`，产品形态从"三栏工作台"简化为"聊天框驱动"后，选型待下一轮复审（见 §10）。
> 原则不变：单用户、单并发、端到端；**简化交互，不简化管线质量**。

## 1. 定位

**一个聊天框驱动的视频创作网站**：与 AI 对话攒齐文稿和分镜，AI 自动渲染出成片。核心引擎是 HyperFrames（HTML 合成 → 确定性 MP4），天然适合信息密度高的品类——**科普、解说、宣传**。

### 是什么 / 不是什么

- 是：确定性代码渲染。画面是 HTML/CSS/GSAP 合成物逐帧 seek 渲染出的 MP4，**预览即成片**。
- 不是：视频生成模型（Sora 类）、真人出镜数字人、通用剪辑软件。
- 用户：个人创作者 + 营销人员，同一产品，不做区分。

### 三个卖点

1. **聊天即创作**：不需要学剪辑软件，说话就是操作。
2. **预览即成片**：确定性渲染，不存在"导出后效果和预览不一样"。
3. **指哪改哪**：段 / 秒 / 帧 / 元素四级寻址，改一处只重渲一段（见 §3.5）。

## 2. 产品形态

### 2.1 布局

```
┌────────────────────────────────────────────────────────────┐
│ 顶栏：项目名 · 状态 · 积分                                     │
├────────┬────────────────────────────────┬──────────────────┤
│ 左栏    │  中间：舞台（Stage）              │  右栏：聊天        │
│ 历史项目 │  文稿视图 → 分镜视图 → 视频+时间轴  │  Agent 对话       │
│ (会话中  │  （随创作阶段演化，见 2.2）        │  引用卡片          │
│  自动   │                                │  进度播报          │
│  收起)  │                                │  输入框            │
└────────┴────────────────────────────────┴──────────────────┘
```

- **视频是主角，对话是驱动的手**：中间舞台占最大空间，右栏聊天全程驱动。
- **左栏只在非会话时展开**：一旦开始和 AI 讨论创作，历史/项目列表自动收起，把空间让给舞台。

### 2.2 舞台的演化

舞台内容随创作阶段推进，每一步都是可查看的文档或产物：

```
会话开始      文稿就绪       分镜就绪        风格图确认         制作完成
┌────────┐  ┌─────────┐  ┌──────────┐   ┌─────────────┐  ┌────────────┐
│ 文稿    │→ │ 分镜表    │→ │ 风格样张   │→  │ 分镜表+段状态  │→ │ 完整视频     │
│(AI起草/ │  │(逐段:    │  │ 1-3 张    │   │(配音中/生成中/ │  │ + 时间轴     │
│用户粘贴)│  │ 旁白+画面)│  │ 用户点头⏸ │   │ 检查中/渲染中) │  │ (一次点亮)   │
└────────┘  └─────────┘  └──────────┘   └─────────────┘  └────────────┘
              右侧聊天框全程驱动，左侧已收起
```

制作期间时间轴以灰色占位段画出来（分段结构可见），**整条渲染完成后一次性点亮为可播放视频**——不做"边渲染边显示"的流式预览。

### 2.3 聊天框的角色

- **唯一驱动入口**：要文稿、出分镜、播进度、接收修改指令，都发生在对话里。
- **引用卡片**：用户在舞台/时间轴上选中任何东西后，输入框上方出现引用 chip（见 §3.5），指令自动携带精确上下文，AI 不用猜用户在说哪。
- **进度播报**：管线每步完成在聊天里报一次（配音完成、第 N 段画面生成、检查通过、开始渲染…）。

## 3. 创作流程

### 3.1 三个前置件（硬门，代码强制检查）

AI 进行视频创作必须满足的前置条件：**有文稿、有分镜、风格图已确认**——三者齐备才允许开工，代码里硬检查，不可跳过。前两件 AI 自检即可；**风格图必须用户点头**，因为"好不好看"只有人能判断。

**文稿（manuscript）**——视频要说的全部内容，旁白的最终来源。

- **一等产物**：有版本、可编辑、可溯源。前置门只认"文稿存在且内容定了"，**不认它从哪来**——来源可插拔：用户粘贴现成的 / 丢链接让 AI 提取（二期）/ 一句主题让 AI 起草再改（二期）。这样"要不要 AI 帮写文稿"永远不影响架构。
- **内容权威**：分镜的旁白必须从文稿来（压缩、口语化改写可以，凭空编造不行）。
- **时长策略（2026-09-22 定）**：忠实原文，时长服从内容，不强制压缩；**硬上限 15 分钟**——估算超限时 AI 主动压缩取舍并与用户协商。

**分镜（storyboard / script.json）**——怎么说的制作方案。

- 每段 = `{ id, narration, visual_brief, duration_hint }`，头部携带 `{ timing_basis, plan, style_id }`（AI 裁量的载体）。
- 分镜确认后，**段旁白以分镜为准**（用户改分镜旁白不需要回写文稿）。
- 分镜表是系统的中枢数据结构：TTS 的输入、合成物生成的输入、段级重渲的寻址单元、时间轴的分段依据。

**风格图（style samples）**——视觉风格的"定妆照"，唯一必须用户确认的前置件。

- AI 用拟采用的风格参数（色板/字阶/组件/动效偏好）渲出 **1–3 张 HTML 样张**：与成片出自同一套 token，所见即所得，不会"样张好看、成片走样"。
- 风格输入灵活：用户可随口说偏好（"手绘风、轻松点"），不说则 AI 按文稿气质自动定。
- 用户确认即锁定为该项目的 StylePack（出片后可直接沉淀进方法库 §4.6）；不满意就重出样张，改到点头为止。

### 3.2 AI 自检（开工前的门）

三个前置件齐了，AI 自检通过才开工。自检四项：

1. **材料完备**：文稿、分镜存在且非空，风格图状态为"已确认"。
2. **结构合法**：分镜 schema 校验通过（段数、每段旁白非空、timing_basis 已声明、总时长 ≤ 15 分钟）。
3. **内容一致**：分镜旁白覆盖文稿要点、无凭空事实（LLM 自查 + 规则检查）。
4. **可制作**：每段有画面提示，风格图确认的 StylePack 存在。

不强制用户点头确认——责任模式是 **AI 自检把关，用户随时可插手**（文档都在页面上，改了就重新自检）。

### 3.3 状态机

```
空会话 → 起草文稿 → 文稿就绪 → 生成分镜 → 分镜就绪
  → 出风格样张 → 用户确认 ⏸（不点头不出片）→ 风格图就绪
  → AI 自检 ──通过──→ 制作中（TTS → 合成物 → 检查 → 渲染 → 拼接）
  │                    ↓
  │              整条视频就绪（舞台点亮）
  │                    ↓
  │              修改循环（四级寻址，§3.5）⟲
  │                    ↓
  └── 不通过 → 回到对应文档/样张修改 ──→ 出片（高清渲染）→ 完成
```

### 3.4 制作管线（开工后）

```
分镜表 → TTS（每段音频 + 逐词时间戳）
      → 双语字幕翻译（可选 1.5 步：bi_subtitle 开启时短语级英文，幂等，失败不挡片）
      → 合成物生成（每段一个 sub-composition，元素命名规范 §4.2）
      → lint/check 门禁 + 四帧视觉审查 + scene 确定性回放门禁 + 自修复循环（≤3 次）
      → 段级并行渲染（N 段 N 进程）→ 拼接 → 统一后期（暗角/颗粒/色差 + BGM 混音）→ 整条视频就绪
```

- **音频先于画面**（时序原则，§4.1）：段时长以 TTS 实际音频长度为准。
- 字幕烧在合成物画面里（三模式：line 无框细字默认 / box 胶囊 / none，可选中英双语次行），逐词高亮，前端不需要任何字幕引擎。

### 3.5 修改循环：四级寻址

成片就绪后，用户**指着任何东西说话**：

| 级 | 用户操作 | 引用卡片示例 |
|---|---|---|
| 段 | 时间轴点一下某段 | `📎 段3` |
| 秒 | 暂停，时间码定位 | `📎 00:45.2` |
| 帧 | 同上（帧 = 秒的精确化） | `📎 段3 · 00:45.2` |
| 元素 | 暂停帧上悬停点选**命名元素**（§4.2） | `📎 段3 · 00:45.2 ·「箭头：模型→工具」` |
| 兜底 | 直接嘴说（"45 秒那个往右飞的箭头"） | AI 拿该帧截图 + 该段 HTML 自行解析 |

三种元素选择方式，精确度递减：**悬停点选**（首选）→ **圈选**（在帧上画框，系统按包围盒几何解析成元素引用）→ **嘴说**（AI 视觉+源码定位）。

**关键区分：修改单元 ≠ 重渲染单元。**

- 修改单元可以细到**元素**（改的是该元素在 HTML/CSS/GSAP 里的定义，整段所有关键帧都变）。
- 重渲染单元永远是**段**：只重渲被改的段再拼回时间轴，其余段不动。架构不因元素级修改而变复杂。

### 3.6 出片

用户满意 → 点出片/说"出片" → 1080p 高清渲染（同样段级并行）→ 下载 MP4。

## 4. 核心机制

### 4.1 时序原则（单一时间基准）

每个项目先确定"谁拥有时间轴"并声明在分镜头部（`timing_basis`）。科普/解说默认**旁白驱动**：先 TTS 得到每段实际时长与逐词时间戳，合成物按这些时长生成，逐词高亮字幕直接消费时间戳。宣传/卡点类可音乐驱动。不变的约束：**基准产物必须先于适配它的产物**。音效在合成物内按节拍点（转场/数据揭示/强调）自动布点。

### 4.2 元素命名规范（生成要求 + lint 门禁）

这是四级寻址里"元素级"的地基，一条生成纪律：

- AI 生成每段合成物时，**每个有意义的视觉元素必须打上稳定 id + 人话名字**（`data-hf-name="箭头：模型→工具"`）。
- 写进 lint 门禁：未命名元素报错，与既有确定性规则（无网络/无时钟/资产本地化）同级强制。
- 前端悬停时高亮 + 显示人话名字，用户在"人话世界"里选东西，不是在选 DOM 节点。

### 4.3 预览的双模形态

- **播放态**：`<video>` 播 draft/final MP4。
- **修改态**（暂停 + 检视）：舞台加载**活合成物**（该段 HTML + GSAP 时间轴）seek 到该帧。确定性渲染保证这一帧与 MP4 逐像素一致，所以选元素、圈选、改完即所见都在活 DOM 上进行。

### 4.4 并行渲染与拼接

- 一段 = 一个独立 sub-composition 文件，段间无依赖 → **N 段 N 进程并行渲染，FFmpeg 拼接**。总耗时 ≈ 最慢一段 + 拼接，与段级重生成是同一设计的两份收益。
- **段间转场**（v1 已落地）：每段首尾 0.25s 黑场微叠化（转场词表 cut|fade 由风格 token 决定，t 线性函数确定性不受影响）；段画面重叠的交叉叠化（xfade）为后置项——需整片重编码，等观感反馈再决定。

### 4.5 质量门禁与自修复

四道闸：契约校验（ValidateSpec）→ `hyperframes lint/check`（含元素命名规则）→ 四帧视觉审查（frameQA：首帧/开场/落定/尾帧，视觉模型判定，scene 段豁免卡片式空白/重心判定）→ scene 确定性回放门禁（含程序化画布的段，同 t 两轮截帧像素比对，带 LSB 容差，失败按段回喂修复）。
- 失败读 JSON 诊断 → 定点修改 → 重查，≤3 次；仍失败则该段标记问题，聊天里告知用户。
- **每步产物落盘**（文稿、分镜、audio/、compositions/、check 报告、renders/、聊天记录），失败可从任意步重放。

### 4.6 方法库：风格与经验的沉淀-复用循环（冷启动无预置）

**冷启动阶段没有任何预置风格模板**：每条视频的风格由 Agent 按文稿气质与用户意图现场生成（色板/字阶/组件/动效全现写）。成品的过程就是模板的来源：

```
生成（无模板，Agent 现写风格）
  → 成片 → 沉淀：提炼 StylePack（frame.md 式规范 + 组件库）与经验卡，用户确认入方法库
  → 首页展示 → 后来者选同一风格直接复用（生成时注入该模板）
  → 持续深挖：提示词 / 注意事项 / 镜头词汇 / 分镜结构 / 文稿套路均总结入库
     → 生成质量随做片数量上升（飞轮）
```

方法库两类条目：

- **风格模板（StylePack）**：frame.md 式规范（色板/字阶/组件/动效偏好）+ 配套组件；从哪个项目提炼的可溯源。
- **经验卡（MethodNote）**：五类——提示词片段 / 踩坑记录（如"中文字体必须本地化"）/ 镜头词汇（blueprint 库）/ 分镜结构 arc（钩子→痛点→机制→证明→CTA）/ 文稿套路。

沉淀的原料免费：聊天记录与引用卡片（用户改了什么、重做了哪里）本身就是最强的反馈信号——**被重做最多的环节就是经验最值钱的地方**，这些数据已天然落盘（ChatMessage + refs[]），无需额外埋点。

提炼触发：成片出片时 Agent 自动起草 → **用户一键确认入库**（全自动会污染库，纯手动依赖用户勤快，起草自动 + 入库确认取两者之长）。

### 4.7 Agent 设计：ReAct 循环 + 状态机护栏

**总架构：一个对话大脑（ReAct 循环 + 工具调用）+ 一组无人格技能 + 确定性管线编排。** 主管 Agent 遵循标准 ReAct——推理 → 调工具 → 看观察 → 再推理，直到本轮任务完成；实现走 OpenAI 兼容 function calling（DeepSeek/GLM/Qwen 均支持），循环由 Go 侧驱动。LLM 永远不直接碰文件和数据库——它只发起工具调用，Go 校验后执行。

**护栏 1：工具受状态机门禁。** 每个工具标注可用状态，越界调用被拒绝、原因回喂（Agent 换路或向用户解释）。工具粒度是**决策**而非步骤：`start_production` 是一个粗粒度工具，内部管线（TTS→合成→lint→渲染）是 Go 确定性编排，不进 LLM 循环——步骤之间不需要判断的地方全是 Go，LLM 只出现在需要判断的位置（分镜规划、合成物生成、修复决策、引用解析、方法库提炼）。

**护栏 2：循环有边界。** 三停：① 到达用户门（要材料/要拍板）；② 步数上限（默认 10 步，超出强制总结+提问）；③ 出错且重试耗尽。默认流程可自主连贯执行（自检通过直接开工、边做边播报，对应 §3.2"不强制用户点头"），用户随时插话。

工具清单 v1：`save_manuscript` / `draft_storyboard` / `update_storyboard` / `draft_style_samples`（出风格样张，用户在舞台点头确认）/ `run_selfcheck` / `start_production` / `cancel_production` / `rework(ref, instruction)` / `export`，观察类 `read_project` / `search_method_library`。

**分层循环**：外层是对话 Agent 的 ReAct（管流程决策）；内层是管线内的固定循环——每段合成物"生成→lint→修（LLM 只在修复点介入）→重查 ≤3"，写死不自主；段与段并行、各持一个 packet 上下文（分包生成，继承验证片 frame-packets 模式）。

**模型分层**：主管对话（便宜快）／分镜规划（中档）／合成物生成（最强，HTML 画质是产品命脉）。M0 bake-off 分档实测后冻结。

**人格（默认，可调）**：靠谱的剪辑搭档——懂行、话少、主动汇报、给专业建议但尊重用户决定。

**开源参考**：Agent 循环首参考 pi（~418 行极简循环），管线编排参考 MoneyPrinterTurbo，自修复模式参考 OpenHands/gpt-engineer——完整借鉴映射见 `docs/references.md`。

示例轨迹：

```
用户：「这是我写好的文稿，直接做吧」
① 想：有文稿 → save_manuscript      → 观察：已存，状态=文稿就绪
② 想：下一步出分镜 → draft_storyboard → 观察：9 段生成
③ 想：应该自检 → run_selfcheck       → 观察：通过
④ 想：可以开工 → start_production    → 观察：管线已启动（TTS 中…）
⑤ 回复：「文稿已存，分镜 9 段、自检通过，已开工，进度我随时报。」
```

## 5. 数据模型 v1

```
Project      { id, name, status, aspect, created_at }
Manuscript   { id, project_id, content, source(paste|link|ai), version }
Storyboard   { id, project_id, timing_basis, plan, style_id, segments[] }
Segment      { id, narration, visual_brief, duration_hint,
               tts_path, comp_path, element_registry[], version }
RenderJob    { id, project_id, quality(draft|delivery), status, output_path,
               started_at, finished_at, error }
StylePack    { id, name, tokens(JSON: 色板/字阶/组件/动效偏好), origin_project_id, published }
MethodNote   { id, kind(prompt|gotcha|shot|storyboard_arc|manuscript), content, tags, origin }
ChatMessage  { id, project_id, role(user|agent|system), type(text|tool_call|progress|error),
               content, refs[], tool_name, tool_args, tool_result,
               meta(model/token/耗时——成本记账), created_at }
（追加-only 事件流：SSE 推送、审计、回放、方法库挖掘共用一张表；LLM 调用级
 trace 另走每项目 run manifest 落盘；文稿/分镜版本不入此表，tool_result 携版本指针。）
```

（相对 v0 新增：Manuscript、ChatMessage、StylePack/MethodNote（方法库，§4.6）；Segment 增加 element_registry。）

## 6. 架构模块

```

│ Web 前端：聊天工作台                                    │
```

## 7. 里程碑 v1

- **M0 管线打通（1–2 周，无 UI）**：CLI 串起 文稿 → 分镜 → 风格样张 → TTS → 合成物（含元素命名）→ lint/check → 并行渲染 → 拼接 → draft + delivery。**LLM 作业双模式起步（2026-09-22 定）**：先"会话模式"——LLM 步骤由开发会话中的 AI 担任（零 key，文件契约对接，验证片已验证此模式），跑通管线、出样片、打磨 prompt；管线稳后切"API 模式"（DeepSeek 主选）做 bake-off 与自动化实测。10 篇真实文章实测：单条耗时 / 成本 / 一次通过率。**全项目最大技术风险，最先验证。** 验证清单在 `docs/tech-stack.md` §7。
- **M1 聊天工作台（2–4 周）**：新布局（左收起/中舞台/右聊天）+ 舞台四态演化（文稿→分镜→风格图→视频）+ 三前置硬门自检 + 整条生成 + 播放 + **段级重做**（时间轴点段）+ 出片下载。风格冷启动（Agent 现出样张，用户确认）+ 方法库第一版（成片提炼 StylePack，用户确认入库，首页展示可复用）。默认 9:16、可切 16:9；无 BGM（M2 再议）。验收即 MVP 验收：真实创作者无工程师在场，粘贴文稿 → 60–90s 片 10 分钟内拿到带字幕旁白成片（时长忠实原文、上限 15 分钟）；10 次生成免修复可用 ≥7；至少一条愿意发到自己账号。
- **M2 精细修改 + 种子试用（2–3 周）**：帧/元素级寻址（悬停点选命名元素、圈选）、段级局部重渲的体验打磨、方法库深挖（经验卡五类沉淀 + 生成时检索注入）、10 名真实创作者试用，收集"10 次生成可用率"与"发出率"。

## 9. 风险与对冲

| 风险 | 对冲 |
|---|---|
| HyperFrames 0.x API 变动 | 锁 patch 版本；渲染层薄封装；关注 release note |
| LLM 写合成物一次通过率低 | check JSON 诊断驱动自修复（≤3 次）；分段隔离爆炸半径；失败模式沉淀进方法库（§4.6） |
| 元素命名规范拖低生成通过率 | M0 实测命名规则对通过率的影响；名字生成模板化（类型+方位+对象） |

| 中文 TTS 逐词时间戳不可得 | 降级 ASR 反打（funASR Paraformer） |
| 中文字体在渲染容器不可用 | 渲染容器预装/内嵌中文字体（woff2 本地化），lint 检查 font-family 有对应 @font-face |
| 渲染耗时超预期 | draft 低清低帧率；段级并行；delivery 异步排队 |
| 单条成本不可控 | M0 实测 LLM+TTS+渲染成本，定价前建立单条成本账 |

### 词汇表（LLM 可用的表达面）

- **元素 kind 28 种**：原 26 种排版元素 + `scene`（全画幅确定性画布：粒子/弦图/线框3D/函数曲线/生成艺术，`__draw(t,ctx,W,H,rng)` 函数体、seeded PRNG、≤8000 字、回放门禁兜底）+ `formula`（KaTeX 离线公式排版）。
- **镜头**：5 微动预设 + `camera_spec` 关键帧（起止 zoom/pan/rot + easing，整段插值）。
- **背景 fx**：glow/stars/**particles**（双层密星）/**noise**（噪点颗粒）/**vignette**（暗角）/dots/grid/grid_persp；`text_glow` 文字辉光 token；背景图 scrim 三模式（paper/dark/none，深色风格 dark 保照片影调）。
- **字幕**：三模式（line 默认/box/none）+ 可选中英双语（短语级 LLM 翻译，中文主行+英文斜体次行，`set_subtitle` 工具开关）。

- **后期链路**：整片统一 暗角+胶片颗粒+轻微色差（风格 token 配强度，project.json 可关），与 BGM 侧链混音一条命令图完成。
- **跨段 HUD（overlay）**：分镜级配置——左上章节角标（中文+英文 small caps）/右上实时计数器/底部进度线，单段重渲各自带全。
- **转场**：段首尾黑场微叠化（v1，零重编码）+ **转场 sfx 层**（段边界 whoosh 气流、章节切换 riser 上扬，`set_sfx` 工具开关/风格 token，stitch 秒级重混）；交叉叠化后置。
- **BGM 曲库 9 首**：calm/bright/deep/epic/mysterious/warm/melancholy/upbeat/nostalgic（程序化确定性合成，版权自持），`set_bgm` 随时换乐秒级重混。
