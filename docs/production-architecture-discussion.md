# 四工位制作架构讨论纪要（2026-10-15）

> 与 AI 协作完成的架构讨论实录与结论。起点：导演层 v2 方案（见 [director-architecture-discussion.md](director-architecture-discussion.md)，2026-10-14）实施前的代码对表；结论：**v2 八步演进整体搁置，回归四工位简化架构——导演角色退役、预期考卷并入审核工位、分镜加段落层**。本文档取代 v2 方案作为当前架构基线。

## 一、讨论路径与关键结论

### 1. 起点：v2 复核 → "太复杂了"

对 v2 八步清单逐条对代码：绑定机器（章→段、母题表、节拍表及校验）已随 f1097f2 意外建成，阐述/ctxpack/批评家/手记/分档全部未动工，前端全空白。用户判断整体过度复杂化，转向简化。讨论确认 v2 复杂度实为两类东西：**未验证的赌注**（导演阐述、结构自检等，真机样本为零）可砍；**看不见的管道**（指纹/缓存/上下文拼装）是修复经济性的地基（打回一段只花一段的钱），不可砍。

### 2. 四工位模型提出与公正评价

用户模型：准备阶段两个智能体（①文稿分镜、②风格库探索/风格描述+样张），制作阶段两个（③写画面代码、可并行、④审核画面质量、打分打回），每段 HTML 过程序 check 后交审，最后渲染出片。

评价结论：**大体是对现有系统的准确提炼，不是另起炉灶**。四工位每张都过"四条分工边界"检验（分段=可修性经济账、审核独立=裁判运动员分离、样张=人的介入点、check 前置=便宜门挡贵门前）；打分自带记账副产品。真正的新决策只有一个：把分散的三处审查收拢为一个带打分的审核工位——成立。

评价中发现三处真空：

- **渲后没人管**——审核在渲前看截帧，转场/退场/动效等"动起来才可见"的问题无人负责（prereview 已知盲区、渲后 frameQA 存在的全部理由）；
- **打回循环没刹车**——裸"分数低打回"会撞已付学费的三病：打地鼠（修好 A 冒出 B）、不收敛（check 三轮死锁教训）、口味漂移（审片员自相矛盾）；
- **接缝无主**——写画面并行各画各的，段界无人负责；单段考卷审的是十四部短片，不是一部片。

三真空解法（终版见二）：

- **渲后=审核第二场**，考卷只查动态；时机在段渲完、拼接前（重渲只花一段）；动态问题先分诊——能在拼接层机械修的（转场/字幕时序）直接修不打回，段内真动错了才重画且 ≤1 轮；
- **刹车三药**：销账+帧比对（修复回来逐条销账，帧差异确认只动该动之处——防打地鼠）；预算+同题两现即停（≤2 轮烧尽降级，同一条意见两轮没修动立即停——防不收敛）；判据锚+意见单向追加（分数从可查清单算出、每条带证据，第二轮只许销账不许发明新标准——防口味漂移）；
- **接缝四层**：防（邻段首末拍双向承诺，prompt 两行、白送）/ 查（接缝帧对进审核考卷+色量亮度跳变程序预筛，便宜）/ 兜（逐边界转场覆盖，一次性动 assemble）/ 治（只修后段+前段收尾帧参考图，等"查"的记账有真伤再开工）。

### 3. 分段深挖：现状事实与"粗暴"诊断

代码事实：`stageStoryboard` 一次 LLM 调用干三件事（口语化改写旁白+切段+每段画面提示）；"每段 8–16 秒"只是 prompt 劝告，未进校验；`duration_hint` 为估算（实测乐观约 12%），真实时长 TTS 后才知道。超窗实证：276s 片仅切 14 段（均 19.7s）。

段的身份=四同构：**段=文件=时间轴=渲染单位=缓存单位**。一段=一个自包含 HTML，画面是 t 的纯函数（契约 docs/contract.md：唯一 paused timeline、禁页面自走时钟/未种子化随机/CSS animation、回放探针验像素一致）——这是段能当并行、修复、审查单位的物理前提。

"粗暴"三处：秒表驱动非画面驱动（按 8–16 秒剁旁白，画面结构事后追认）；边界不带理由（该换画的缝与凑数的缝一视同仁）；"同一幅画讲很久"没有表达法（同舞台延续只能切段，相邻段视觉连续靠全局风格+运气，并行还放大漂移）。

提案演进：先提出硬界/软界+场景条目（舞台描述一次写好、段引用）→ 用户裁定太麻烦，**只加段落层**。

### 4. 段落层定稿

分镜结构加一张表：`paragraphs: [{title: 一句话主题, segs: [...]}]`；校验一条：段落按段序连续铺满（抄章校验模式）；判据一句进分镜 prompt："同一话题、同一画面的分镜归入同一段落，通常 2–4 段一段落"；段落只带主题句，不加别的字段。

层级：**片 → 章（导演划，管叙事弧）→ 段落（分镜规划器划，管内容话题）→ 段（渲染单位）**——每层一个生产者。下游三收益：生成侧注入"本段落主题+段内位置"；审查侧知道哪些段是一伙的（段落内两侧长得像不是问题，段落间还像才是）；转场分层（段落内朴素切、段落间讲究转场，动 assemble，缓做）。退化情形合法：全硬界片（快节奏叙事）与几乎全软界片（一个舞台讲到底）都是正常答案。

### 5. 章的用途梳理（含撞名澄清）

章（ArcChapter）四处消费：生成侧情绪定位（directorNoteFor：本段是第 N 章第 i/j 段、承担开篇/推进/收尾）；设计侧呼应（directorDesignBlock：各章情绪差异可进双皮肤）；审片判据（pacing/deadair 两查的坐标系）；缓存指纹（改章=全片段过期）。撞名澄清：`Segment.Chapter`（overlay 章节角标，分镜写的显示标签）≠ ArcChapter（导演的叙事结构）。真机数据里章是配角。

### 6. 导演存废 → 考卷归属审核（终局决定）

现状确认：导演=流水线上两个 LLM 介入点而非 agent（M1 定调：分镜后补注章/母题/节拍表；M2 审片：组装后 24 帧连环画四查、high 打回 ≤1 轮），已随 f1097f2 落地并真机验证。

存废分析：**"导演"角色可消失，但节拍表（预期考卷）是刚需**——拉普拉斯妖对照实验结论：内容缺失型 bug 程序全盲、凭感觉看片抓不住，唯一手段是"先写下该有什么、再对帧验收"；打回循环的销账、审片靶向抽帧（锚句×词级时间戳机械换算时刻）、生成侧编排注入都吃它。母题可选（零母题本就合法）、章配角可砍。

考卷生产的现状分工=大模型写内容+程序管锚定：锚句逐字校验（防幻觉定位键）、2–6 条数量窗、时刻换算与抽帧纯机械；Expect（"该有什么"）本身无程序可验证，误报风险只能记账观察。

**用户裁定：考卷交审核工位，在审核提示词里做对应审核。** 配套三件：

1. **作业顺序写死：先考卷、后看片**——第一步只读旁白（带句级时间戳）逐句写"该有什么"，第二步才对照截帧逐条查。"预期先于画面"从流水线时序降级为作业纪律，锚定偏差防掉大半；起步单调用+顺序规定，防护不够再拆两次调用（无帧出清单/带帧对照）；
2. **抽帧换句末靶向**——每句旁白念完的时刻抽一帧（每段封顶两三帧+首尾帧），帧身份标注"此刻刚念完「某句」"。靶向性≈按锚句抽（锚句本就从句子里挑），覆盖更全；全句抽约四五十帧，封顶控制预算；
3. **首轮清单即冻结**——第一轮审核写下的清单落盘存档，修复轮只对照这份清单逐条销账、不重新发明标准；人可复核（"审片说缺怀表——查它第一轮清单"），误报记账有据。

接受代价：生成侧失去节拍注入（每段画面提示+词级时间戳+契约时机纪律仍在，内容与节拍的对应粗一档，记账观察）。

## 二、最终架构（四工位 v3）

```
用户输入主题/稿件
  → 【准备阶段】
     ① 文稿分镜工位：旁白口语化改写 + 段落划分 + 切段（每段一句画面提示）
     ② 风格工位：风格库探索 / 风格描述 → 样张（用户确认门，全流程唯一人工门）
  → 【制作阶段】
     TTS + 词级对齐（程序化）
     ③ 写画面工位：逐段并行生成 HTML
        （注入：段落主题+段内位置+画面提示+词级时间戳+设计系统）
        每段 HTML → 程序 check（契约 lint + 产物不变量：强制软件光栅、字幕完整性等）
     ④ 审核工位（多模态调用，两场两卷）：
        渲前场（静态卷）：句末抽帧；先写"该有什么"清单、后对照帧；分数从清单算出；
          结构化意见（位置/期望/现状/证据）；打回 ≤2 轮，销账+帧比对，同题两现即停
        渲后场（动态卷）：段渲完、拼接前；边界帧对+动效/转场/退场判据；
          机械修优先（拼接层修转场、字幕时序），段内动态 bug 才重画且 ≤1 轮
  → 拼接 → 渲染出片
```

要点：角色=工位标签非实体，一个工位可多次调用，Go 拥有循环（确定性、可重放、manifest 可查）；段是并行/缓存/修复的统一单位；**审核工位是三真空的交汇点——考卷格式与意见单格式是核心资产**，设计好了其余都是接线。

## 四、明确放弃 / 接受的代价

**放弃（v2 八步整体搁置，其精神部分已被四工位配套吸收）**：导演阐述先行、结构自检、阐述指纹、ctxpack 收拢、介质词汇表注入、文稿批评家循环、导演手记 observation 档、质量分档配置化。

**接受代价（记账观察清单）**：

- 生成侧失去节拍注入，内容与节拍的对应粗一档；
- 审核清单为事后产物（单调用+顺序纪律，锚定防护打折，不够再拆两调用）；
- 审帧预算上升（句末抽帧 30–40 帧 vs 现 24 帧）；
- Expect 质量仍无程序验证，误报率只能靠记账。

- **先配后切**（TTS 前移、拿真实句级时间戳再切段）：讨论过，未采纳未否决，独立事项；
- **时长窗校验**是否加进分镜自检（8–20s 硬带）：未决；
- **转场分层**（段落内朴素切/段落间讲究转场）：动 assemble，缓做；
- **接缝"治"**（参考图修后段）：等"查"的记账报出真伤再开工；
- 段级自检等 v2 概念：一律等记账数据说话。

## 六、续讨论（2026-10-15 同日）：准备阶段重排为三步，四工位更名五工位

> 起点：分镜样例（画面提示里出现"黑板/深空"等风格词）暴露"风格未定、分镜先写画面"的自相矛盾；进而确认**切段与缝型同样受风格影响**（羊皮纸手稿风=页翻式语法、硬切多段碎；连贯长镜头风=match 多段长）。结论：结构与场景全部移到人工门之后，风格成为分镜的前置输入。

### 1. 准备阶段三步走（五工位）

```
① 文稿工位（门前）：口语化改写 → 纯文字稿（不含任何结构/视觉决策，门后冻结）
② 风格工位：风格库探索 → 样张（吃纯文字稿，画的是自己内容）→ 👤 人工确认门
   新增：风格描述带「剪辑语法」字段——切分密度 / 缝型倾向 / 同舞台延续 / 段长带
③ 分镜工位（门后一次调用）：段落 + 切段 + seam_in + 逐段场景规划 + match 缝首末拍设计
   输入 = 纯文字稿 + 确认风格 + 剪辑语法
```

原「文稿分镜工位」混称退役，架构由四工位更名**五工位**（文稿/风格/分镜/写画面/审核）。人工门成为真正的分叉点：门定了，结构才存在；**换风格 = 整张分镜重排（特性非缺陷）**。

### 2. 切段决策的三层合成（写入③的 prompt）

- **停顿层**（先配后切采纳时）：TTS 停顿 = 候选切点，证据；
- **话题层**：话题没讲完不能切——硬约束；
- **风格层**：剪辑语法决定切多密、缝型怎么配——软约束。

优先级写死：**话题完整 > 风格密度**；全局段长钳制（5–20s）兜渲染与审核经济性。**未决项"时长窗校验（8–20s 硬带）"就此了结**：全局硬带取消，改为每风格段长带 + 全局钳制，分镜调用时机械校验。

### 3. seam_in 缝型字段定案

除首段外每段必填 `seam_in ∈ {cut, match, fade}`：cut=硬切；match=与上段末帧接续（触发首末拍双向承诺注入）；fade=机械转场（拼接层处理，落地前按 cut 出片）。进段指纹，改缝型 = 邻段缓存过期。它是审核考卷按缝出查项的输入——这是它不能拖的真正原因。物理上限备忘：并行段渲染下跨段连续动画不存在，"丝滑"= 帧匹配切 / 机械叠化 / 硬切三形态；**想要"连着动"的地方不该设段界**（并入上一段）。
