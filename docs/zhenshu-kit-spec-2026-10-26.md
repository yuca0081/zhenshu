# zhenshu-kit 规范 v1（画材包统一契约）

> 2026-10-26 起草并同日定稿，依据：蒸馏方案 docs/style-kit-distillation-plan-2026-10-26.md 第 1 步；
> 实例校准：demo/stylekit-pixelstage（像素族，首单，终审 82/100）与
> demo/p5brush-sample（笔刷族，四画风矩阵）。
> 状态：**已定稿（D1-D3 已拍板，见 §8）**。

## 0. 一句话

zhenshu-kit 是风格库画材包的统一契约：**kit 只存画法不存题材**（去题材化），按
「笔/色/纹理/明度」四类语义暴露原语，库坑在 kit 层封装挡掉，毕业过检才能被
制作管线消费——从「每次从零造笔画一幅画」到「用现成画材摆画面」的制度层。

## 1. 三层结构（谁负责什么）

```
场景代码（制作期画面工位写）——画什么：构图/内容/文字，调用 kit 原语
zhenshu-kit（蒸馏工位产）    ——怎么画：画风原语+纪律+后处理，同 seed 确定性
底层画图库（p5.brush/p5/纯 Canvas2D）——被 kit 封装，场景代码永不见库
```

- 场景与 kit 分离是换题考试的自动化基础：同一场景代码换 kit = 换画风。
- kit 作者（蒸馏 agent）在沙箱内自由选底层库；**选型记入 Framework 字段**
  （选型本身是风格知识，如首单"像素风的笔触单位是格子，不选笔刷库"）。
- 零依赖合法（首单即例）：Deps 为空，毕业检查①②③免验。

## 2. 统一 API：四类语义原语

画风差异大（笔触 vs 格子），不做全族同构 API；按**语义四类**统一命名与职责，
族内自由扩展。CheatSheet 必须按四类组织（这是画面工位提示词真正注入的形态）。

| 类 | 语义 | 像素族实例（pixelstage） | 笔刷族实例（p5brush 系） |
|---|---|---|---|
| 笔 mark | 落一笔/一块的原子与部件组装 | rect/text/box/part+stamp/rgbSplit | brush.line/spline/wash/flowField（流场用完 noField） |
| 色 palette | 取色纪律的**唯一入口** | PS 调色板对象（橙=交互/黄=焦点≤2处） | ramp 色阶/明度场查 10 档 |
| 纹理 texture | 颗粒/纸纹/做旧/扫描行 | scanRows/pixSmoke/confetti(Burst) | grain/silkPaper/做旧三层/颗粒暗角 |
| 明度 light | 分层/光/辉光/色阶控制 | 双画布分层/glowSpot/spotlight/letterbox | with2d 图层混合/toneWash/流场明度 |

硬性要求（跨族统一，判卷与工具链依赖这些）：

1. **种子确定性**：kit 全部随机走种子，构造传 seed，禁 Math.random；同 seed
   同场景渲染逐字节一致（首单已验证的做法，毕业检查⑤）。
2. **分层契约**：kit 必须声明自己的层模型（像素族=像素层+平滑层；笔刷族=
   WEBGL 笔触层+2D 图层），并保证"底色画在哪层"有明确文档——首单 r1 教训
   （平滑层不透明底盖掉像素层）写进每族 CheatSheet 首条纪律。
3. **compose 收口**：后处理链（辉光/色差/噪点/做旧）只经 kit 的 compose 一次
   收口，场景代码不自行叠加后处理——避免质感通道失控。
4. **转场件**：黑帧/白闪/段落开关由 kit 提供（pixelstage 的 whiteFlash/bgFlat）。

## 3. 库坑封装（五坑条款）

底层库的隐性坑由 kit 层封装挡掉，场景代码永不见坑。已知坑清单（实证）：

- p5.brush 2.2.3 五坑：pressure 隐性必填 / 流场须 noField / **两点 spline 静默
  不渲染** / wash 前 noStroke / 'ink' 非内置笔（详见方案 §1.3）。
- Canvas2D 分层坑：不透明底覆盖序（首单 r1）。
- Chrome headless：路径须 Windows 风格（cygpath）；virtual-time-budget 预算。

新 kit 蒸馏中发现的坑：必须封装进 kit + 记入 Notes（配方笔记），不得留给场景层。

## 4. 去题材化纪律

- kit 永不包含题材内容：人物造型、图标、文字内容、叙事元素一律属场景代码。
  （pixelstage 的机器人 part 是考题场景文件，不在 kit.js——首单已按此执行。）
- 例外：**画风签名件**（如战斗UI的橙框按钮排、LIVE 角标）属于画风语言不算
  题材，进 kit 或 CheatSheet 配方；边界判据=「换一个故事还用不用」。
- 毕业必测换题考试：中性测试图（圆+方块+波浪）保持风格 ≥70/100（首单 v2
  实测 82；v1 惨败教训见 §7）。

## 5. 判卷口径（第 0 步校准固化）

- 四维各 10 分：**像素感（块感/锐度）/ 色阶（值域/色板命中）/ 质感（分层/
  特效形态）/ 构图语言（镜头感/UI 墨水层）**；盯风格特征，不逐像素比对内容。
- 过线门槛：每考题 ≥30/40 且无致命穿帮（远看神似、并排不穿帮——首单 B/C
  31 分即「贴线过」，判卷官须显式给 是/否 判定）。
- 判卷与画师自查分离：判卷模型 ≠ 画师模型（防自夸偏差）；判卷官必看的对照
  图=真迹 3 帧拼网格。
- **像素实测交叉验证**：判卷结论中的关键事实（黑边有无/CRT 有无/值域）须
  用程序化像素测量裁决——多模态会 confidently 误判（首单 frame-02 黑边被
  首读误判、形容词版把「CRT 直播感」字面化）。
- 带伤交卷：迭代到预算上限必须交当前最好版本并标分（Score.Reproduce 带轮次）。

## 7. 已知陷阱（配方笔记要重复的）

1. 换题场景必须与考题场景**同配方版本**——首单换题图 v1 停在旧参数，被纯
   形容词版反超 40 分；v2 同步后 82:56 反超。自动化监工（第 2 步）须把换题
   场景与考题场景放同一迭代循环。
2. RGB 色散是爆点专属特效，不可下放为元素填色；主体一律白线稿（复审补律）。
3. UI 墨水层取色锁真迹值域；新增色须有真迹出处。
4. 文字描述会字面化（CRT→扫描线幻觉）：一切色彩/质感结论以像素实测为准。

## 8. 决策点（已拍板 2026-10-26）

- **D1 kit 与 Signatures 关系 ✅**：特色升参数版（形容词→精确色值+笔触参数）
  落在 **kit 侧**（CheatSheet/调色板携带），Signatures 保持纯文字不动（它是
  检索/审核语言）；两处以条目 ID 关联，不双维护。理由：v2 教训是文字字段
  没人用，参数跟着可执行代码走才有效。
- **D2 过线门槛 ✅（暂行）**：30/40 + 换题 70/100，贴首单实测（B/C 31 贴线
  过、换题 82）；第 2 步自动化跑出分数分布后复调。
- **D3 CheatSheet 形态与时机 ✅**：形态=四类组织+纪律首条+≤2k token，**正文
  整体存 `kit.cheat_sheet` 字段**（注入即取，不让工位拉文件拼装——首单
  2026-10-26 已灌正文为证）；注入时机随第 3 步画面工位接入定。
