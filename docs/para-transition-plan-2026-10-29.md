# 接缝转场方案：段界机械转场 + 段落制创作（2026-10-29）

起点：用户看片反馈「分镜之间切换太生硬，突然就切了」。讨论收敛出两层答案：
**段落之间的缝**用机械程序化转场（轻，复用现有叠化机器），**段落之内的缝**用
段落制创作让写画面 agent 在一条连续时间轴上自己编排过渡（重，动渲染单位，
比武先行）。本文沉淀调研结论、两案机制、工程影响与走法，拍板后按 §7 实施。

## 0. 术语对齐（讨论中撞过车，先钉死）

| 口语/界面 | 代码 | 是什么 |
|---|---|---|
| **分镜** | `Segment`（seg01…） | 旁白+画面最小单位：一段 TTS、一个 HTML、时间轴一格、渲染/缓存/审核单位 |
| **段落** | `DraftParagraph`（draft.json） | 2~5 个分镜的话题分组：只有一句主题，无文件无画面 |

用户口语「段」= 本文的「段落」；本文一律用全称。层级：**片 → 段落 → 分镜**。

## 1. 问题与成因（三层叠加，均已实证）

1. **拼接层硬切**：段片 `concat -c copy` 首尾相接零过渡（`pipeline.concatSegs`）。
   这是 D5 接缝契约的赌注：各分镜首帧即景/末帧定格+段内入场收尾编排接管段间
   节奏，平台不默认加转场。
2. **设计系统转场政策执行不可靠**：实测片的设计写了
   `motion.transition = "噪点扫过：密度瞬间拉高再快速退散至下段首帧"`——其执行
   方式是指望每个分镜在自己开场/收尾动画里实现噪点密度变化，12 个分镜独立生成
   基本没做出来。
3. **机械令牌认不出这句措辞**：`transitionTokenOf` 只认「叠化/交叉/淡入淡出」
   → xfade，其余一律 → cut。「噪点扫过」落成 cut。

教训：**设计措辞→机械效果的翻译层只存在两种出口，现场发明的转场手法无法机械
表达**——方案乙（段落制）就是承认这一点：手法本体交给创作层，机械层只管兜底。

## 2. 现状机制盘点（复用资产与坑）

- **转场令牌**：`project.json` 的 `transition` 字段（LockDesign 从设计系统
  motion.transition 映射写入，`design.transitionTokenOf`）；`transitionFor`
  读取，缺省 cut。现有令牌：cut（直切）/ fade（v1 页内黑场微叠化，已退役不产新）/
  xfade（v1b 真交叉叠化）。
- **xfade 机器（v1b，完整可用）**：`buildXfadeGraph` 纯函数
  （offset_i = Σ_{k≤i}d_k − D·i，有测试）+ `xfadeConcat`
  （xfade=fade 0.4s + acrossfade 0.4s，crf18 整片重编码一次）；
  `errXfadeShort`（段过短）回退硬拼；`timeline.json` 写实际段起点
  （字幕/SFX 落点/前端时间轴的权威边界）。
- **音频实测**（p20261029-124651，TTS wav 直接量波）：首音起点 0.13–0.14s，
  尾音后静音 0.21–0.28s；段 mp4 音频垫满全段（9.624s vs 视频 9.633s）；
  加 `SegTail=0.35` → **每个分镜结尾 ≥0.5s 静音、开头只有 0.13s 垫**。
- **acrossfade 的坑**：叠化窗 0.4s 内 incoming 音频线性淡入 → 每个分镜第一个字
  从约 32% 音量爬升，听得出来。**旁白开头不能吃**——这决定了音频侧方案（§4.3）。
- **终审锚点**：`segpipe.segStartAnchorT` = 段起点 +0.4s（历史修复：越过段头
  淡入区）。与 0.4s 叠化恰好对齐；0.5s 段界转场时锚点落在转场尾段（画面九成
  是新段），可接受。
- **import 纪律**：pipeline 不能 import prep（反向依赖环）——段落界信息在
  pipeline 侧用本地小结构直读 `storyboards/draft.json`（同 project.json 直读惯例）。

## 3. 用户政策定调（2026-10-29）

1. 段落内分镜之间的过渡要**流畅**；
2. 段落之间关联松，可以用**比较硬的程序化转场**；
3. 追加（同日）：程序化转场也生硬——**能否让 agent 完成一个段落的 HTML 创作，
   一组分镜合在一条时间轴里连续编排**（→ 方案乙）。

## 4. 方案甲：转场分层（机械层，轻，两案通用）

### 4.1 转场语法

```
段落内：分镜A ── fade 叠化 0.4s ── 分镜B      （两幅画互相溶解，顺接）
段落间：分镜C ── 程序化转场 0.5s ── 分镜D     （明确的"翻页"感，待选型）
```

- 新令牌 **`para`**（project.json transition）：段内 fade + 段界程序化转场。
  cut / xfade 令牌语义保留不动。
- 边界分类：读 draft.json 段落层（分镜→段落序号，相邻同号=段内）；无段落层的
  老项目全按段界处理（保守）。
- `buildXfadeGraph` 泛化：每边界带 `{转场名, 窗口秒}`，offset 推广为
  Σd − ΣD（全同窗口时与旧公式逐字节同结果，旧测试语义不破）。
- 兜底不变：任一相邻段短于窗口 → errXfadeShort → 整片回退硬拼。

### 4.2 段界转场选型（待拍板）

推荐 **smoothleft**（定向推切，干净利落）；备选 pixelize（像素质感，适科技/游戏风）。
全片统一一种，不做设计措辞→花式效果的映射（§1 教训）。

### 4.3 音频：裁尾对接（不用 acrossfade）

- 每个边界：outgoing 音频 `atrim` 到转场起点（裁掉的 ≥0.4s 全是实测静音），
  incoming 音频经 `concat` 满音量对接。**旁白零损伤**，滤镜均为十年级老 API，
  部署环境零版本风险。
- 画面照常 xfade 重叠 0.4s；时间轴起点与视频共用同一套图计算，字幕/SFX 自动对齐。

### 4.4 接线

- `transitionTokenOf` 默认映射改为 **para**（本次政策即平台政策）；设计文字明确
  写「直切/硬切」的仍尊重 cut；同步更新 design.go 转场字段的 schema 提示语。
- 老项目不静默变行为（旧 project.json 已写死 cut 的保持 cut）；验证路径：
  把当条片置 `transition: "para"` 重拼——纯程序零 token，重跑 assemble 即见。
- 不加界面开关（先手改字段）。

## 5. 方案乙：段落制创作（用户提议，重，比武先行）

### 5.1 机制

**渲染单位从分镜换成段落**：写画面 agent 一次领一个段落的作业书（该段全部分镜的
旁白+词级时间戳+画面要点+设计系统），产出**一张连续的段落 HTML**（一条 paused
时间轴），渲一个段落 mp4。段内的分镜间过渡是 agent 编排的 GSAP 动画——同一舞台
元素跨分镜演进、运镜跨分镜延续，**缝在创作层消失**。

- **分镜不消失**，退居旁白/节拍/审片单位：TTS 仍按分镜配音、字幕仍按分镜出、
  审核仍按分镜锚句抽帧。
- **时间轴网格**：段落内每个分镜占 [累计旁白时长+收尾垫] 切出的格子；旁白贴格子，
  画面动画**可以跨格子**（旁白在格上、画面穿格而过=要的流畅）。词序表按段落
  拼接（分镜偏移累计）下发。
- **粒度规则（半自由）**：默认整段一个 HTML；超 **5 个分镜或 45 秒**强制拆，
  拆点用方案甲的叠化兜底。不做全自由（"看 agent 自己设计"）——管线必须按最复杂
  情况建设（时间轴/缓存/审核都要支持一个 HTML 含 N 分镜），自由粒度不省机制
  只多代码路径，但保留超长逃生阀。
- 段落之间的缝：方案甲的程序化转场照用（那里硬切/翻页反而自然）。

### 5.2 工程影响（诚实账）

- **手术面**（段级流水线建成以来最大）：写画面按段落发作业；段级状态机与指纹
  按段落记账（一分镜改稿→整段落重画）；逐段审按段落装帧格；拼接与 timeline.json
  改段落行+分镜内切片映射；聊天引用与前端时间轴按分镜定位到段落内时刻；重画路由。
- **单次生成变大**：段落 HTML ≈ 现单分镜 3–5 倍，lint 失败与返工爆炸半径变大；
  缓解：强制拆上限、元素级改动单修复（现有）、last-good 兜底（现有）。
- **并发变少**：12 分镜 → ~5 段落，写槽位（≤4）吃不满，总耗时估计持平略差。
- **一次性全量重渲**：单位变更作废全部段级缓存；老项目不静默迁移。

### 5.3 为什么值得

段内的缝是结构性缺陷而非参数问题：分镜各自独立成画，任何机械转场都是「两张不同
的画互相溶解/推切」。段落制把"同一话题的一组分镜"还给同一个创作头脑，过渡是
编排出来的不是后期贴上去的——这也是 v3 讨论记录里「同一幅画讲很久没有表达法」
的正面解。

## 6. 走法：比武先行，换骨在后

1. **第一步·比武实验（不动管线代码，半天级）**：挑一个 3~4 分镜的段落，手工按
   §5.1 格式写作业书发写画面工位，走完 check→渲染→段审全链。验收三指标：
   契约一次过率、段审得分 vs 该段落分镜单写基线、过渡观感（人评）。
2. **第二步·换骨（比武赢了才动）**：按 §5.2 清单改造，全量回归测试护住；
   方案甲的段界机械转场随本次一并落地（两案通用件）。
3. 若比武输了（模型写不动连续编排）：退回方案甲独立成立，段内也用叠化。

## 7. 拍板（2026-10-29 当日定案）与实施记录

1. 段界程序化转场选型：**smoothleft**（拍板采纳推荐；备选 pixelize 未采用）。
   实测复核（31 段真片 p20261023-110234 重拼）：机理正确（合成红蓝片左旧右新
   可见软边推切缝、滤镜图数学逐秒吻合），但**暗画面段落观感偏溶解**——smoothleft
   边缘渐变很宽，两暗场景之间推切读起来像叠化。若人评「翻页感」不足，换硬边
   转场只需改 `pipeline.go` 的 `paraEdgeKind` 常量（wipeleft 硬边 / slideleft
   整帧滑入），重跑 assemble 即见。
2. 新项目设计锁定默认写 para 令牌：**是**。`transitionTokenOf` 缺省映射已改
   para；明说「直切/硬切」尊重 cut；叠化类措辞仍 xfade。老项目（project.json
   已写死 cut/xfade）行为不变。
3. 比武实验：**已跑**（当日），材料=同片段落1（seg01–03，破题段），结果见
   §8。
4. 方案甲段界半边：**已随本拍板整体落地**（para 令牌=段内 fade 0.4s + 段界
   smoothleft 0.5s + 音频裁尾对接，一个令牌两层一起上，未拆半边）。

## 8. 比武实验结果（2026-10-29，详见 docs/test-result/para-contest-2026-10-29.md）

材料：同片段落 1（seg01–03「破题」，3 分镜 18.996s）。三指标：

1. **契约一次过率：段落制 1/1 一次过（0 修复轮）vs 基线 1/3**（seg01/03 各
   1–2 轮修复）。段落 HTML ≈ 单段 3 倍体量（compl 4615 tokens）下 lint+契约
   一次全过——「单次生成变大→返工爆炸半径变大」的担忧未兑现。
2. **段审：段落制六维全 pass、零 high**（仅 2 low）vs 基线三段各带伤（seg01
   device fail、seg03 修后仍有 1 条 high content）。
3. **过渡观感（机器印象，终审权在用户）**：背景舞台全程连续、无黑屏无硬切、
   每个边界后新信息点按旁白节拍入场——从「两张画硬切」升级为「同一舞台换景」。
   短板：前景装置在分镜边界整体退场留约 0.3s 空台，非旧元素保留变形的连续演进
   ——换骨提示词补一条「边界处旧元素优先保留变形（缩小/上移/变淡成引言）」。

**结论：比武赢了，建议进第二步换骨**（§5.2 清单，全量回归护住；段落作业书
正式化时吸收观感短板的编排要求）。产物在 data/paracontest/（沙盒）与
reports/para-sample/（方案甲真片样张）。

## 9. 换骨实施（2026-10-29 当日落地）

比武赢了当日动工，**架构路线：段落单元冒充分镜走既有管线**（比武验证的全套
机器原样复用），手术面收敛为「单元表 + 路由 + 组装」三处：

- **单元模型**（`server/internal/produce/units.go`）：TTS 后从 draft 段落层构建
  渲染单元（`storyboards/units.json` + `units-storyboard.json`，契约类型
  `contract.RenderUnit/UnitSeg`）。粒度=§5.1 半自由：>5 分镜或 >45s 贪心拆，
  拆点边界由方案甲段内 fade 兜底（同段落各拆 Part 同 ParaIdx）。**钉选纪律**：
  project.json `unit` 字段——处女项目首次制作钉 para；已有分镜制产物的老项目
  钉 seg **永不静默迁移**；钉 para 后段落层丢失退钉 seg。
- **单元冒充分镜**：单元表的 Segment（合并旁白/主题/格子化 brief）经
  `pipeline.WorkStoryboard()`（段落制=单元表）喂给协调器与全下游——写画面/
  渲染/机检/判卷/拼接的既有代码零改动按单元工作。**句子与事实零改造**：
  `segSentences` 按旁白前缀游走匹配，单元合并旁白自动收齐段内全部句子
  （N 编号全片唯一，比武手工版的重编号问题生产路径天然不存在）。
- **写画面**（`produce/paraprompt.go`）：比武作业书生产化（`paraUnitPrompt`），
  含观感补丁——「边界处旧元素优先保留变形（缩小/上移/变淡成引言/角标），
  避免整体退场留空台」。修复轮/用户指令/底稿块与单段作业书同语义。素材
  两段式 v1 暂不进段落作业（比武基线亦无素材）。指纹：分镜级指纹吃合并旁白
  （段内微调传导）+ 单元计划指纹（分组/格子变化传导）双保险。
- **组装**（`ai/assemble.py` 单元模式）：单元 wav=各分镜 atrim(旁白时长)+
  apad(0.35 尾垫) 拼接（=格子切法）；字幕带=单元一条（词级时间戳按格子偏移
  合并，phrases 索引重排）；index/单段工程按单元挂载；章节角标=首分镜章。
  分镜 wav/字幕契约（cap-*.html）不动。
- **拼接与时间轴**：timeline.json=单元行（sfx/终审的拼接真值）；新增
  `renders/segmap.json`=分镜行（单元起点+格子偏移）——前端时间轴分镜标/聊天
  引用/锚句定位的权威口径。边界分类（`segParaIndex`）单元表优先：拆点 fade、
  段界 smoothleft。
- **帧路由**：`pipeline.SegVideoLocate(segID)`→（段落片, 格子偏移）；frameQA
  逐段抽帧改吃单元表（首/尾帧=段落首尾帧，与接续契约同粒度）；段审锚句帧
  按句子末时刻落在单元片内（句子时刻=格子偏移+段内时刻，判卷链同口径）。

**已知边界（v1）**：素材申请两段式未进段落作业书；重做指令 `only=` 在段落制
下认单元 id（paraNN），聊天层提分镜名→单元映射待接（segmap.json 已备好数据）；
段落制项目恢复（journal 按 seg 记账）跨模式不互通（模式已钉，不会发生）。
