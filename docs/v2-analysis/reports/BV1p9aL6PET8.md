## 0. 制作方式判断

**"真人口播 + 自制 demo 网页录屏 + 首尾 AI 风格 MG 页"三段式教程**。画面哪些是 Rough.js 代码库效果: 中段(scene_05~09)所有手绘笔触(粉笔圆/框/箭头、hatch 斜线填充柱状图、红棕圈选涂鸦、绿色对勾)全部来自 Rough.js 库——demo 底部常驻参数条直接标注 `roughness / bowing / strokeWidth / fillStyle / hachureGap` 并配"复制参数/重画"按钮,自证是代码生成而非后期手绘或手绘素材。首尾深绿 MG 页(scene_04 的四特点卡、scene_10 的结尾卡)与 demo UI 的深绿主题一致,大概率同为 HTML 渲染(AI 生成),而非 AE。真人口播段为卧室实拍+硬字幕。

## 1. 内容与结构

讲 Rough.js 这个"让 AI 画手绘风"的技术点,面向 vibecoding 用户:

- **开场(0~31s, scene_01~02)**: 真人出镜抛现象("这个、这个、还有这个、还有这个"),左侧内嵌录屏窗口快速切换两种手绘 demo(绿板/牛皮纸便签)做视觉钩子。内嵌窗口偏小,内容辨识度低。
- **承上启下(31~54.6s, scene_03)**: 纯口播特写 23s("所以你跟AI进行对话的时候…"),画面信息密度为零。
- **核心特点页(54.6~63.7s, scene_04)**: 深绿底"Rough.js 核心特点 / 用手绘笔触画可交互几何"四卡: 01 抖动参数(roughness/bowing,不是后期滤镜)、02 几何全家桶、03 Canvas与SVG、04 可抄参数(fillStyle、hachureGap现场复制带走)。全片制作水准最高的一页。
- **四场景对比演示(63.7~116.3s, scene_05~08)**: 自制对比 web app 录屏,顶部 tab[01白板课堂示意|02手批涂鸦标注|03产品线框草图|04草图柱状图],右上[未使用|分解|已使用]切换;左右分栏中间"对比"竖条,底部参数 chip + 复制参数/重画。逐一演示: 课堂示意(白卡 vs 粉笔手绘)、手批涂鸦(便签 emoji vs 手绘圈线,"圆、框、箭头都带着粉笔的一个抖动")、产品线框(渐变 UI vs X 盒手绘线框)、柱状图(蓝色渐变 vs hatch 填充)。
- **实用收束(116.3~127.2s, scene_09)**: 独立 demo"重点圈选本"——产品复盘文字中一句被手绘椭圆圈选+对勾,按钮[换下一句][清除标注],右上"已标1处重点"。
- **结尾(127.2~138s, scene_10)**: "记住一句话: 凡是你在跟AI做「用手绘笔触画可交互几何」,就可以点名使用 Rough.js 技术。"+四个场景胶囊。

结构评价: "现象→原理四点→分场景演示→可带走的一句话",是标准工具安利结构;"可抄参数+复制参数按钮"把教学闭环做进 demo,是真实用心的设计。缺点: 口播段与录屏段的画面质感断崖,23s 无信息空窗。

## 2. 视觉工艺

- **demo app 本身**: 完成度高于一般 vibecoding 演示——统一深绿主题、tab 导航、左右对比+中缝标签、底部参数条、状态角标("已标1处重点"),排版干净。参数 chip 用等宽字体,工程审美在线。
- **MG 页(scene_04/10)**: 深绿底+橙色编号+白标题+灰说明,克制专业;但与真人段(白墙、日光灯、竖百叶窗帘)反差大,观感"两张皮"。
- **信息密度**: demo 段中等(左侧"未使用"侧多为占位内容,如"概念A/概念B/例子/结论");口播段零。
- **动效水平**: 视频层动效≈0——录屏点击+页面内 Rough 抖动动画;无镜头运动、无转场设计(硬切)。手绘"抖动"动画是 Rough.js 自带库行为,不是视频动效。
- **一致性**: 硬字幕白字黑边全程;水印"Ning的笔记 bilibili"常驻;demo 主题色与结尾页呼应,尚有一致性自觉。

## 3. 水平定位

**5 / 10**。(a) 对标专业 MG 工作室: 3~4 档——视频工艺(运镜、转场、包装)基本缺席,实拍环境简陋。(b) 对标头部知识区 UP: 5 档——选题嗅觉好(瞄准"AI 画不出手绘感"的真痛点)、demo 工具设计有巧思,但制作执行粗糙: 23s 纯脸空窗、demo 占位词内容、无字幕排版设计。属于"点子 7 分、执行 3 分"的典型 vibecoding 分享视频。

## 4. 与"文章→自动成片平台"的差距拆解

**模板+组件可复刻(约 40%)**:
- scene_04"核心特点四卡"页与 scene_10"记住一句话"结尾页: 纯标题+卡片+胶囊列表,标准模板直接套。
- 硬字幕、水印、章节化结构。

**必须模型自由创作(约 60%)**:
1. **可交互 demo 网页本身**: 理解 Rough.js API、写出四场景对比 app + 参数条 + 复制按钮——这是本片的真正资产。模板管线无法覆盖,唯一路径是"LLM 现写 demo + 录屏脚本"。若平台想覆盖"技术教程"品类,需要"生成活 demo → 程序化驱动录制"这一全新环节(比渲染页面更难,因为要可交互、可复现操作)。
2. **录屏的操作编排**: 先点哪个 tab、圈哪句话、何时切分屏,依赖讲解逻辑;程序化录制需要把"操作脚本"与"旁白"对齐。
3. **真人信任感**: 出镜口播承担"人背书",这是自动成片平台结构性做不到(除非数字人,会损失真实感)。
4. **demo 内容语义**: "未使用 vs 已使用"左右分栏的对比语义,需要理解每场景"什么算丑、什么算手绘感"。

**结论**: 该片证明"教程品类"的核心资产是 demo 而非版式——对主人平台是坏消息(管线够不着),也是机会(若平台增加"代码生成可交互演示"插件,即可拿下 vibecoding 教程这一高频品类)。

## 5. 瑕疵(具体到帧)

- **scene_01(0.1s)/scene_02(0.4s)**: 开场即真人怼脸+内嵌小窗,窗口只占画面 ~1/4,绿板与便签内容在 1080p 缩放下不可读;两个场景时间戳几乎相同(0.1/0.43),说明 0~31s 内画面变化微小,钩子效率低。
- **scene_03(31.2s)**: 23 秒纯口播零画面辅助——全片最大空洞段。
- **scene_05(54.6s)**: 顶部 tab 栏第一个 tab"01 白板课堂示意"左上与 UP 水印重叠;左栏"概念A/概念B/例子/结论"为占位词,演示说服力打折;底部字幕"OK我将从4个场景来具体的展示一下Rough技术"语病("的"多余)。
- **scene_06(83.2s)**: 左栏便签的 emoji(星/火/图钉)与右栏手绘线的"对比点"不够直观,观众需靠旁白理解差在哪。
- **scene_09(116.3s)**: 红棕手绘椭圆压住被圈句子部分笔画(演示效果使然,但"重点"二字被圈线穿过,截图不可读);"这是使用Rough做的一个"字幕在句中被抽中,信息断裂。
- **scene_10(127.2s)**: 结尾页下半 40% 空置;标题句引号嵌套排版("「用手绘笔触画可交互几何」")在两行折行处略显生硬。
- 全片 1906×1080 非标准宽,平台兼容小瑕疵;录屏文字在部分帧有轻微摩尔纹。无"AI 味"配色问题(深绿主题克制),但真人段与 MG 段质感割裂是最大观感伤。

## 6. 制作方式线索

- 标签自带"vibecoding/经验分享/手绘风/Rough": 定位为经验分享而非成品展示;demo 参数条+"复制参数"按钮暗示 demo 本身可被观众复用,UP 把 demo 当作品集。
- 制作链条推断: AI 对话生成 demo(标签与内容口径一致)→ 真人录口播+录屏 → 简单剪辑+硬字幕 → 首尾 HTML 风 MG 页。
- 成本: 几乎为零(卧室布景、自然光、无包装);回报 822 播放/0 评论,互动率低说明分发与封面(未抽到)未做优化。
- 与对照组的含义: 同为"AI 写代码做视频"叙事,这条展示的是"AI 写 demo 当教具",而 BV1DTaH6fEYr 展示的是"AI 写渲染代码当成片"——后者才是与渲染平台直接可比的形态。
