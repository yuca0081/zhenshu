## 2. 视觉工艺

- **核心工艺——水彩模拟**: 疆域边界不是 GIS 多边形描边,而是颜料浸润效果: 每个势力色块带水彩的浓淡不均、边缘沉积(深色描边环)、纸面纤维纹理透色;势力消亡用"褪色/被覆盖/墨泪流淌"表达。这是 Canvas/WebGL 级的生成艺术,不是滤镜。
- **统一 UI 层**: 右上年份徽章(月桂环+IMPERIVM ROMANVM+罗马体年份,颜色随时代红→紫);左下章节卡(CAPVT 编号+标题+斜体一句话,羊皮底柔影);罗盘、山脉小符号、城市小字(ROMA/CARTHAGO NOVA/SYRACUSAE/ALEXANDRIA/CONSTANTINOPOLIS)。UI 全程不抢戏。

- **信息密度**: 视觉密度高、知识密度中——疆域时序大体准确(287 BC 意大利统一、212 BC 汉尼拔、115 AD 极盛、476 西亡、1453 君堡陷),但无数字标注、无事件日期文本(年份牌除外),属于"氛围向历史可视化"。

## 4. 与"文章→自动成片平台"的差距拆解

**模板+组件可复刻(约 15%)**:
- UI 层: 年份徽章、章节卡、罗盘、比例尺类装饰组件——标准的"状态驱动 HUD",spec 化容易。
- 章节制结构、时间轴驱动、收尾定格页。

**必须模型自由创作(约 85%)**:
1. **水彩渲染器**: 墨渍扩散、边缘沉积、纸纤维透色的 shader/Canvas 笔刷算法是本片的灵魂,组件库不存在,需 LLM 现写(简介明确"纯 JavaScript")。这是四条片中"模型自由创作"占比最高的一个。
2. **历史疆域时序数据**: 数十个时间点 × 数十个势力的领土多边形 + 兴衰节奏 + 颜色语义(红=罗马、蓝=迦太基、绿=希腊化/突厥、灰=日耳曼、紫=拜占庭),需要数据整理与艺术判断双重能力;平台管线没有"为叙事重建数据集"环节。
3. **隐喻系统的贯穿设计**: "stain/染/干/流"四个动词同时驱动视觉与文案,是内容概念层,任何模板都到不了。
4. **镜头编排**: 一镜到底的推拉节奏与 2200 年时间轴的对位。

**结论**: 这条片子代表"LLM 写图形算法 + 自备数据"的极限形态,与"模板+组件"平台几乎不重叠;平台的正确姿势不是复刻它,而是开放"模型生成的风格化渲染插件/自定义渲染器"接口,让它成为管线里的高级品类,否则此类内容永远在平台射程外。
