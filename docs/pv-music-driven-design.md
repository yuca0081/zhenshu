# 音乐驱动 PV 架构方案（草案）

状态：**2026-10-21 讨论定稿；同日第 0 步原型闸已跑通**（实录与缺口清单见 `docs/test-result/pv-prototype-gate-2026-10-21.md`，产物 `demo/pv-prototype/`）。交互架构图见 `docs/production-architecture-v3-interactive.html`（第二页签，URL 带 `#music` 直达）。先例素材：`demo/agi-mv-repro/`（人肉 MV 复刻：analyze_audio.py + shots.json）、`demo/ak-pv-repro/`。

## 一句话

发令枪从文稿换成音乐——**舞台还是那个舞台（渲染引擎/素材/风格库/段级流水线机器不动），换的是指挥**：以前指挥是念稿人，现在是指挥棒（节拍）。

## 三条铁律

1. **曲先行，分镜跟曲走**——这是唯一解，不是偏好：生成式做曲无法按给定分镜表精确作曲，所以分镜只认"实际生成/上传的那首曲"分析出的音乐地图（物理事实），不认曲 brief（创作意图）。
2. **LLM 听不了音频**——音乐理解必须本地算成 JSON 再喂：DSP 分析（上传曲/神经曲）或谱面直出（曲库曲）。地图脚本就是音乐工位 agent 的耳朵。
3. **纯音乐、无歌词**——歌词/字幕/TTS 整个退场，时间轴来源唯一化；生成曲+无歌词=版权干净。节拍检测对鼓点清晰的曲风最准，一期只承诺这类曲风，曲风怪预留人工校正口子。

## 两种入口（想法页签，一个表单）

| 模式 | 输入 | 音乐工位的活 |
|---|---|---|
| A · AI 做曲 | 一句话主题（+可选氛围标签） | 三格全跑：brief → 做曲 → 地图 |
| B · 带曲入场 | 一句话主题（必填）＋上传音频（+可选氛围标签） | 只跑第三格：地图＋读谱 |

模式B = 做曲工具的第三个后端，架构零改动。情绪色彩层（悲伤/恢弘）地图推不准（只有快慢/能量/亮度的物理层），靠主题+氛围标签+终审门人工纠正三层兜底——所以主题必填，不能只扔文件。用户上传他人曲目版权自担，产品提示不拦。

## 准备阶段

**① 音乐工位（一站三交付，ReAct agent）**：一个会话交付三件套——曲brief（主题→曲风/情绪/BPM 带/能量走向，顶替"起稿"位子）→ 做曲/选曲工具（拿音频）→ 地图脚本（节拍网格/段落/能量 JSON）。
- **自检环**（合并成一站的核心理由）：agent 出完曲立刻跑地图，拿 JSON 对 brief 数字比对（"要 128 拍爆发收尾，出来 120 拍平铺 → 调参重做"）。拆成三个工位这个闭环就不存在。
- **护栏一**：做曲与地图分析都是白名单确定性工具，agent 只准调用判读、不准手改数据——"地图=物理事实、同输入同输出、可缓存可重放"不丢。
- **护栏二**：做曲重生成封顶 ≤2 次，超限带伤交门或退回选曲兜底。
- **产物**：三件套各自落盘（brief / 音频 / 地图）——交付主体是一站，产物分开，门的试听与反馈路由、下游分镜全不用改。

**② 分镜工位（判据换血）**：音乐地图 × 视觉概念 → 镜头表（每镜头占哪几拍、什么情绪、首/末帧承诺），镜头边界钉在节拍上；切段判据从"话题完整"换成"音乐段落/乐句"；风格选择整套复用现行风格工位（风格库/样张/设计系统）。产物 shots.json 形态（agi-mv-repro 已有人肉先例）。

**打包终审门（唯一人工门）**：brief＋音频试听＋地图＋镜头表（＋风格包）一次确认，拦在昂贵制作之前。反馈路由：改感觉/节拍不对 → 重①（可先人工校正地图再进）；改镜头 → 重②。

## 制作阶段（机器全复用，判据换血）

- **音乐地图＋音轨 = 发令枪**（TTS 的位子）。
- **写画面 ×N 并行 ≤4**：镜头=段=文件=时间轴=渲染单位=缓存单位=调度单位，画面是 t 的纯函数——铁律不变；新注入=镜头 brief＋节拍事件表（切点/重拍）。镜头比解说段碎（一两秒一个），设计调用变多，总帧数不变（歌长定死），成本同量级或略高。
- **程序 check（逐镜头）**：工程门（lint/不变量/回放门禁/接缝亮度闸）照搬＋新**卡点机械闸**：切点偏离节拍 >N 毫秒打回、段落-画面能量匹配机检初筛——能机器判的绝不花 LLM 的钱。
- **段渲染**：照搬，~20s/镜头，check 过即渲；重渲只花一个镜头的钱。
- **镜头审（判卷）**：段审骨架照搬（锚点帧+判卷+重写≤2 轮续写+patch+签名刹车）；新判据=画面对情绪、节拍感（动效落重拍）、段落匹配（副歌够炸）。软判据拿样张迭代（同动效章节方法论）。分工：卡点准不准归 check，这里只管好不好看、对不对味。
- **拼接**：镜头视频按序拼＋挂原曲音轨——mixBGM 简化版（去闪避、去循环，曲长对齐＋首尾淡出），音轨管道同源。
- **全片终审（判据换血）**：抽帧=镜头界+段落界+副歌界；查卡点整体准不准、节奏与能量曲线对不对、段落-画面情绪匹配、拼接完整性。回合预算/按镜头重渲循环骨架照搬。

交付物=音频文件（＋地图），下游不认来源，工位整体可插拔。

| 后端 | 状态 | 说明 |
|---|---|---|
| **#0 曲库 v2（先行）** | 已有，待改造 | `ai/make_bgm_v2.py`（MIDIUtil 写谱＋FluidSynth 渲染，MIT 音色）：确定性/免费/零显存/零授权坑；**节拍地图从谱面直出，DSP 只做校验，卡点精度天花板**。改造：曲长 33–60s 循环垫 → 整曲多段落（能量弧线＋目标时长，from_bar 声部递进机制已在）；清单附节拍/段落/能量 JSON。选曲层直接搬 bgmpick 骨架（LLM 挑＋机械改判＋填空不推翻），提示词换 brief |

## 复用清单（从文稿驱动白嫖）

渲染链（canvas→帧→ffmpeg）· 段级流水线骨架（逐段生成+判卷+重写轮回）· 审查机器与机械闸方法论 · 成本闸/磁盘缓存/事件流/过程页 · 风格库/样张/素材工位/设计系统 · 续写+patch 修复 · **BGM 三件套**（曲库=后端#0、bgmpick 选曲骨架、mixBGM 音轨管道）。

## 全新件（零家底，要从零做）

音乐工位（agent＋工具接口＋曲库整曲改造）· 卡点机械闸 · 镜头审/终审新判据 · 拼接挂原曲 · 想法页签双模式入口（上传 UI）· 地图脚本补段落切分与能量包络（节拍检测已验证）。

## 分期路线

- **第 0 步 · 原型闸**（✅ 2026-10-21 已过）：曲库后端出 80s 整曲＋谱面地图 → 半自动走通 40s 副歌片段全链，机械闸全绿、看片合格、缺口清单 10 条归档。最大发现：裸自相关 BPM 有 ±2–3% 误差＋八度混淆——模式B 上传曲的地图脚本不能裸用，主判据必须是「onset→网格贴合度」而非 BPM 估计。
- **M1** 音乐工位落地：工具接口＋曲库后端改造＋地图脚本补段落/能量。
- **M2** 分镜工位＋写画面节拍事件注入。
- **M3** 卡点机械闸＋拼接挂原曲＋镜头审/终审新判据（样张迭代）。
- **M4** 想法页签双模式入口＋上传链路（模式B）。
- **M5**（远景）神经/API 后端离线出库进曲库。
