## 二、问题清单

### P1 致命（出不了片的根因）

**P1-1 审查"系统性刹车"×修复轮不收敛：9 轮管线执行全灭**
- 现象：三次尝试、九轮执行，无一走完。失败链条：`seg check 三轮未过` / `系统性刹车：2 个不同轨道出现同类别 xxx high` 交替出现，自动重跑 2 次烧完即终局。刹车类别逐轮漂移（content → first_last → subtitle → content），每轮被判 high 的段落也在换（seg11→seg12/seg04→seg07→b05/seg04）——审查意见呈**掷骰子式分布**，但刹车机制把"两段同类 high"当系统性问题处死整片。
- 根因层：①画面审查（判卷 ReAct）对单段出具 high 的比例偏高且不稳定；②刹车阈值（2 轨道同类）对 13 段并发审查来说过灵敏；③场景代码由 LLM 重写，同一个坑反复踩（seg07 的朱橙弧线装置反复生成负半径 arc()），修复轮无法收敛。
- 后果：**13 段视频在这种"审查随机惩罚 × 整片连坐"机制下几乎不可能走完**。每轮重跑还重写全部场景代码（`llm.usage scene segXX` 反复出现），约 2 小时 token 烧在重复劳动上。
- 证据：manifest `produce.retry` ×4、`review.brake` ×5、`produce.error` ×2；截图 `t28_second_failure.png`。

**P1-2 审查工位"回合预算耗尽"后管线挂死：无超时、无失败落账、无心跳**
- 现象：12:07–12:08 审查工位连报两条 `回合预算耗尽仍未提交`（`review.bnd_error` b05 / `review.seg_error` seg04）后，管线进入完全静默：LLM 目录 12:02 后无新文件、审查帧渲染 12:05 后停、manifest 12:08 后零新增、服务端日志 12:03 后零新增。**直到测试结束（12:26+）UI 一直转圈"制作管线运行中"**，不失败、不重跑、不报错。
- 用户视角：平台"看起来在干活"，实际死透。没有任何提示告诉用户该停掉重来。
- 证据：`t30_hung_after_cancel.png`（12:24 仍运行中）、manifest 尾部、server.log 尾部。
- **楔死实锤（重启后自动续跑的 run10 复现并排除最后一种解释）**：run10 于 12:52:59 边界打回 `b08 → seg08`、12:55:27 段审打回 `seg02 r1`，12:55:41 后全管线静默；**LLM 单次 600 秒超时早已过期（13:05:27）仍零动静、llm/ 目录无任何重写产物**——排除"上游 API 卡住"的解释，坐实打回指令没有到达任何工位。根因定位见 `docs/produce-reliability-fix-plan-2026-10-17.md` P0-1：`dispatchRewrite` 的阻塞发送（`segpipe.go:838`）无视 ctx/无 worker 存活保证，而"账本已审段不起 worker"（`segpipe.go:437`）与"打回时现起 worker"只在终审路径实现（`segpipe.go:479`）——边界审把打回路由给恢复进场的无 worker 段即触发；泄漏的审查 goroutine 又卡死收尾 `auditWg.Wait()`（`segpipe.go:487`），终态永远落不了账。

**P1-3 「停止制作」杀不掉挂死的管线**
- 现象：12:20:29 点击「停止制作」，`POST /api/projects/:id/cancel` 返回 202 受理；6 分钟后 UI 仍显示"制作管线运行中"、停止按钮仍在、manifest 无 cancel 落账。挂死的审查池连取消信号都消化不了。
- 用户唯一逃生 = 重启服务（mem store 下聊天记录还会丢）。
- 证据：server.log（12:20:29 POST cancel 后无任何后续）、`t30_hung_after_cancel.png`。

### P2 中等

1. **对话栏 Enter 发送静默失效（⚠ 后已改判，见下）**：11:00 的「开始」能 Enter 发出；11:31、11:52、11:53 三条「继续」fill+Enter 后**全部静默留在输入框**——不在消息列表、无报错、无 toast，只能改点「发送」按钮。
   - **改判（同日补充实验）**：用真实键击路径（逐键输入 + 真实 Enter）重测，发送正常（服务端 `POST /chat` 202 收到）。三次失败全部发生在 Playwright fill+press 合成输入下，且服务端 GIN 日志里连 429 都没有——请求根本没发出。**结论：自动化输入假象，非平台 bug**；前端 ChatPanel 的 IME 防护逻辑本身正确。昨日报告的 P2-4 应同步改判。真实用户不受影响。
2. **准备阶段中间产物无处可看**：①文字稿 10:38 就完成了，但想法页工位卡片点击无展开、「文稿」页签恒为 0 字（自动稿不回填）、对话栏无稿——**用户要等 16 分钟全部跑完才能在终审页第一次读到文稿**；②风格样张 10:42 已出，「风格」页签却停留在"①选风格"库选择界面，直到 10:54 全部完成才切换成样张态，中间 12 分钟看不到自己的样张。准备期用户处于"黑箱等待"。
3. **重跑成本失控**：自动重跑/「继续」都会重写全部 13 段场景代码并重渲染，单轮 10–18 分钟；三次尝试 9 轮执行 ≈ 86 分钟、海量 token，产出为零。TTS 跨轮有缓存（11:31 起 tts 秒级完成，✓ 好设计），但画面层没有等价的"过检段落复用"。
4. **新建视频弹窗创建成功后不自动关闭（昨日 P2-1 复现）**：项目已进侧栏、工作区已加载，弹窗还开着且保留上次主题文本，极易误点再建一个重复项目。证据：`t02_after_create.png`。

### P3 轻微 / 观察

1. **准备耗时 21 分钟 vs 界面承诺"一般几分钟"（昨日 P3-1 复现）**。预期管理失准，用户会以为卡了。
2. **文案打架（昨日 P2-5 部分复现）**：想法页说"每步的详细动作在右侧「事件流」有账"，但该面板叫「**制作**事件流」且准备阶段全程空白（`t08_eventstream_during_prep.png`）；风格页自称"唯一必须你拍板的门"，终审页又有"打包终审"门——本次两道门状态写对了没打架，但口径应统一。
3. **"有进展我随时时报"未兑现**：智能体在制作开始、两次失败、两次重启时各发了一条，中间约 70 分钟的拉锯（9 轮执行、几十次打回）对话栏零插话，全靠用户自己去事件流翻账。
4. **工具层观察（非平台 bug）**：ZCode 内嵌浏览器对本页大量按钮的 Playwright 定位点击（locator.click）持续 3s 超时，坐标点击（真实鼠标事件）全部正常——真实用户不受影响，但自动化测试/无障碍工具在此页面上基本不可用；另外制作重负载期间浏览器截图面 3 次超时（DOM 快照正常）。

## 四、给下一步的建议（按优先级）

1. **审查判据先校准再上强度**：单段 high 意见的稳定性（同一渲染物多轮审查是否同判）是根子——先做"同物重审一致性"测量，再调刹车阈值；或者把刹车从"处死整片"降级为"标记该类别段落重修 + 人工提示"。
2. **管线必须有看门狗**：任何工位静默超过 N 分钟（无 LLM 调用、无帧产出）应自动落 `produce.error` 并释放，宁可失败不可假活。
3. **cancel 必须可达**：停止要能打断/抛弃卡住的工位（超时强杀 + 落账），否则 P1-2 无解。
4. **过检段落跨轮复用**：重跑只重做被打回的段，别整片重写（TTS 缓存已证明可行）。
5. **修 Enter 发送**（复现率 3/4，用户感知是"平台不理我"）。
6. 准备期中间产物（文稿/样张）即时上屏；弹窗创建后自动关；"一般几分钟"文案改实际区间。
7. 终审的 `window.confirm` 换应用内弹层（本次侥幸可用，昨日环境挂死的根因还在源码里）。

## 五、测试方式说明

- 环境准备动作：仓库根 `./bin/server.exe` 起服务（8080），其余全部通过 GUI 完成；未修改任何项目代码/数据，未预填任何项目状态。
- 观察手段：页面截图 + 只读 DOM 快照（黑盒），另以只读方式参照服务端 manifest 账本与 GIN 日志做时间线对账；`/prep`、`/api/projects/:id` 接口仅作只读监控。
- 原生 confirm 对话框通过浏览器对话框 API 以"用户点确定"方式接受，属正常用户操作路径。
