## 当场修复的新 bug（随本次提交）

### 高-1：边界审打回后永不重派（整线冻结）

- **现象**：12:34:36 起全管线静默 21 分钟，无事件无报错，干等 32 分钟看门狗。
- **根因**：b10 打回 seg10 重写。旧 `boundaryTracker` 的「在飞」标志只在「过审记账」分支复位（`gp==sg && gn==ng`），而打回路径不记账（`genP/genN` 保持 -1）→ 标志永不复位 → 被打回段重写过审后该边界再无人重派 → `allPassed()` 永假。
- **修复**：`bndBusy` 在飞表由 `auditBoundary` 完成时自释放（defer，含打回路径）；跟踪器双检防并发重派。**回归测试** `TestBoundaryTrackerRedispatchAfterRework` 锁定三段行为：未记账即派发 / busy 期间不重派 / 释放后代际失配即重派。

### 高-2：终审意见单被空 id 误杀（预算空转）

- **现象**：成片已就绪，终审连续两轮「回合预算耗尽仍未提交」，烧光自动重跑额度。
- **根因**：终审提示词与 submit_verdict schema 都没让模型给 findings.id，模型交的 3 条意见全空 id；校验器却按「id 重复」拒收。而收下后 `AssignIDs()` 本来就会把 id 全部覆盖成 f1..fN——**校验一个必被覆盖的字段，纯误杀**。
- **修复**：删掉 findings.id 去重检查（reassessment 对上一轮服务端编号的复核逻辑保留，那个才有意义）。修复后终审一次提交成功并正确打回 seg01。

### 中-1：注入图缩略图接错工位（本次纠正）

- MessageImgs 旧接在 preReview/frameQA——**这两处在 10-16 段级流水线里是旧路径专用**，新流水线带图的是段审/边界审/终审（review.Loop 的 KickoffIm），路径引用没接 → 过程页缩略图在真管线上永不出现。
- 本次：`Loop.KickoffRefs []llm.ImgRef` + 落留痕走 MessageImgs；三工位的锚点帧/样张/末首帧/终审帧格全带项目内路径+标签；`extractFrame` 返回相对路径；取件白名单补 `reports/audit/`；留痕截断改保头保尾（打回意见单在尾部，旧截断正好砍掉排查最想看的部分）。
