## 三次刹车与两个真 bug

1. **seg03「content@N1 连续两轮 high」**——画面承诺的线稿小人剪影缺失。根因：
   模型在 style 属性里写 JS 属性名 `zIndex: 5`，CSS 解析器静默丢弃整条声明，
   canvas 掉回 DOM 序底层被不透明卡片盖住。修复轮修不掉是因为模型带着同样的
   坏习惯重写（刹车刹得对）。救法：手补 `z-index: 5` 后重开制作（场景复用走
   输入指纹，手补生效）；治本：scene_lint 新增 **T11** 机械打回 CSS 语境驼峰
   属性名（f0c296d）。重开后 seg03 复审 0 high。
2. **seg10「subtitle@t=1.45 连续两轮 high」**——审片员说 seg10 开场 2.4s 有
   "上一段残留字幕"，但 seg10 的字幕就是它自己旁白 N14 的烧入。根因是更大的鱼：
   **segSentences 从 N1 起前缀匹配，seg02 起的段全部匹配失败——段审的旁白节和
   锚点 N 标签对非首段从出生起就是空的**（c028f75 埋的，此前全部片子带伤跑）。
   审片员被喂"本段无旁白"+brief 承诺"全屏只留主句"，把自己段的字幕判成残留；
   场景重写碰不到音频烧入字幕 → 修复轮永不可解。修：段首句全表定位再顺序吃
   （f0c296d，四向回归锁）。修复+重启后 seg10 复审过，全片终审一轮过。
3. 中间一次是 8080 被并行会话重启，prep 链随进程消亡——工件即状态，重放续跑
   （文稿跳站），衍生风格还从库里认领了上一世注册的「夜讲金线」。

## 教训

- **签名刹车是金矿**：两次"不可解"各挖出一个平台 bug（审查材料注入全盲 +
  lint 空窗），盲目的第三次重跑只会烧钱。
- 审查工位的输入可信度要进巡检清单：注入材料缺维（旁白节空）时审片员的结论
  逻辑自洽但前提是假的——"判卷对不对"先要问"它看到了什么"。
- 场景文件手补的生效条件：复用判据是输入指纹（旁车），不看产物字节——补产物
  不动输入即可被复用。
