# 3 分钟测试片真机全链实测（段落制换骨后首跑）2026-10-30

## 目的

验证 d317196 段落制换骨（渲染单位从分镜换成段落单元）的真机全链出片。这是 PARA_SMOKE（零 LLM 冒烟）之后的第一次真 LLM 全链。

## 项目

- **p20261030-003621**「深夜便利店3分钟测试」
- 带稿直建：810 字 / 8 段测试稿（server/test-body-3min.json），9:16，无风格库条目（模型自由发挥）
- project.json 手工加 `"target_seconds": 180`（带稿直建 API 无此字段，缺省 120s≈540 字的老问题仍在）

## 结果：出片 ✅

- **成片**：`renders/main.mp4` 146.13 秒（2分26秒）、165MB、9:16，终审通过（折算 4.5 分）
- **时长没到 180s 的原因**：prep 文字稿润色把稿压到 660 字（LLM 行为，非管线问题）
- **段落制全链验证点全过**：
  - units.json / units-storyboard.json 真机落盘：7 个渲染单元（6 段落，para04 长段自动拆 a/b 两 part），每单元合并旁白 + 内部 segs（首拍/末拍边界衔接"接续同舞台"）
  - segmap.json 14 行（分镜定位），timeline 单元行
  - 逐单元渲染 + 回放门禁（check.seg_replay diff=0）+ 接缝检查 pass
  - 段审判卷、系统性刹车、自动重跑、全片终审五查全走了一遍

## 环境坑两枚

1. **8080 起不来**：本机 PID 14480 把 8080 当出站连接源端口占着（ESTABLISHED），bind 被拒。换 `ADDR=127.0.0.1:8082` 解决。
2. **edge-tts 7.2.8 全灭**：微软 403（WSS 握手拒，Sec-MS-GEC token 被封），`pip install -U edge-tts` 升 7.3.1 后恢复。**待办：版本固化**，避免下次环境重建再踩。

## 制作三轮史（最大发现：长单元写画面不收敛）

- **r1**：字幕刹车——3 轨道同类 "subtitle" high（para02 字眉压注解重叠、N7 句字幕条与旁白进度错配）。另有一轮 para01 契约检查三轮未过触发 produce.retry。
- **r2**：content 刹车——para02（brief 承诺的便当/关东煮图标全程未画）、para04a（成本条 bars2 与营收条 bars1 同位置叠加，bars2 淡入时序缺失 → 渲染帧"空格子"）、para06（三组标题层叠压成乱字团）。registry 里元素都在，**是动画时序没写对，判卷抓得准，不是误杀**。
- **r3**：手动 POST produce 重开（刹车记账是内存态随 run 重置，过审单元走 render.seg.cached 缓存），收敛出片。

**规律**：重灾区恰是复杂度最高的单元（para02 21s、para04a 36.8s/3segs/11 元素、para06 30.5s）；12s 级短单元全部一次过审。长单元（>20s 多 seg 多元素进出）的 comp 动画时序是写画面 LLM 的稳定弱点，也是重写 token 的最大黑洞。

## 成本

全项目 LLM 记账：**180 calls / prompt 1.33M / completion 162k / cached 631k**（命中率 47%）。两轮刹车重写（全单元重写）是花费大头；r3 靠缓存只重写未过审单元，成本低得多。
