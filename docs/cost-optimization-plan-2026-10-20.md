## 〇、一句话目标

把 60 秒片的消耗从 55-60 万 token 压到 **15-25 万**（诊断账目标线：每分钟成片 < 25 万 token），墙钟从 2.5 小时级砍半以上——手段是拆掉「审核占七成」的结构性浪费，把修复从「失忆重写」改成「续写打补丁」。

## 二、方案一：撤销段审（对应 D1）

### 2.1 现状与动机

- 段审（ReAct 判卷 agent）是最大成本中心：段审+边界审占总 token 69-76%，单次审 5-10 分钟，最高单审 14.4 万 prompt。
- 段审审的是段内「内容对不对」（六维：内容一致/事实/风格/首末拍合规/装置落点/字幕文字），打回触发重写闭环。
- 用户的结构判断：分镜已是「文件→段→镜头」层级，段间拼接早已是设计系统模板零改动；段内一旦组件化（P2），段审就没有存在理由——与其瘦身续命，不如直接撤。

### 2.2 改造设计

1. **开关式撤销，不删代码**：加配置开关（如 `PRODUCE_SEG_AUDIT`），**默认 off**。关闭后段级流水线变为：
   `写画面 → 程序 check → 渲染 → 边界审 → 拼接 → 全片终审`
   回滚 = 改一个环境变量，不动仓库。跑稳数条片后再连代码一起清理。
2. **边界审触发改线**：原触发条件「两侧段审都过」改为「两侧 check 都过且都渲完」。边界审本身保留（只看边界短片段+末首帧对，便宜）。
3. **全片终审保留**，升格为**唯一多模态兜底**：12-16 帧抽样，查 pacing / deadair / 拼接完整 / 渐变跑偏，回合预算 ≤4。段审撤后它的拦截账要单独记。
4. **随段审休眠的机制**（跟开关走，不单独动）：锚点帧预截、取证帽、图历史裁剪、findings 签名与打回分诊、修复轮「先复核既往意见」。

### 2.3 风险与回滚

- **已知代价**：内容型错误（画面与稿子不符、该有的元素没画、事实错误）失去每段把关，靠全片终审抽样兜底。拉普拉斯妖手工复盘 13 FAIL 中 6 真伤——这类真伤今后可能静默进成片。
- **回滚手段**：开关拉回即可恢复原流水线。
- **观察指标**：全片终审 findings 中「本该段审抓的内容型问题」占比。连续数条片偏低 = 撤对了；偏高 = 开关拉回并重议。

## 三、方案二：修复轮改「续写 + patch」（对应 D2）

### 3.1 现状（要砍掉的钱）

`scenegen.go` 现状：修复轮**新开失忆对话**，把上一版 HTML 全文（7-10KB）作为 `prevHTML` 塞回 user prompt 当底稿，模型**整文件重抄一遍**只改几处。即 C3：改一个元素重抄 7-10KB，每次修复 1.2-1.7 万 prompt + 3-5k completion。平台已在付「历史」的钱（每轮重贴全文），却没拿到「记忆」的收益。

### 3.2 续写（改「谁来修」）

1. 打回时**不重开对话**：保留首轮 messages，把审核/check 的错误清单作为新的 user 消息追加，原写画面 Agent 在同一对话里接着回复。
2. **对话历史落盘**到项目目录（如 `llm/comp-<seg>.history.json`），进程重启/断点续跑后能接着聊——不然重启即失忆，续写白做（哲学同 P0 磁盘缓存）。
3. **护栏**：
   - 同签名（诊断归一化签名，复用 `checkSig` 口径）连续两轮未收敛 → **切断续写**，新开干净会话重写（防第一版思路就歪、被自己带偏）；
   - 续写轮数帽 ≤3（防历史无限膨胀；GLM 端点无前缀缓存，历史每轮照付 prompt）；
   - 现有的「同签名回退上一版过检画面」刹车保留，作为续写收场兜底。

### 3.3 patch（改「交什么」）

1. 修复轮模型**只回改动清单**（JSON），覆盖三类改动：文字（改文案）、样式（颜色/字号/位置）、时序（元素出现/退场时刻）。示意：

   ```json
   {"patches":[
     {"target":"#title3","set":{"text":"量子纠缠"}},
     {"target":"#orbit","set":{"timing":{"start":3.8}}}
   ]}
   ```

2. **程序侧应用与校验**：逐条校验 target 真实存在（元素注册表 / 选择器命中）→ 全命中则程序自动替换生成新文件；任一未命中或 JSON 不合法 → **整单回退「重写全文」老路**，保证不卡死、不烧第二轮。
3. patch 格式细则（时序改动如何落到 GSAP timeline、样式改动如何避开 lint 红线）在实现阶段定稿，写进本文 §八。

### 3.4 适用范围

- 程序 check 的修复轮回喂（撤段审后它是唯一高频修复源）**必须**走续写+patch；
- 首写仍是全文生成（无历史可续）；
- 用户手动改画（rework）走续写（有首轮上下文）；换风格等「推倒重来」类不走续写。

## 四、保留的门禁盘点（撤段审后的安全网）

| 门 | 查什么 | 性质 |
|---|---|---|
| 静态 lint（scene_lint.py） | 格式契约 / 禁真实时钟 / 禁未种子随机 / 禁 CSS 动画 / 禁网络 / canvas 纯函数 / JS 语法 | 程序化 · 零 token |
| hyperframes check | 元素重叠 / 越界与字幕禁放区 / 对比度 / 字体存在 / 运行时错误 | 程序化（外购件，'Ph' 幽灵已知内伤有绕法） |
| 回放门禁（canvas 段） | 同时刻两轮截帧逐像素一致（防藏非确定性） | 程序化 |
| 边界审 | 收尾播完 / 入场起步 / 接续成立 / 闪帧黑帧 | 多模态 · 便宜（帽 8 次取证） |
| 全片终审 | pacing / deadair / 拼接完整 / 渐变跑偏 | 多模态 · 便宜（12-16 帧，预算 4） |
| 打包终审门 | 文字稿+风格包+分镜稿人工确认 | 唯一人工门（制作前） |

**留出的空当**（撤段审的已知代价，见 §2.3）：内容一致 / 事实 / 风格走样 / 字幕文字正误——机器门全部不查。

## 六、实施顺序

- **第 0 步**：工作区 7 个未提交文件先落袋（哨兵链修复 / 幽灵 TDZ 复检 / 重审去金样张，测试已验全绿）——新改动与它们动同一片代码，须先提交隔离。**等用户点头。**
- **第 1 步**：段审开关化撤销 + 边界审触发改线 + 写画面提示词加「内容忠实」硬条款（§八·5，对冲撤审空当）。
- **第 2 步**：续写（对话历史落盘 + 断点恢复 + 两条护栏）。
- **第 3 步**：patch 协议（格式定稿 + 程序应用 + 校验回退）+ 修复调用轻量提示词（§八·1，与 patch 是同一件事）。
- **第 4 步**：跑一条实测片对账（token / 墙钟 / 全片终审拦截账），数据回填本文。
- **第 5 步**：收尾——架构图 HTML 同步更新（老规矩：图随方案改）；然后逐工位商量系统提示词（写画面 Agent 第一）。

## 七、验收线

1. 实测片 token ≤ 25 万/分钟成片；墙钟 ≤ 75 分钟（60s 片口径，第 4 步实测定格）。
2. 首写通过率（check 一次过）不低于改造前——patch 修复不得引入回退全文的退化常态。
3. 全片终审拦截账中内容型问题占比连续 3 条片低于约定阈值（阈值第 4 步定）——超标则开关拉回段审并重议方案。

### 提示词修订方案（写画面工位，2026-10-20 讨论定稿方向；其余工位照方抓药）

> 现状澄清：写画面「系统提示词」本身仅两三句，负担在每次调用整套重发的注入包（契约摘要 11 条 / 设计系统全文 / 金样例整份 HTML / 词序表 / 布局与动效规则 / 修复反馈含 prevHTML 全文）。prompt 占总 token 79-84% 且一段调用 2-10 次，提示词瘦身是全链路乘法。七刀：

| # | 改什么 | 并入哪步 |
|---|---|---|
| 1 | **修复调用轻量提示词**：续写+patch 落地后，修复轮只带 patch 格式说明+错误清单（契约/设计系统/金样例已在对话历史，不重发）——最频繁的调用换最轻的包 | 第 3 步 |
| 2 | **账本裁规则**：判断标准＝「违反一次的代价 ≥ 每次重复的成本」才留常驻。canvas 接线/timeline paused 留；几乎不自发违反、lint 兜底的（@import/Worker/video 类）撤出。从 manifest 拉 lint 触发记录，从没触发的就是白背的 | 第 4 步后（要数据） |
| 3 | **金样例瘦身+升级**：整份 HTML 是最大单项注入；只留结构骨架（template/timeline/接线/一个代表元素）；动效做成「有性格」的版本（教训：模型被样例锚住的力量大于规则，样例朴素则规则全废） | 第 4 步后 |
| 4 | **稳定前缀布局**：跨调用不变部分（契约/设计系统/金样例/规则）前置，段变量+修复反馈后置——换有前缀缓存的端点自动吃缓存价 | 第 4 步后 |
| 5 | **内容忠实硬条款**：brief 首拍/末拍承诺必须可见落实、旁白点到的关键实体必须出现——撤段审后内容对齐只剩提示词+终审抽样，几句话买漏网率 | 第 1 步（随撤审同步） |
| 6 | **禁令改写为默认写法**：正指令遵从率高于负禁令；纯「禁 X」条目转成「默认怎么做」 | 随 1/3 顺手 |
| 7 | **防膨胀机制**：加一条新规则必须删一条旧的；定期拉账本，没触发的撤、反复触发的改写而非加长 | 立规矩，即刻生效 |

### 二阶优化（已识别，排已拍板第 1-3 步之后；红线＝不过度打磨幸存审核层）

- **全片终审重进瘦身**（三项里最实在）：终审发现问题 → 按段重渲 → 重进终审时，不再全套重发 12-16 帧，只注入**被重渲段的帧 + 上一轮意见单文本**（未动过的段上轮已看过）。重进一次省一小半。
- **边界审/终审分模型**：判卷是"看图勾表"式活，走便宜快的小模型；误报记账护航，升了就换回（与挂账的分模型决策合并处理）。
- 判卷提示词修订：撤段审后边界审与终审的职责边界重新划一遍，随本节提示词方案一起过。
