## 修复项（AI 使能，非机械闸）

### A：审查 Loop 的并行 tool_calls 消息契约（复活全部段审）

**落点**：`server/internal/review/review.go` Run 循环（约 L186-206）；`server/internal/prep/loop.go` 同构拷贝。

**改法**：每轮工具执行改两遍扫描——第一遍执行全部 tool_calls 并把 N 条 tool 消息**连续**追加；第二遍把本轮所有 Images 合并成**一条** user 附图消息追加在本轮最后一条 tool 消息之后。保持"图走 user 消息通道"设计不变，只修 contiguity。`trimStaleImgs` 记账簿同步调整。

**测试**：mock ChatClient 发并行 tool_calls（≥2），断言 msgs 结构：assistant 之后 N 条 tool 连续、附图唯一且在块尾。回归用例复刻 400 形状断言不再产出。

**量级**：S。修完全部段审/边界审/终审恢复真检——这是 B 项生效的前提。段审复活后，黑帧这类"承诺元素不可见"问题本就属于段审判据范围（分镜 brief 对照），由 AI 在段级拦下。

**状态（2026-11-03）**：已落地。`review.Loop` / `prep.Loop` 改两遍扫描（全部 tool 消息连续追加 → 本轮附图合并成一条接块尾），回归用例在 `review/loop_toolmsg_test.go`、`prep/loop_toolmsg_test.go`。触发落地的实证：p20261102-204948 素材链测试 9/9 段审仍全数 HTTP 400 降级（该片终审通过但段级真检为 0）。

### B：重写轮喂失败帧截图（让写手对着证据改）

**落点**：`server/internal/produce/scenehistory.go:121`（检查回喂拼装处）+ 终审打回重写清单生成处。打回意见附带被点名的 anchor 帧 data URL（≤2 张/段，复用 review Loop 的 KickoffIm 通道与 ValidImageData 拦截）。

**说明**：comp 生成调用目前纯文本；llm.Provider 已支持 image parts（prep 通道在用），扩展该调用路径即可。成本：每轮重写多 ~1000 token 图载荷，可忽略。

**量级**：S-M。这是防"三轮同错"的关键——写手看到的是"这帧里横带就是没出来"，自己判断病根，而不是对着一句转述猜。

### C：降级放行的可见性（小改，可选保险丝）

段审降级时，在终审 kickoff 里对该段标注"段审未完成，请重点核查"（woundedNotes 已有账，补一条提示注入）。A 落地后降级应归零，此项是保险丝——把信息给到 AI，由终审自行加权，不做机械拦截。
