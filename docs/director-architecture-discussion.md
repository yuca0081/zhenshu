# 导演层架构讨论纪要（2026-10-14）

> 与 AI 协作完成的架构讨论实录与结论。起点：导演层两介入点（f1097f2）刚落地，讨论"像真人剧组一样分工"的工位架构应如何演进。最终产出一份可实施的方案，含三次中途修正。

## 一、讨论路径与关键结论

### 1. 起点：工位化诉求 → 发现真问题

初始设想是"像真人剧组那样设岗"：前期三件套（文稿/分镜/风格）不动，制作阶段导演统领，配音先行，段级代码质检，导演看画面满意才渲染。

对照代码逐条核查后修正认知：

- **"导演满意才渲染"现状已有七成**——prereview 本来就是渲前逐段截帧视觉审 + ≤2 轮修复；净增量比设想小得多，是"考卷升级+时机前移"的优化，不是新架构；
- **"质检走代码"接不住最伤片的问题**——内容缺失型 bug（该出现的没出现）代码全盲，是拉普拉斯妖实验的实证结论，视觉验收不能省；
- **渲后 frameQA 不能砍**——转场/退场类动态判据的证据是渲后段片边界帧序列，渲前 snapshot 截不出（prereview.go 已知取舍），它是动态问题的唯一工位；
- **"导演统领"名不副实**——导演对分段/时长无结构权（applyDirectorPlan 只动 arc/motifs/beats，防幻觉的刻意设计），是执行导演；
- **自产自收风险**——写预期（定调）与按预期验收（审片）同源，E2E 样本 n=1，误报率未知，轮数预算不能拍脑袋。

### 2. 导演前移 → 形式选"阐述先行"，拒绝"审稿循环"

把导演介入点从"分镜后补注"前移到"文稿之前定盘"，解决"烂分镜进来导演只能顺着补注"的结构性问题。两种形式对比：

- ❌ **审稿循环**（文稿→导演提意见→改→再审）：意见是口味不是事实、循环失控、烧用户交互等待时间；
- ✅ **阐述先行**：文稿之前产出《导演阐述》（plan 档 1 次调用），顺流程向下游灌注。文稿/分镜是全系统唯二零审查的杠杆环节，阐述让它们第一次有眼睛。

### 3. Agent 形态：三层分工，控制流归谁谁说了算

判据不是"剧组的头衔"，是**控制流归谁 + 有没有工具需求**：

| 层 | 形态 | 现状 |
|---|---|---|
| 主管 | 唯一对话 agent（react.Core + 工具表 + 播报钩子） | 新增 read_brief/edit_brief |
| ReAct 工位 | 需自主决策（文稿联网核实是唯一够格的） | drafter 模式保留 |
| 确定性作业 | 其余全部：阐述/分镜/绑定/设计/审查 | Go 拥有循环，manifest 可查 |

无工具的 agent 是负资产：贵、不可重放、指纹失效，产出与 Go 的 for 循环相同。

### 4. 多轮 ≠ agent：批评家循环

"一轮出不了好结果"的痛点是真的，但系统现状本就是多轮（校验拒绝回喂 ≤3 轮、prereview ≤2 轮）——缺的是**"不够好就重写"**的触发，不是"代理权"。解法是 Go 拥有的"起草→批评→修订"循环，批评锚定可检查清单（钩子 8 秒/张力曲线/出处），防 taste churn，预算 ≤1~2 轮烧尽放行。

### 5. 上下文：文件 + ctxpack 推送，不建库

- 内容留**项目工件目录**（指纹靠内容哈希、人可直接查、demo 烧镜像友好）；状态才入 SQLite。LLM 消费反正要序列化，入库是纯搬运；
- 流水线作业走**推送**：ctxpack 层收拢全部拼装逻辑（现状散在 directorNoteFor/designNoteFor/storyboardDigest 四五处），每工位一个函数=上下文契约+切片纪律。确定性是缓存指纹与幂等重放的地基；
- 对话侧主管走**拉取**（工具按需取），用户问什么不可预知。

### 6. 段间衔接：并发保留的四层方案

场景 HTML 3 路并发生成，衔接靠"共享契约 + 机械转场 + 事后审查"，不靠工人互看结果（串行=时长×3 + 邻居依赖破坏缓存指纹，级联失效比衔接瑕疵危险得多）。四层：

1. **防**：边界节拍双向注入（邻段首末拍 expect = 双向承诺）；
2. **查**：接缝帧对（seam±时刻）进粗剪审考卷，判视觉重量/焦点/色量/动势四维；
3. **治**：只修后段 + 前段收尾帧作参考图（前段永不动=无级联）；
4. **兜**：修复烧尽的接缝机械升级 cut→fade/xfade（assemble 需支持逐边界覆盖）。

刻意不做边界关键帧预生成：DOM 对参考图只能近似不可强制，且定妆帧会夹死段内节拍编排。

### 7. "束缚 AI 能力吗" → 三类束缚，分类处置

- **过程自主权**（推送上下文/Go 控制流/固定预算）：刻意收死，买确定性，维持；
- **创意上限**：四处真实能力税——无前向创意通道、自检深度浅、导演世界模型是静帧、非阻塞=按中位数交付 → 产出能力释放三件套（见方案 E）；
- **媒介盒**（曾误判为"HTML 画不了图像"）：已修正——SVG/Canvas/Three.js 都在合同内（Three.js 是官方 adapter），真盒子是"生成一次成功率 × QC 覆盖"，可渐进解锁（SVG→Canvas→Three.js，每级配齐质检；一切动画守可 seek 时间轴的确定性合同）。

### 8. 终局反思：分工的四条真实边界

"人需要分工是能力有限，模型能力丰富不该精细分工"——对一半。**站得住的分工理由只有四条，没有一条是能力不够**：

1. 输出长度物理墙（一次调用一个交付物，塞多了每个都平庸）；
2. 可修性经济账（改 seg05 只重画 seg05，分段=产物可局部替换=缓存的根基）；
3. 裁判独立于运动员（作者与批评家必须两次调用）；
4. 人的介入点（样张确认、文稿可改）。

角色名只是调用的标签不是实体。**设计单位 = 产物 + 调用 + 门禁**，人格化叙事删除。跨域损失（写稿的不知道渲染器擅长什么）用"介质词汇表注入"对冲，不用合并角色解决。

## 二、最终方案（v2）

**总纲**：以《导演阐述》为唯一创意源头的单向流水线。导演的权力 = 阐述（源头）+ 注入（切片）+ 验收（粗剪审）。过程确定性焊死，创意上限留门。零对话循环、非阻塞、保 3 路并发、agent 只留主管。

```
用户输入主题/稿件
  → 导演阐述（生成+自批评 ≤1 轮；UI 卡片可见可改，非阻塞门）
  → ① 文稿（ReAct agent + 批评家循环 standard≤2/quality≤3）
  → ② 分镜（确定性作业，prompt 带阐述）
  → 导演定调【重定义】= 绑定章→段号 + 母题出场表 + 节拍表（锚句逐字抄旁白）
      + 结构自检（同一调用内对照阐述验张力曲线/章平衡/时长/钩子；
        high 回喂分镜重出 ≤1 轮，导演不亲自动手）
      + 阐述指纹入旁车（改阐述→分镜过期→段缓存级联失效；文稿不自动重写）
  → ③ 风格设计（数据源改阐述；样张=唯一用户确认门）
  → ④ TTS+词级对齐（程序化） → ⑤ 逐段画面生成（最强档+3路并发+导演注）
      [数据门后：段级自检——生成完自截帧对照节拍表再交卷]
  → ⑥ 组装 → ⑦ 粗剪审（24/40 帧：节拍锚点+接缝帧对；四查；
        意见单含 observation 档→导演手记呈给用户）
  → ⑧ check 机械门禁 → ⑨ 渲前预审（考卷+弧线/母题维度） 
  → ⑩ 渲染拼接 → ⑪ 渲后 frameQA（保留，动态问题唯一工位）+ 误报记账
```

### 能力释放三件套

1. **导演手记**：审片/复核意见单增 observation 档（非问题的观察与建议），落盘+manifest+UI 呈现，不自动执行——AI 的场上发现有出口，处置权在人；
2. **质量分档**：`standard`/`quality` 两档配置化预算（批评家轮数/审片帧数/自检开关），确定性不变、深度解封；
3. **段级自检**：重新定性为"生成模型的自我修正权"（原"段级验收环"），等真机记账数据开门。

### 明确不做 / 缓做

**不做**：审稿循环与多角色会话 ❌ 导演直接改分镜本体 ❌ 砍渲后 frameQA ❌ 内容入库 ❌ Station 元框架 ❌ 边界关键帧预生成 ❌
**缓做（数据门后）**：段级自检（等 2–3 部真机片记账）；Three.js 解锁（等 SVG/Canvas 铺稳）；逐缝转场覆盖（衔接修复真实发生后）。

### 实施顺序（每步可回退）

| # | 内容 | 风险 |
|---|---|---|
| 1 | DirectorBrief 契约+生成+UI 卡片 | 零 |
| 2 | 注入文稿/分镜 prompt + 定调重定义为绑定 | 主战场 |
| 3 | 结构自检 + 阐述指纹 + ctxpack 收拢 + 介质词汇表注入 | 中 |
| 4 | prereview 考卷升级 + 意见单复盘记账 | 低 |
| 5 | 衔接四层 | 中 |
| 6 | 文稿批评家 + 阐述自批评 | 低 |
| 7 | 导演手记（observation 档 + UI） | 低 |
| 8 | 质量分档（预算配置化） | 低 |

### 成本与验证

前期每片 +4~6 次 plan 调用（standard 档，约 2 分钟），quality 档约翻倍；制作侧调用量不变。**验收三指标**：阐述采纳率、结构自检命中率、审片误报率——跑 2–3 部真机片回看，据其决定段级自检是否开门、轮数预算松紧。
