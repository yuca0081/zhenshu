# 风格库 v3 方案：标签 + 特色清单（2026-10-08 讨论稿）

## 一、理念转变

v2 库把自己当成"风格事实源"：入库时提取色板/字体/动效档位/HTML 样张，制作时机械套用。
v3 把库降维成"**策展目录 + 绝活收藏夹**"：

- **公认风格是模型的固有知识**——包豪斯、赛博朋克、粘土定格，模型自己会画。库只需要用**名字**指一下它（标签），不需要替模型"教学"（提取 tokens/五件套）。
- **独有手法才是库的家底**——一支参考片里值得偷师的东西（运镜、转场、贯穿母题、动效设计、素材用法、配色），提炼成**特色清单**，制作时由制作者**勾选复用**。
- **证据是对照物**——原片 + 抽帧快照保留：打标的证据、QA 的考卷、回看的素材。

一句话：**标签管气质（家族名），特色管绝活（招牌菜），证据管对照。**
通用的不进库（模型已会），独有的才进库（值得复用），用哪条由制作者当场选。

副产品：设计阶段只有一条路——"现场发明设计系统"；选库内条目 = 给发明过程塞一份**参考简报**，不选 = 裸发明。v2 的"条目整包拷贝进项目"路径退役。

## 二、条目结构（styles.json 新 schema）

```jsonc
{
  "id": "vid-<refID>[-sNN] | sp-<ts>",        // id 体系沿用，M3 再谈合一
  "name": "展示名（如：故障风数据片）",
  "tags": {
    "main": "cyberpunk",                       // 主标签 ×1，词表 id
    "aux": ["retro-futurism", "claymation"]    // 辅标签 ≤2（混入风格）
  },
  "tag_evidence": [                            // 每个标签必须带证据指认
    { "tag": "cyberpunk", "note": "第2段：紫青撞色+网格地平线", "frames": ["frame-08.png"] }
  ],
  "signatures": [                              // 特色清单 ≤6 条，制作时可勾选
    {
      "id": "sig1",
      "kind": "transition",                    // 受控枚举，见下
      "name": "道具递接转场",                   // 人话短名
      "mechanism": "前一画面被画面内物件推出画框时，后一画面跟随进场；同片物件不重复",
      "frames": ["frame-12.png", "frame-30.png"],  // 证据帧
      "use_hint": "适合章节切换的节拍"
    }
  ],
  "subject": "原片题材一句话",                  // 只供检索，永不进生成提示词
  "origin_project": "video:<refID>",
  "published": true,
  "created_at": "..."
}
```

**signature.kind 受控枚举**（六类，对应"独特的东西"可能藏在哪）：

| kind | 覆盖 | 例 |
|---|---|---|
| `camera` | 运镜（推拉摇移、节奏） | "每段开场缓推 1.5s 到主体" |
| `transition` | 转场机制 | 道具递接、色块擦除、动作匹配剪辑 |
| `motif` | 构图母题/贯穿装置 | "每章同一张卡片换内容复现" |
| `motion` | 动效设计 | "数字滚动带故障抖动收尾" |
| `material` | 素材用法 | "历史实物照片做旧拼贴+手绘箭头批注" |
| `palette` | 配色（仅当配色本身就是特色时提取） | "青橙对撞+大面积黑" |

**特色写作纪律（入库校验执行）**：
1. **机制不写物件**——"猫爪转场"必须写成"道具递接式转场"（题材中毒的后门，堵死在入库）；
2. 每条必须**指认证据帧**（在片子的哪里看到的）；
3. ≤6 条，宁缺毋滥——没有独特之处的片，特色清单就是空的，标签本身就够了。

## 三、风格词表（vocab.json，新增）

```jsonc
// data/library/vocab.json
{
  "cyberpunk": {
    "name": "赛博朋克",
    "aliases": ["cyberpunk", "霓虹科幻"],       // 同义词都挂到同一词条（查重用）
    "brief": "高饱和霓虹对撞深底；金属拉丝+全息质感；湿光反射；无衬线窄体",
    "tells": "紫青撞色、网格地平线、全息 UI、雨夜湿光"   // 打标时在帧里认什么
  }
}
```

- **收录标准**：只收"有公认视觉定义"的风格名词（设计史/影视行话立得住的），拒收"高级感/简洁大气"类空话。
- **冷启动**：模型按标准起草 ~40 条（覆盖短视频常见风格），用户人工砍定稿。
- **打标约束**：主 1 + 辅 ≤2，只能从词表选，每个标签带证据帧。
- **增长申请制**：词表没有 → 打标 agent 可申请新词（名字+候选别名+证据帧）→ 自动**查重**（拿候选词和别名对照现有词条："这些里有没有同一个东西的不同名字"）→ 通过才收录。词表是同义词问题的唯一管辖层；**条目层不去重**（同标签多条目正常，特色各自不同）。

## 四、入库流程（重做，比现在轻）

```
上传视频
→ 抽帧取色（脚本，保留现状）
→ 判单/多风格 + 段拆分（保留现有能力）
→ 每段/整片一次轻解析：
    调工具「查风格词表」→ 打标签（主+辅+证据）
    → 提炼特色清单（≤6，机制化写作+证据帧）
→ 前端展示：标签 / 特色清单 / 抽帧回看
→ 用户可增删改特色（"分段勾选入库"的旧待办在此顺势解决）
→ 确认入库 = 写入新条目 + 媒体快照（原片+帧，机制沿用）
```

**入库不再产出**：五件套（concept/fonts/motion/device/anti_patterns）、tokens 色板（除非配色被提为 palette 特色）、HTML 样张、skin、layouts。
解析从"三轮 LLM+校验打回"变成"一次轻解析"，入库速度和成功率都上一个台阶。

## 五、使用流程（制作时，"强参考"的落点）

选库内条目 → 弹出**参考选择**界面：
- 展示：标签（带机制描述）+ 特色清单（带证据帧缩略图）；
- **制作者勾选要复用的特色**（默认不勾；只勾标签不勾特色 = 只要气质基调）；
- 确认 → 项目里生成 **风格简报** `style/style_brief.json`：
  主/辅标签（含词表 brief）+ 选中的特色条目（含证据帧路径）。

设计阶段（design.go，笼子机制不变）提示词升级为"**参考发明**"：
- 标签的 brief = 本片气质基调；
- **勾选的特色 = 必须落进设计系统的硬要求**（吸收机制，物件换成本片内容）——"强参考"强在这：用户勾了就不是建议，是验收项；
- 未勾选/未选条目 = 裸发明（v2 现状，已上线）。

场景生成与 QA 完全沿用 v2 笼子（DesignDoc 注入不变）；QA 考卷对照物 = 项目样张 + 简报证据帧（顶替原真迹考卷）；题材中毒反向判据保留。

## 九、存储层：PG（元数据）+ MinIO（媒体），磁盘退为缓存 —— **设计保留，暂缓实施**

> **状态（2026-10-08 拍板）**：近期先全本地文件模式把流程跑通，远端服务器的 PG/MinIO 暂不使用（服务器部署软件待整理）。本节设计原样保留，作为 M4 启用时的施工图；启用时按下方降级阶梯渐进（可先只上 PG）。

项目已接 PostgreSQL（internal/store，GORM）；MinIO 半埋地基——minio-go v7 在 go.mod（零 import）、.env.example 有 MINIO_* 配置键（注释）、compose 假定宿主机 MinIO(9000)、0003 迁移写下"PG 存目录、MinIO 存媒体、磁盘是渲染事实源"的哲学。**本机 .env 的 PG_DSN/MINIO_* 当前全被注释，启用前先开服务。**
历史包袱：0001/0003 里的 manuscripts/storyboards/style_packs/method_notes/assets 五张表无代码读写（v1 残留），迁移时清理；assets 表设计与本方案同构，可改造复用。

### 存放原则——三层

| 层 | 去哪 | 内容 |
|---|---|---|
| 元数据层 | **PG** | 风格条目 `style_entries`（tags/signatures jsonb + 证据帧文件名）、词表 `style_vocab`（aliases TEXT[]）、参考视频登记（ref.json 升格为表，可选）；styles.json 整文件读写+互斥锁机械退休 |
| 媒体资产层 | **MinIO**（事实源） | 参考视频原片 `refs/<id>/video.mp4`、抽帧/封面 `library/<id>/frame-*.png`；对象键记在 PG 行里 |
| 渲染工作区 | **本地磁盘**（缓存） | 解析抽帧/场景渲染的中间产物、成片 working set——断点续跑语义（文件在=跳过）不动；成片 main.mp4 可选推 MinIO 留档 |

媒体流转：上传视频流式进 MinIO → 解析时按需拉到本地缓存 `data/cache/`（ffmpeg 只吃本地路径）→ 抽帧产物推回 MinIO → 前端回看走服务端代理（本地部署简单可靠；将来省带宽可换预签名 URL）。

### 降级阶梯（开发机零依赖，主线不被存储挡住）

| 配置 | 行为 |
|---|---|
| PG + MinIO 都配 | 完整模式：元数据入库、媒体入对象存储（部署目标形态） |
| 只配 PG | 元数据入库、媒体留盘（过渡形态，media 层 disk 实现） |
| 都没配 | 全本地文件（现状；styles.json/ref.json 为事实源） |
| 配了连不上 | 拒启（fail-fast，与 chat 案卷同一策略） |

实现形状照抄 store 层先例：objectStore 接口（Put/Get/Stat + 本地缓存策略）= minio 实现 + disk 实现；config.go 补 MINIO_* 字段。SDK 已在依赖，不加包。

### 代价（诚实清单）

- 上传/媒体服务三条路由（uploadReference / referenceMedia / libraryMedia）从"读文件"改"读对象存储+缓存"，含 200MB 流式 multipart 与内存控制；
- 开发机要跑 MinIO（单 exe 或 docker）才能测完整模式；不跑就走降级，不挡 M1/M2；
- compose 里 data/library、data/references 卷从"事实源"降为"缓存"，初期保留不删（回滚保险）。

## 十、风险与对策

| 风险 | 对策 |
|---|---|
| 标签打歪/漂移 | 证据帧强制指认 + 词表 tells 统一判据 |
| 特色写成物件（题材中毒后门） | 入库机制化校验 + 使用侧"风格≠题材"纪律照旧 |
| 气质还原变弱（丢精确色板/样张） | palette 列为特色类型可提取；将来不够再把"样张对照"加回 |
| 强参考变枷锁 | 勾选制本身就是阀门：不勾=不约束；设计提示词明确"吸收机制、替换物件" |
| PG/MinIO 双写不一致（对象传成功、元数据写失败等） | 定序：先传对象、后写元数据行；孤儿对象（无行引用）启动时/定期清扫 |
