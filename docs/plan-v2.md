### 1.2 五个关键发现(全部有画面/简介证据)

1. **这批视频与 v1 是同一条技术路线**:全部是 LLM 写代码 → 逐帧确定性渲染,无一条用视频生成扩散模型。路线被市场验证,需要换的是中间层的生产方式。
2. **高分的来源是"项目级设计系统",不是模板**:8分以上的片全部自带本片专属设计系统(双皮肤/riso三色/黑金双色/新粗野主义),且是模型现场为本片发明的,不是从库里选的。模型为单项目"发明约束然后遵守"的能力,上限高于"从模板库选一个填内容"。
3. **流量与质量分不相关**:斗拱 8 分 484 播,GVUF 7 分 14k,蹭上 world.execute(me) 音乐 IP 的两条 139k/94k 霸榜。选题装置×情绪钩子×音乐IP决定流量,工艺决定留存。**平台不需要追 9 分才有用户价值,需要稳定 7 分。**
4. **瑕疵清单=检视门禁的需求文档**(详见 §12):模型自由发挥处必露怯(空镜/占位符/错字/图表不可读),有系统约束处必精湛。
5. **成本结构是平台的立足点**:最贵一条 $570/217s、3598 次调用、数天耗时——一次性手工艺术品。营销/科普要的是"每周五条、改三稿、锁定品牌、一条母版出N变体",这批案例没有一条能做到。**单条爆款比上限,生意比可复制的中位数。**

## 2. v2 架构总览

### 2.1 保留(行为不动)

- 分镜稿上游 + 门1(用户确认内容);
- TTS/逐词时间戳/单一时间基准(旁白驱动)。**2026-09-30 修订**:时间权威不变,但 TTS 从 scene_gen 的前置降为质检/渲染的前置——scene_gen 按分镜估时先行,真 TTS 并行落地后机械解析(§2.4);
- 确定性渲染下游:HyperFrames(无头浏览器逐帧截图)+ FFmpeg(编码/混音/stitch);
- 段级一文件结构(失败隔离与段级重生成的安全网);
- 门2(草稿确认 + 段级重生成)。

### 2.2 替换(旧 spec 四职能 → 新承载物)

| 旧 spec 兼任角色 | 新承载物 |
|---|---|
| 把分镜内容转述成 JSON(内容载体) | 分镜稿本身 + 每段轻量 brief(纯文字+数据+TTS时间戳,不再是布局 schema) |
| JSON Schema 契约(格式约束) | **笼子一**:运行时契约 + lint(管技术合法性,不管内容) |
| StylePack(全片风格一致) | **笼子二**:模型先生成本片设计系统,每段注入 |
| check 失败后重生成的依据 | 模型自己的场景文件 + 违规详情 + 问题帧(外科修复) |

**死掉的只有一件事**:用 JSON 槽位描述画面布局、再由引擎翻译成 HTML 这个翻译动作(斗拱剖面/水彩渲染器/点云在槽位体系里没有格子)。

### 2.3 管线图(v2 目标态,2026-09-30 修订:TTS 并行化)

```
manuscript → storyboard(门1) → design【笼子二】
                                 ├─ scene_gen【笼子一,逐段直写,按估时】──┐
                                 └─ tts(并行跑) → 时序解析(机械,比例→绝对) ─┤
                                                                            └→ 质检站(分级门禁+外科修复) → render(HyperFrames) → stitch(门2/段级重生成)
```

对应 v1 `pipeline.go Stages()` 八阶段的变化:`style_samples` 演化为 `design`;`compositions`(genSpecs)替换为 `scene_gen`;`check` 重造为分级质检站;`tts` 不再阻塞 scene_gen(§2.4)。

### 2.4 TTS 时序:先行条件与并行化(2026-09-30 定稿)

**用户提案**:唯一先行条件=分镜+风格,TTS 放开。**裁定:生成顺序放开,时间权威不放开。**

- 不放开的原因(物理性,v1 踩坑结论维持):旁白驱动品类配音是时间最终权威——TTS 语速不可自然伸缩,改画面远易于改配音;先画面后配音必时长错位。
- 放开的机制(四条):
  1. scene_gen 按分镜**估时**先行(字数÷语速+标点停顿,v1 M0 已有 CJK 估计器);先行条件=分镜+风格+估时;
  2. 契约要求旁白驱动段用**段内比例时序**(data-in/out 写 0~1,不写绝对秒)→ 真 TTS 落地零重生成,比例自动伸缩;
  3. TTS 并行执行,落地后**机械 pass** 把比例解析为绝对值(纯算术,非 LLM 作业);卡点/音乐驱动类维持音乐节拍先行(v1 timing_basis 不变);
  4. 估时偏差 >25% 只重跑该段 scene_gen(段级隔离,便宜)。
- 诚实边界:可看草稿(draft.mp4,含卡拉OK字幕)仍需等 TTS——字幕层=TTS 时间戳机械装配,模型永不手写字幕 cue。省的是串行等待,不是跳过 TTS。

### 2.5 scene_gen 具体形态:段=自包含场景文件(2026-09-30 定稿)

**不是"一口吃大量 HTML"**:60-90s 片 = 6-10 段 × 每段 150-500 行,每段独立生成(段间并发)、独立质检、独立重生成。量级由三样框住:段级切分、平台 shim、设计系统(风格决策已在 design 阶段完成)。

**文件切分原则(2026-09-30 补,讨论澄清)**:每**段**一个 HTML,不是每**镜头**一个。镜头=段文件内部的编排(元素 data-in/out 进出点+转场设计);文件切分跟**时间权威单元**走——旁白驱动=旁白块,卡点驱动=音乐段落(§2.4 推论),因为镜头没有独立时间锚,且段内镜头呼应(重复版式/节奏递进,如列LEN"访客卡×5")正是风格本身,按镜头切文件会毁掉它。段太长(感知上限 ~20-30s)在分镜阶段拆;一镜到底类=少而长的段,结构不变。

| | 写什么 |
|---|---|
| 模型写(全部是创意) | 每片一次:design.md+tokens。每段:版式、动效编排、canvas/Three 图形程序、data-el 标注、自定义场景参数注册 |
| 平台写(机械,模型永不碰) | 运行时 shim(~200行,读 data-* 驱动 GSAP)、tokens.css 注入、字幕层(TTS时间戳装配)、比例→绝对解析、lint/frameQA、render/stitch |

场景文件形态示意(shim API 在 contract.md 定稿):

```html
<!-- seg03 | 旁白驱动 | 估时 11.2s -->
<style> /* design.md 约束下的自由发挥 */ </style>
<div class="stage" data-mode="frac">
  <h1 class="clip" data-el="hook-title" data-in="0" data-out="0.35">干这么重的活,个头小不了</h1>
  <canvas class="clip" data-el="dougong-section" data-in="0.10" data-out="1.00"></canvas>
</div>
<script>
  HF.scene({ draw(t){ /* 参数化图形程序,f(t) */ }, params:{ floors:{...} } });
</script>
```

## 3. 笼子一:运行时契约(待建 `docs/contract.md`)

管**什么样的代码有资格进渲染器**——技术合法性,硬法律,lint+沙箱机械执行。条款(每条必须可机械判定;模糊条款一律降级为报告项):

1. 固定舞台元素、固定画幅,禁改舞台本身;
2. 时序一律 `data-*` 属性声明,**旁白驱动段用段内比例(0~1),卡点/音乐驱动段用绝对秒(来自节拍表)**;比例→绝对由平台机械解析(真 TTS 时长落地后),模型不写绝对秒(2026-09-30 修订,见 §2.4);
3. `class="clip"` 标记剪辑单元;
4. 字体仅限白名单本地字体,`@font-face` 声明(v1 gotcha:`src:local()`);
5. 禁网络请求、禁外链资源,资产全部本地,附来源清单;
6. 禁实时时钟 API;随机数必须带种子;
7. **所有运动必须走 GSAP 时间轴/适配器**;CSS keyframes/WAAPI/自走 rAF 禁用于运动(它们跑在合成器时钟上,seek 不到,逐帧截图=随机噪声);
8. 运动一律**参数化** `f(t)`,禁逐帧累积状态(物理积分必须闭式化或从0重放);
9. 一段一个文件,文件名即段号;
10. 每个逻辑元素带 `data-el` 语义标注(见 §7);
11. 自定义场景必须注册参数(见 §7 Canvas 部分);
12. WebGL 截图规范:`preserveDrawingBuffer` 或渲染后同步截取,禁自转循环(render-on-demand);
13. 段渲染时长必须等于旁白 cue 时长。

## 4. 笼子二:设计系统先行(新阶段,落位 style_samples)

- **防的病**:段级各自生成的漂移——每段单看都行,拼起来像 PPT 拼盘。
- **做法**:分镜确认后、场景生成前,模型通读全部分镜,为**本片**发明设计系统:色彩语义/字体栈/版式网格/组件清单/动效语言(缓动、转场习惯),落成 `design.md` + `tokens.json`,注入之后每一段的生成上下文。
- **关键在"发明"**:系统是模型现场为这部片设计的(参照穆阿蒂布双皮肤/列LEN riso三色/自画像黑金),**不是**从 styles.json 里选一个套上。
- **执行方式**:软约束——生成前注入 + 门2人审 + Tier1 抽检报告项(色彩/字体偏离)。**不是**硬 lint(风格偏离无法机械判定,强行判定=误报泛滥)。
- **模板库降级**:`data/library`(styles/templates/methods,37 文件已随 v1 迁入)成为 few-shot 弹药库与兜底,**停止扩编**。

## 5. 检视分级(重造,不删除)

检视约束的是"什么能发出去",不是"能写什么";自由度越高越需要。证据:9分爆款=自由+3598次自我迭代循环;无检视的自由=Gemini那条4.5分。v1 检视的病灶是"检查项没分级+修复粗暴",不是"检查多余"。

- **Tier 0 机械硬门禁**(零误报,阻断+外科修复):渲染异常/崩溃、空白黑帧、元素溢出舞台、段时长≠旁白cue、字体缺失回退、确定性哈希(同输入同输出)、data-el 缺失、随机数未驯服。
- **Tier 1 视觉抽检**(frameQA 收窄为是非题):"文字被裁切?元素重叠?大面积空白?"——是非题精确度远高于审美题;高置信违规才阻断,≤2轮,修不好标"转人工"交门2,**禁止自动换模板兜底**。
- **Tier 2 主观审美**(只报告不阻断):好不好看/风格对不对/信息密度——机器别装懂,人在门2判断。
- **修复原则:外科手术式**——喂回违规详情+问题帧截图+模型自己写的场景文件,让它修自己的代码;创意意图保留,只修缺陷。**默认禁止回退模板**(那才是杀创意的机制)。
- **治理**:每检查项误报率落日志,超阈值自动降级 warning——"bug多"从体感变数字,烂检查被数据淘汰。
- **inspect_check.py 检视壳降级为开发期工具**;预览用低清真渲染替代(确定性渲染器里"预览=成片"应由架构保证,不靠模仿成片观感的壳)。

## 6. 人机接口:元素点击在自由模式下依然成立

- **能选中元素靠浏览器 DOM,不靠模板引擎**——`elementFromPoint`/命中测试对任何 HTML 有效(DevTools 对任意网页都能检查元素)。
- **退化的是"选中后系统知不知道这是什么"**→ 解法=生成时契约让模型自标 `data-el`(§3 条10),lint 兜底。命名约定≠布局规定,不碰视觉表达。
- **元素级指认在自由模式下更重要**:输出空间大增,只剩"整段重生成"会让人为改一个错别字赌一次重抽。元素级指认+外科修复是同一套 `data-el` 的两面(机器自修复要定位,人指认也要定位)。
- **Canvas/WebGL 无 DOM,物理边界**:点击降级为场景级("重新生成/一句话描述要改什么");契约要求自定义场景**注册参数**(出跳份数/水彩湿度/粒子数),声明了参数就有参数级滑杆——创作者对图形类画面的自然修改粒度。

## 7. 动画与 3D 纪律

- **GSAP 局限的准确表述**:不在"能不能配 Three.js"(HyperFrames 内置七个运行时适配器,Three.js 是其中之一;穆阿蒂布那条就是 Three.js/WebGL2+GLSL 逐帧渲的),而在"一切运动必须走时间轴"(§3 条7/8)。
- **GSAP 全插件免费**(Webflow 收购后 3.13 起,MorphSVG/DrawSVG/SplitText 等),无版权墙。
- **Three.js 正确姿势**:禁 `setAnimationLoop` 自转;render-on-demand( seek 到哪渲染哪);运动参数化;随机种子;`preserveDrawingBuffer`。GSAP 驱动代理对象,`onUpdate` 更新场景+手动 `renderer.render()`。
- **确定性=同机同配置**,不承诺跨 GPU 逐像素一致(抗锯齿/浮点差异)。对"同集群出片/改稿重渲/批量变体"够用,对外话术别过度承诺。
- **成本分工**:90% 画面(科普卡片/字幕/图表)用 DOM/SVG/Canvas2D,快且稳;Three.js/WebGL 留给每部片 1-2 个装置镜头(点云/晶格/三维剖面)——是 8 分和 6 分的分水岭,但不必全片都是它。4K WebGL 按天算渲染成本,段级并发缓解。

## 8. 模型策略

- **创意层(设计系统+场景代码)用最强可用模型**(Opus 级)。代差是真的:爆款全 Opus5.5,v1 genSpecs 主选 DeepSeek/GLM——质量差距第一因子可能是模型档位而非架构。生成是一次性成本,渲染反正确定性。
- **v1 spec 路径不删除,冻结为兜底**:弱模型跑量、批量营销变体"要稳不要炸"场景可用。两条路径输出汇合同一点(符合运行时契约的场景文件),对下游透明。
- **bake-off 后重审 LLM 主选**:v1 选 DeepSeek 的标准是"按契约出 spec 最稳",新标准是"谁写的场景代码最好"。

### 9.3 拆除清单(v2 内,开工 M0' 第一步执行;本次迁移未动刀,原因:避免留下半拆不编译的骨架)
