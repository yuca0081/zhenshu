## 1. 决策记录（为什么这么改）

| # | 决策 | 一句话理由 |
|---|---|---|
| D1 | 设计系统归②风格工位，制作阶段零设计作业 | 风格包第三件随打包终审门确认；制作只消费 |
| D2 | 段级流水线取代阶段栅栏 | 写吃 API、渲吃 CPU、check 吃浏览器，栅栏让三类资源互相干等 |

| D6 | 全片终审已拍板采纳 | 逐段审看不见段间渐变跑偏，全片终审是唯一兜底 |

## 2. 目标架构总览

```
TTS（一次，全局，已有）
→ ④写画面 ×N（并发 ≤4）：谁写完谁往下流，不等齐
   段链：check（本段，本地）→ 段渲染（~20s/段，不被审核闸）→ ⑤段审（ReAct）
→ 邻居两侧段审都过 → ⑤边界审（边界短片段 + 末首帧对）
→ 最后一对边界通过 → 拼接（永远零改动）→ 全片终审 → 出片
```

**段状态机**：`written → checked → rendered → audited`，打回走 `rewriting → written` 循环；**边界对**：`pending → 通过 → passed`。全局：全部边界通过 → 拼接 → 终审 → 出片。

## 3. 现状要点（实现者需要知道的功能性事实）

- 现有制作管线是**阶段栅栏式**：写画面等全部段就绪才放行、check 全局一遍、审核尚不存在——本次改造的核心就是拆栅栏。
- 渲染逐段 HTML→视频，已有**段级缓存**；实测 ~20s/段（≈3×段内容时长）。
- **TTS 词级时间戳已存在**：段内每句话的精确时刻可换算——这是锚点帧抽取和「帧身份」的坐标基础。
- 准备阶段已实施并接线：打包终审确认时风格包已 confirmed、设计系统已锁定落盘。
- **存量老项目走 legacy 路径**（无文字稿工件、有旧样张流程），必须继续兼容且行为不变。
- 拼接层已有字幕时序等机械修能力（既有行为，本次不新增拼接层机制）。

## 4. 工作项 ⑬：段级流水线调度

### 4.1 功能需求

把「全段写完才 check、全部 check 完才渲、全部渲完才拼」的栅栏改成**每段独立推进**：一段写完 → 本段 check → 本段渲染 → 本段段审，全程不等其他段。对外阶段语义保留（进度与记录兼容现状）。

### 4.2 段状态机

| 状态 | 进入条件 |
|---|---|
| written | 段页面落盘并通过既有机械钳 |
| checked | 本段 check 通过（只查本段） |
| rendered | 段视频产出且完整（帧数核对） |
| audited | 段审意见单落盘且无 high；有 high → rewriting |
| rewriting | ④修复调用已派发（注入程序整理的失败条目），完成后回 written |

同段打回 ≤2 轮，超限触发刹车（§4.5）。**渲染不设审核闸**：checked 即渲。

### 4.3 调度规则

1. 三个资源池独立限流，**均为配置项**：写 ≤4、审核 ≤4、渲染 ≤min(4, CPU核数-2)，默认即此值；
2. 写优先于审：写队列非空时，审核队列每轮最多放行一个；
3. 谁写完谁往下流，全并发不等齐；
4. 边界对 = 相邻两段：**两侧段审都通过才审这一对**；任一侧重画 → 相邻边界对失效重审；
5. 最后一对边界通过 → 拼接 → 全片终审 → 出片。

### 4.4 可追溯与重放

每次段状态迁移、每次审核取证（工具+参数+结果指纹）落盘可查；进程中断重跑时从记录恢复，**不重做已完成段**；记录追加只写。

### 4.5 刹车

- 签名 = `类别 + 锚点`（如 `事实@N3`）；
- 同签名两轮 high → 刹车；系统性早停：≥2 个不同段出现同类别 high → 刹车；
- 刹车动作 = **停止派发新作业 + 在飞作业排干**，然后停在审核阶段报错待人工（降级出口未拍板，见 §10）。

## 5. 工作项 ⑭：设计发明路径退役

- **prep 新项目**：设计系统已随打包终审确认——制作管线中**不再存在任何设计发明调用**；风格包缺失或未确认时明确报错引导走 prep 反馈重跑，不静默发明、不等待样张确认。
- **存量老项目**：现有 legacy 设计流程**原样保留**，行为不变（含其会话工具）。
- 现有设计系统校验器、锁定落盘、样张渲染设施**全部复用**（风格包深校验与②样张渲染还在用），不重写、不删除。

## 6. 工作项 ⑯：审核 agent

### 6.1 形态

一个**判卷型 ReAct agent**、三种调用档案（段审/边界审/终审）：多模态、温度 ≈0、回合预算小（段审 ≤6 / 边界审 ≤4 / 终审单轮）、`submit_verdict` 唯一出口（submit-or-die）。项目内已有同款模式的实现（准备阶段三 agent），照其惯例落地。

### 6.2 工具（两读一交，档案间同一套）

| 工具 | 行为 |
|---|---|
| `get_frame(目标段, t)` | 取指定时刻单帧（ffmpeg，按段+时刻缓存，越界报错回流）；边界审目标段=前段/后段 |
| `get_clip(目标段, t1, t2)` | 取连续短片段（跨度 ≤2.5s，超限截断报错）；视频直喂优先，退路 6–8fps 带时间戳帧序列 |
| `submit_verdict(payload)` | 唯一出口；校验失败 → 错误清单回流循环内自修 |

### 6.3 开场注入（程序装配，不走工具）

| 档案 | 注入 |
|---|---|
| 段审 | 锚点帧（首末帧 + 句末帧，封顶 ~6，超出均匀采样；帧上标注「此刻刚念完 N 几」）+ 分镜 brief + 本段句编号旁白 + 样张 + 设计规则要点（可空）+ 本段相关事实清单条目；修复轮追加既往意见单 |
| 边界审 | 两侧 brief 承诺原文 + 边界短片段×2（窗口 ≥ max(入场/收尾动画预算, 1.5s)）+ 末帧×首帧对；修复轮追加既往意见单 |
| 终审 | 12–16 帧（§7） |

### 6.4 系统提示词

定稿全文见**附录 A**。规则两层已固化：通用判卷法 + 固定查项表（段审六维 / 边界审四查，每维 pass·fail·NA）；**本片期望不预先生成**，agent 从 brief+旁白现场推导（考卷退役——期望源诞生于帧之前，不存在泄题）。

### 6.5 意见单权威 schema

**段审**（submit_verdict 载荷）：

```json
{
  "type": "object", "additionalProperties": false,
  "required": ["dims", "findings"],
  "properties": {
    "dims": { "type": "object", "additionalProperties": false,
      "required": ["content","fact","style","first_last","device","subtitle"],
      "properties": {
        "content": {"enum":["pass","fail","NA"]},
        "fact": {"enum":["pass","fail","NA"]},
        "style": {"enum":["pass","fail","NA"]},
        "first_last": {"enum":["pass","fail","NA"]},
        "device": {"enum":["pass","fail","NA"]},
        "subtitle": {"enum":["pass","fail","NA"]} } },
    "findings": { "type": "array", "items": {
      "type": "object", "additionalProperties": false,
      "required": ["category","anchor","severity","evidence","fix"],
      "properties": {
        "category": {"enum":["content","fact","style","first_last","device","subtitle"]},
        "anchor": {"type":"string","pattern":"^(N[1-9][0-9]*|t=[0-9]+(\\.[0-9]+)?)$"},
        "severity": {"enum":["high","low"]},
        "evidence": {"type":"string","minLength":1},
        "fix": {"enum":["redraw","pass"]} } } },
    "reassessment": { "type": "array", "items": {
      "type": "object", "additionalProperties": false,
      "required": ["id","result"],
      "properties": { "id": {"type":"string"}, "result": {"enum":["fixed","still_broken"]}, "evidence": {"type":"string"} } } }
  }
}
```

**边界审**差异：dims 键 = `outro_done / intro_started / continuity / glitch`；category 枚举同四查；anchor pattern = `^b[0-9]+\|t=-?[0-9]+(\.[0-9]+)?$`（负=前段内）；fix 枚举 = `stitch_fix / redraw / pass`。
**终审**差异：无 dims；category = `pacing / deadair / stitch / drift`；anchor = `t=全片秒`；**fix 字段移除**（处置由程序按时刻落段映射，不由模型给）。

**跨字段规则（schema 之外，程序校验层）**：
1. severity=high 的 evidence 必须含帧时刻；
2. **severity×fix 一致性**：high → redraw / stitch_fix；low → pass；
3. 修复轮：既往意见单每条 id 必须出现在 reassessment，且 dims 仍须完整重交；
4. 校验失败 → 错误清单回流循环内自修，不落盘。

### 6.6 打回 · 分诊 · 签名刹车

审片员只诊断+分诊建议，不执行任何修复：

| fix | 含义 | 程序路由 |
|---|---|---|
| redraw | 画面/动画本身错 | high → ④重画该段（只带失败条目+证据+期望）→ 重渲 → 重审 |
| stitch_fix | 拼接参数能修（仅边界审：字幕时序、过渡参数） | 拼接修正清单，机械执行，不打回 |
| pass | 记录不修 | 账本 |

签名刹车见 §4.5。

### 6.7 已知风险与守卫（P4 哨兵）

无冻结考卷的实测病理是「越修越多」（2026-10-15 e2e：修复轮全量重审，一段从 1 问题挂出 4 新问题）。守卫已固化在 schema：修复轮先复核既往意见（reassessment 硬校验）+ 新发现须 high 才立案。**记账哨兵：修复轮新发现率**；复发则回退「预期先行」——同 agent 第一轮只看文字盲写预期清单、第二轮再看帧（考卷轻量复活，一档之隔）。

### 6.8 验收

- [ ] 构造含错字/数字错的段：段审 high 立案、打回信息含帧时刻与期望、修复后重审通过；
- [ ] 意见单缺 dims 键 / anchor 越界 / high+pass 矛盾组合：均被校验拦截且回流修复；
- [ ] 边界插黑帧 → glitch high → redraw；字幕时序错位 → stitch_fix → 拼接修正清单；
- [ ] 取证调用留痕可查、重放不重取（缓存命中）。

## 7. 工作项 ⑮：全片终审（已拍板采纳）

- **触发**：拼接完成后自动进入；发现问题 → 重渲清单 → 重拼 → 重审，≤2 轮或触发刹车。
- **抽帧**：段落界帧（每个段落首段起点）必取，剩余名额用段界帧均匀补足，总帧 12–16；帧上标注「此刻=第几段/段落界」。
- **查项**：pacing（节奏失衡）/ deadair（单点空转）/ stitch（段序、黑帧、音画错位）/ drift（段间风格渐变——逐段审的盲区，本档案存在的主要理由，**不可省略**）。
- **动作**：意见按时刻落段映射重渲清单（drift 含相邻段），重渲 → 重拼 → 重审。提示词按附录 A 同款模板（材料/流程/查项表/意见条目/输出样例）替换查项表即可，无工具、无修复轮。

## 8. 工作项 ⑰：并发配置

三个上限均为配置项（默认值见 §4.3 第 1 条），改配置不改代码。

## 9. 不变量（实现红线，违反即架构退化）

1. **拼接层永远零改动**：不新增任何转场/过渡机制；stitch_fix 仅限既有机械修正能力；
2. **画面是 t 的纯函数**：现有渲染契约（唯一暂停时间轴、禁页面自走时钟等）不放松；
3. **段 = 缓存/重放单位**：重渲只重渲受影响段；
4. **准备阶段不动**；
5. **机制不进提示词**：预算、缓存、签名刹车、路由、分数计算全部框架侧；
6. **确定性焊死清单归属不变**：抽帧时刻、材料装配、schema 校验、打回判定、分数计算、刹车判定都是代码，LLM 只做判卷。

## 10. 未决（不在本次范围，实现者不得自行拍板）

- 修正③残余——**降级出口**：v1 默认「刹车=停机报错待人工」；带伤发布+标注 vs 整片作废待人工拍板；
- 误报记账开张（意见单结构化落盘已具备，汇总分析后做）；
- 先配后切（不实现，锚点帧用现有 TTS 词级时间戳）；
- 前端进度消费（状态记录已含段级信息，UI 另列）；
- 沿袭文档债：总纪要第六节改写、storyboard-sample.md 重写。

## 附录 A：审核 agent 系统提示词定稿

### A.1 段审

```text
你是成片审片员，对本段成片判卷，产出结构化意见单。

## 输入材料（开场已注入）
1. 分镜 brief——场景、首拍、末拍（本段画面承诺）
2. 句编号旁白——N1…Nn（本段内容承诺）
3. 样张——本片风格的实物基准
4. 设计规则要点——贯穿装置与皮肤切换规则（可能为空）
5. 事实清单——硬事实与出处
6. 锚点帧——每帧标注「此刻刚念完 N 几」

## 判卷流程
1. 先读 brief 与旁白，列出本段承诺了什么：该出现什么、每句承载什么画面。
2. 逐帧对照，按六维过一遍，每维给出 pass / fail / NA。
3. 锚点帧不够判断时：get_frame 取指定时刻的帧，get_clip 看连续片段。先核实，再下结论；拿不准的不写。
4. 汇总意见单，调用 submit_verdict。

## 六维判定
| # | 维度 | 判什么 | 记 fail | 记 NA |
|---|---|---|---|---|
| ① | 内容一致 | 承诺的元素是否出现、旁白说到的是否画了 | 承诺没画、画错（多画不算错） | 无 |
| ② | 事实 | 画面的数字、年份、专名与旁白及事实清单是否一致 | 出现且冲突 | 画面未出现数字/专名 |
| ③ | 风格 | 质感、色彩、字体、装饰密度像不像样张 | 明显出戏 | 无 |
| ④ | 首末拍合规 | 首帧按 brief 首拍开场、末帧收在 brief 末拍 | 开场或收尾与承诺不符 | 无 |
| ⑤ | 装置落点 | 贯穿装置/皮肤切换符合设计规则 | 违反规则或漏落点 | 设计规则为空 |
| ⑥ | 字幕文字 | 字幕与画面文字无乱码、缺字、错字、断句错位 | 出现任一 | 画面无文字 |

## 意见条目
每条 fail 写一条 finding：
- category：六维之一（content / fact / style / first_last / device / subtitle）
- anchor：句号（N 几）或帧时刻（t=秒）
- severity：high = 观众能直接察觉（错字、数字错、缺承诺元素、明显出戏）；low = 挑剔级瑕疵。只有 high 会触发打回，标 high 先过这条门槛。
- evidence：帧时刻 + 现状 vs 期望，一句话。
- fix：redraw（需重画）/ pass（记录不修）。

## 输出样例
{
  "dims": {
    "content": "pass", "fact": "fail", "style": "pass",
    "first_last": "pass", "device": "NA", "subtitle": "pass"
  },
  "findings": [
    { "category": "fact", "anchor": "N3", "severity": "high",
      "evidence": "帧 t=12.4s：画面标题写 1985，N3 旁白为 1984",
      "fix": "redraw" },
    { "category": "subtitle", "anchor": "t=8.0", "severity": "low",
      "evidence": "帧 t=8.0s：字幕「绿素」缺字显示为「绿 x」",
      "fix": "pass" }
  ]
}

## 修复轮
输入会附上一轮意见单。先对每条既往意见逐条复核（reassessment：fixed / still_broken，still_broken 需附 evidence），之后才考虑新发现——新发现必须证据确凿才立案，不追加数量。修复轮载荷在同层多 reassessment 数组，findings 只收新发现。

## 输出
完成判卷即调用 submit_verdict；除工具调用外不要输出结论文本。
```

### A.2 边界审

```text
你是成片审片员，对相邻两段的拼接边界判卷，产出结构化意见单。

## 输入材料（开场已注入）
1. 前段末拍承诺（brief）
2. 后段首拍承诺（brief）
3. 前段收尾短片段（最后 1–2 秒）
4. 后段入场短片段（最前 1–2 秒）
5. 末帧×首帧对（物理拼接点）

## 判卷流程
1. 读两条承诺，明确这一边界应该是什么样：延续（末帧状态 = 首帧状态）还是新场景（干净开场）。
2. 按四查过一遍，每查给出 pass / fail / NA。
3. 短片段不够判断时：get_clip 取更早或更晚的连续画面核实。先核实，再下结论；拿不准的不写。
4. 汇总意见单，调用 submit_verdict。

## 四查判定
| # | 查什么 | 记 fail | 记 NA |
|---|---|---|---|
| ① | 收尾播完 | 前段收尾动画停在半途被掐断（淡出没走完、元素收一半） | 前段无收尾动画 |
| ② | 入场起步 | 后段入场动画卡死、跳帧、长时间黑屏 | 后段无入场动画 |
| ③ | 接续成立 | 承诺延续而末帧与首帧对不上（构图/物体位置/颜色跳变）；承诺新场景而后段开场带前段残影 | 两侧无相邻关系承诺且各自完整 |
| ④ | 突变 | 闪帧、黑帧、亮度色量突跳 | 无 |

## 意见条目
每条 fail 写一条 finding：
- category：四查之一（outro_done / intro_started / continuity / glitch）
- anchor：边界号 + 相对拼接点的时刻（如 b02|t=-0.2，负 = 前段内）
- severity：high = 观众直接察觉（黑帧、明显跳变、动画半途截断）；low = 挑剔级。只有 high 触发处理。
- evidence：时刻 + 现状 vs 期望，一句话。
- fix：stitch_fix（拼接参数能修：字幕时序、淡入淡出参数）/ redraw（画面或动画本身错）/ pass。能用拼接参数修的，不要判 redraw。
```
