# 存储改造：产物正本上 MinIO，本地盘降级为缓存，完结自动清理

## 背景与核心判断

- **磁盘大头是媒体 blob**（终片/母版/段片 mp4、配音 wav、QA 截帧、参考视频 ≤200MB/个、npm-cache 垃圾），不是 JSON。所以「搬到数据库」的正确形态是：**货进 MinIO（对象存储），PG 继续只记账**——这正是风格库迁移（`stylelib/media.go` + `docs/style-library-cloud-storage.md`）已验证的模式，本次把它推广到项目产物和参考库。
- **渲染契约不能断**：npx hyperframes / ffmpeg / python 子进程只认本地路径，制作期间本地工作区必须存在。因此本地目录保留为「工作区+缓存」，只在项目完结后清理，需要时从 MinIO 回源。
- **小 JSON 工件不建 PG 表**：15+ 种工件类型建表是巨大的 schema 改造，且它们只有 KB 级、无跨项目查询需求。保持文件契约，按原目录布局整包作为 blob 进 MinIO（`projects/<id>/<相对路径>`），恢复时原样落地。
- **Redis 不引入**（tech-stack.md 已有决策：队列走 PG）。`data/hf` 模型缓存、全局 BGM/字体库不迁（一次性全局数据，不是增长源）。
- **新桶 `zhenshu-data`，不开 versioning**：风格库的 `zhenshu` 桶已开 versioning，段片/终片会反复覆写，同盘存历史版本纯浪费；产物桶覆写即弃旧版。

## 实施内容

### 1. 新包 `server/internal/artifacts`（样板照抄 `stylelib/media.go`）
- `Store` 接口：`Put / Localize / Open(→ServeContent) / Stat / List / DeletePrefix`，另加 `SyncPrefix`（补传缺失）与 `RestorePrefix`（回源缺失）。
- 双实现：`minioStore`（新桶、fail-fast 同 store.Open 语义）与 `localStore`（未配 MinIO 时所有方法退化为本地路径操作——demo 容器与本机开发零影响）。
- key 镜像磁盘布局：`projects/<项目ID>/<相对路径>`、`references/<refID>/<相对路径>`。
- 文件三分类（判定函数收在包里）：
  - **keeper（上传+保留本地）**：全部 JSON/txt/md、`manifest.jsonl`、`.sum`/`.check.stamp` 指纹、终片/母版/段片、配音 wav、样张/小样、`assets/img`、`font_assets.json`；
  - **弃置（不上传，完结即删）**：`reports/frameqa|prereview|replay/` 截帧、`.hf-seg/`、`.hf-clip/`、`compositions/frames|caps/`、`llm/*.request.md`、`*.tmp*`；
  - **垃圾（无条件删）**：`npm-cache/`。
- **安全不变量**：删本地任何文件前必须 `Stat` 确认 MinIO 有正本；MinIO 未配置时清理器整体不运行。

### 2. 配置与接线
- `config.go`：新增 `MINIO_DATA_BUCKET`（默认 `zhenshu-data`）、`DISK_GC_DELAY`（默认 24h；`0`=完结即清，`-1`=永不清理）。
- `cmd/server/main.go`：构造 store，注入 `api.Server`、`produce.Runner`、`prep.Deps`、`styleref`、`pipeline`（包级 setter，沿用 `SetDataDir` 模式）。

### 3. 上传检查点（write-behind，最佳努力+日志，失败不打断制作）
prep 工位 submit 后→三工件+input；TTS 完成→`audio/*`；每段渲染完→`renders/segs/<seg>.mp4`+`.sum`；终片完成→`main.mp4`/`main_voice.mp4`/`timeline.json`/`audio_meta.json`；样张小样完成→`style/sample-*.png`、`style/clips/*`；参考分析完成→`references/<id>/` 全套；`manifest.jsonl` 在终态与停机时同步。

### 4. 读路径切换（前端零改动，URL 永不入库原则不变）
`s.video`、`s.styleClip`、`s.referenceMedia`、`s.llmVideo`、`s.audioMeta` 改为：本地有→直读（热路径零网络开销）；缺→MinIO 流式回源喂 `http.ServeContent`（照抄 `libraryMedia`）。

### 5. 回源与工作区恢复
- `produce.Runner`/`prep.Runner` 启动前 `RestorePrefix`（补齐 keeper 文件）——清理过的老项目重开/续跑/重渲透明可用。
- 重混 BGM、段级 rework 等需要大文件的路径，消费前 `Localize` 拉回（照抄简报证据帧模式）。

### 6. GC 清理器（省空间的关键一步）
启动时 + 每小时 ticker：遍历项目，凡「终态/空闲超过 `DISK_GC_DELAY` 且非运行中」→ 删本地弃置类文件和已上传的大文件；`npm-cache/` 无条件删；逐文件先 Stat 远端正本。`DELETE /projects/:id` 增加 `DeletePrefix` 同步删对象。

### 7. 存量回填 + 部署
- `server -storage-sync` 子命令：幂等回填 `data/projects/*` 与 `data/references/*`（Stat 已在则跳过），服务器跑一遍后由 GC 腾空间。
- `deploy/compose.yml` 卷不动（工作区仍需要）；`.env.example` 补两个新变量；`deploy.sh` 不用改。

### 8. 文档
`docs/storage-cloud-migration.md`：设计、三分类清单、安全不变量、决策记录（为什么 JSON 不进 PG、为什么新桶不开 versioning、Redis 不引入），体例照 `style-library-cloud-storage.md`。

## 实施顺序（每步可独立验证）
1. `artifacts` 包 + localStore 全接线（行为零变化，纯重构验证）；
2. minioStore + 读路径切换 + 上传检查点（此时只加不删，本地仍全量）；
3. Restore/Localize 回源 + GC 清理器（开始省空间）；
4. `-storage-sync` 回填 + env/deploy/文档。

## 验证
本机（隧道连 MinIO）：跑一个项目全流程→确认对象落桶；手删本地 `renders/` 后 video 路由仍可播；GC 清理后重开项目重渲正常；不配 MinIO 跑一遍确认行为与现状完全一致。服务器：`-storage-sync` 回填 + `df -h` 前后对比。

## 默认决策（提问未获回复，取推荐项，可随时改）
中间产物（QA 截帧/渲染壳）**不归档、完结即删**；完结 **24h 后自动清理**（可配）；存量项目**一次性回填**。
