## Context

当前 LLM 设置（供应商 key/url/model、工位绑定）存在**本机文件** `data/llm-config.json`，每台工作机各存一份，换机要手工同步。用户要求把 key/url 等配置挪到**远程数据库**（项目已有 PG），多台工作机共用一套配置。

现状关键事实：
- 设置数据层 `server/internal/llm/settings.go`：`Settings` 结构体 + `validateSettings/normalizeSettings` + `atomic.Pointer` 快照热生效（无文件监听，保存即换指针）；`SaveSettings` tmp+rename 原子落盘
- 解析链「工位→档位→.env→默认」在 `provider.go resolveRole`，每次作业现读快照（不落 DB 也能保持零延迟）
- API `server/internal/api/llmsettings.go`：GET/PUT `/api/llm-settings` + POST test，admin 收口，key 只进不出（掩码尾4位）
- PG 层 `server/internal/store/store.go`：GORM 只当查询执行器、手写 SQL、`Store` 接口 + pgStore/memStore 双实现；迁移双轨制（`server/migrations/NNNN_*.sql` 运维对账 + `store.Open` 幂等自建自管口径）；**尚无设置类表**，最新迁移 0008
- `main.go:64` 先 `llm.InitSettings(path)` 后（:70）`store.Open(cfg.PGDSN)`
- 前端 `web/src/components/LlmSettingsPage.vue` + `api.ts:195-205` + `types.ts:394-458`

## 设计

**事实源切换**：PG 已接（`st.Kind()=="pg"`）→ `app_settings` 表为事实源，本地 `llm-config.json` 降级为缓存/种子；未接 PG（开发/demo/内存模式）→ 维持现状纯文件，零破坏。

**同步机制**：30s 轮询拉 DB（配置面无需 LISTEN/NOTIFY 级实时）；每次 LLM 作业仍读内存快照，不新增 DB 访问。

**启动种子/回灌**（`AttachKV` 时一次性）：
- DB 有值 → DB 内容进快照，并回写本地文件（文件=缓存，断网重启仍有配置）
- DB 无值 + 本地文件有 → 文件内容写入 DB（老配置自动迁移，零手工）
- 都没有 → 空设置（首启常态，与现状一致）

**保存语义**：PUT 校验 → 写 DB → 换快照 → 写本地文件缓存。DB 写失败不阻塞本机：快照+文件照常生效，PUT 返回 `{ok:true, warning:"远程库写入失败…其他工作机暂不同步"}`。双管理员并发保存 = last-write-wins（运维面可接受，文档注明）。

**安全口径不变**：key 在 PG 明文（与现状文件 0600 同级，PG 访问权已在运维手里）；API 永不回明文；`.env` 保持每机兜底层不动。

## 改动清单

1. **`server/migrations/0009_app_settings.sql`**（新增）
   `CREATE TABLE IF NOT EXISTS app_settings (key TEXT PRIMARY KEY, value JSONB NOT NULL, updated_at TIMESTAMPTZ NOT NULL DEFAULT now())`，头注释说明用途与自管口径。

2. **`server/internal/store/store.go`**
   - `Store` 接口加：`GetKV(key string) (val []byte, updatedAt time.Time, ok bool, err error)`、`PutKV(key string, val []byte) error`
   - `Open()` 里沿用 users 表自管口径 `CREATE TABLE IF NOT EXISTS app_settings`（迁移文件留运维对账）
   - pgStore：`SELECT value, updated_at` + `INSERT … ON CONFLICT (key) DO UPDATE SET value=EXCLUDED.value, updated_at=now()`；memStore：`map[string][]byte` + 时间戳，带锁
   - `server/internal/store/store_test.go` 补 KV roundtrip 用例

3. **`server/internal/llm/settings.go`**
   - 定义窄接口 `KVStore`（GetKV/PutKV 同形签名，避免 llm→store import 环；store.Store 天然满足）
   - `AttachKV(kv KVStore)`：执行上述种子/回灌逻辑，并启动 30s `refreshLoop` goroutine（DB 值 bytes 与上次不同才换快照；DB 断连保持旧快照、仅状态翻转时打一次日志）
   - `SaveSettings` 改为：校验 → normalize → JSON → `kv.PutKV`（失败不阻塞，记 warning 返回）→ 换快照 → 文件缓存照旧 tmp+rename；导出 `SaveSettingsWithStatus(s) (warning string, err error)` 供 API 用，`SaveSettings` 保持旧签名（内部调前者弃 warning）兼容现有调用
   - 导出 `StorageInfo() (backend string, updatedAt time.Time)`：kv 非 nil 回 ("db", 上次 DB 行时间)，否则 ("file", 文件 mtime 或零值)
   - 包级 kv 变量随快照一样用 `withSettingsEnv` 式保存/还原便于测试

4. **`server/internal/llm/settings_test.go`** 新增用例：
   - DB 有值优先于本地文件（AttachKV 后快照来自 DB）
   - DB 空 + 文件有 → 种子进 KV（fake KV 收到文件内容）
   - 保存写穿 KV；KV 写失败 → 本机快照/文件仍生效且返回 warning
   - refreshLoop 变更拉新（可用手动调 refresh 函数代替等 30s——把刷新逻辑提成 `refreshFromKV()` 便于测试）

5. **`server/cmd/server/main.go`**：`store.Open` 成功且 `st.Kind()=="pg"` 后调 `llm.AttachKV(st)`（memStore/内存模式不接，文件模式保持现状）

6. **`server/internal/api/llmsettings.go`**
   - GET 加 `"storage": gin.H{"backend": …, "updated_at": …}`
   - PUT 改用 `SaveSettingsWithStatus`，有 warning 时回 `{ok:true, warning:…}`

7. **前端**
   - `web/src/types.ts`：`LlmSettingsView` 加 `storage?: {backend: string; updated_at?: string}`；PUT 响应加可选 `warning`
   - `web/src/components/LlmSettingsPage.vue`：页面顶部一行事实源提示（「远程数据库·多机共享 · 上次更新 xx」/「本机文件（未接远程库）」）；save() 收到 warning 时行内黄条提示
   - `api.ts` 响应透传 warning（现有 req 封装应已回 JSON body，小改）

8. **`docs/llm-settings-2026-10-29.md`** 追加「远程库存储（2026-10-30）」一节：事实源切换语义、种子/回灌、30s 同步、保存降级语义、多机接入步骤（各机配同一 `PG_DSN` 即可；`.env` 仍是每机兜底）

## 验证

1. `cd server && go test ./...` 全绿（含新 KV/设置用例）
2. 冒烟（守 [[zhenshu-smoke-test-safety]]：临时 DATA_DIR、鉴权走 /api/auth/login）：配 PG_DSN 起服务 → UI 保存一个供应商 → `psql` 查 `app_settings` 行存在 → 重启服务配置仍在、GET `storage.backend=="db"`；再起第二个实例（不同临时 DATA_DIR、同 DSN）→ 其 GET 视图 30s 内看到同一份配置
3. 断 DB 场景：停 PG 后 PUT → 本机仍生效、响应带 warning、文件缓存已更新
4. 无 PG 场景回归：不配 PG_DSN 起 dev → 设置面板行为与现状完全一致
