# 防失败机制：项目事实单一清单化

## 病根与原则
病根：磁盘上的项目事实只有一份，但"哪些事实算数"被 8 个视图各自手工抄写，抄写者可以静默漏报（本次事故：失败终态被藏在 HasVideo 条件里）。
原则：**事实只算一次（State），所有视图从同一份事实渲染，每条异常事实必须有出口，测试用"全警报矩阵"强制。**

## 已完成（工作区待提交）

## 改动清单

### 第 1 步 · 事实清单归一（后端核心）
- `server/internal/agent/agent.go`
  - State 加 `Stale{Manuscript, Storyboard, Style bool}`（时间戳字段已在，State() 里顺手算出；projectView 的 inline 计算迁进来）
  - summary() 渲染过期：有成片且任一轴过期 → "⚠ 成片是旧版（出片后改过稿/分镜/风格），重新制作才套用"；未过期才说"✓ 成片已就绪"
  - 新终态渲染："produce.interrupted" → "⏹ 上次制作因服务重启中断（hh:mm）——重新调 start_production 接着做，产物按段复用"
- `server/internal/produce/produce.go`
  - 新常量 `EventProduceInterrupted/EventReworkInterrupted`；Reconcile 补写改用之（不再与真失败混用 *.error），自身扫描把 interrupted 记为终态（幂等不重补）
  - finishJob 与 OnDone 调用包 recover（panic 不炸进程、不跳过终态落盘）；`pipeline.Manifest` 写失败重试一次
  - 新增导出 `LastTerminal(p) (event, detail, ts)`：把 agent 私有的 lastProduceResult 迁来（produce 包 import pipeline 无环；agent/api 共用）
- `server/internal/api/server.go`
  - projectView：video_stale 改读 st.Stale；新增 `last_produce:{event,ts}`
  - listProjects：每行加 `last_produce`（调 produce.LastTerminal；manifest 很小，开销可忽略），status 枚举不动（不破坏现有前端语义）
- `server/internal/api/overview.go`：scanManifest 终态集合加 interrupted

### 第 2 步 · 工具门禁同权（agent 行为面）
- `server/internal/agent/tools.go`
  - start_production 门禁：有成片且（任一过期 ∨ 上次失败/中断）→ 放行整片重做（与 UI"按最新内容重做"按钮同权）；成片新鲜健康 → 维持拒绝，文案指引 rework
  - export：过期/失败后 → 照给地址但必须带"这是旧版"警告（不硬拒，版本事实必须说）
  - rework：文稿/分镜已过期 → 结果语附"改旁白需整片重做"
  - run_selfcheck：补"最近制作终态 / 成片是否过期"两行
- systemPrompt（agent.go:394 一带）："成片就绪后不再 start_production" → "成片就绪**且未过期**时不再 start_production；过期/上次失败后用户要重做就 start_production"
